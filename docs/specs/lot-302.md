## 6. Interfaces

### 6.1 Ce que le fichier de comptes contient

Structure lue dans le serveur de Carnet Réa. **Microbio n'y écrit jamais et n'y crée rien**, pas même un onglet manquant. Toutes les cellules y sont au format texte.

| Onglet | Colonnes lues | Sens |
|---|---|---|
| `Sessions` | `jeton (empreinte)`, `uid`, `créé`, `dernière activité` | Une ligne par session. Le jeton n'y est pas : seule son empreinte y est. `uid` est l'`ID compte`. `dernière activité` est un nombre de millisecondes depuis 1970, écrit en texte. |
| `Utilisateurs` | `id`, `del`, `actif`, `anon` | `id` est l'`ID compte`. `del` : ligne supprimée. `actif` : compte actif. `anon` : compte anonymisé. |
| `Config` | `id`, `del`, `valeur` | Une ligne par réglage. La ligne dont `id` vaut `securite` a pour `valeur` un texte JSON, dont le champ `sessionJours` est la durée de vie d'une session sans activité, en jours. |

L'onglet `Utilisateurs` contient d'autres colonnes, dont des données d'identité et des empreintes de mots de passe. **Microbio ne les lit jamais** (§ 6.3).

**Empreinte d'un jeton** — `empreinteDuJeton(jeton)` dans `serveur/empreinte.js` :

```
Utilities.base64EncodeWebSafe(
  Utilities.computeDigest(Utilities.DigestAlgorithm.SHA_256, jeton, Utilities.Charset.UTF_8)
).replace(/=+$/, '')
```

C'est le SHA-256 du jeton, en base64 « web » sans les `=` de fin. Vecteur de contrôle : le texte `abc` donne `ungWv48Bz-pBQUDeXa4iI7ADYaOWF3qctBD_YfIAFa0`.

### 6.2 Fonctions pures de la session (`logique/session-regles.js`)

| Nom | Entrée → sortie |
|---|---|
| `JETON_LONGUEUR_MIN` | 40. |
| `JETON_LONGUEUR_MAX` | 200. |
| `SESSION_JOURS_PAR_DEFAUT` | 14. |
| `MS_PAR_JOUR` | 86 400 000. |
| `DUREE_CACHE_SESSION_S` | 300. |
| `jetonBienForme(jeton)` | → vrai si `jeton` est un texte de `JETON_LONGUEUR_MIN` à `JETON_LONGUEUR_MAX` caractères. |
| `versBooleenCarnetRea(valeur)` | → vrai si `valeur` vaut `true`, `1`, `'1'`, ou si `String(valeur)` en minuscules vaut `'true'`. Faux sinon, cellule vide comprise. |
| `lireSessionJours(ligneSecurite)` | `ligneSecurite` : ligne `{ numero, valeurs }` ou `null`. → `valeurs.valeur` décodé en JSON, champ `sessionJours`, si c'est un nombre fini strictement positif. Dans tous les autres cas (ligne nulle, `del` vrai, JSON illisible, champ absent ou incorrect) → `SESSION_JOURS_PAR_DEFAUT`. |
| `trouverCompte(lignesUtilisateurs, uid)` | → la **dernière** ligne dont `String(valeurs.id)` égale `uid` ; `null` si aucune. Une ligne dont `id` est vide est ignorée. |
| `deciderSession(donnees)` | → l'`ID compte` (texte), ou lève `session_invalide`. |
| `cleDeCacheSession(empreinte)` | → `'session:' + empreinte`. |

`donnees` de `deciderSession` : `{ ligneSession, lignesUtilisateurs, ligneSecurite, maintenantMs }`.

Contrôles de `deciderSession`, dans l'ordre ; le premier qui échoue lève `session_invalide` :

1. `ligneSession` est `null`.
2. `uid = String(ligneSession.valeurs['uid'])` est vide.
3. `derniere = Number(ligneSession.valeurs['dernière activité'])` n'est pas un nombre fini.
4. `derniere + lireSessionJours(ligneSecurite) × MS_PAR_JOUR < maintenantMs` (session expirée ; l'égalité est encore valide).
5. `compte = trouverCompte(lignesUtilisateurs, uid)` est `null`.
6. `versBooleenCarnetRea(compte.valeurs.del)` est vrai.
7. `versBooleenCarnetRea(compte.valeurs.actif)` est faux.
8. `versBooleenCarnetRea(compte.valeurs.anon)` est vrai.

Sinon rend `uid`.

Ces règles sont celles de Carnet Réa. Deux écarts voulus, toujours dans le sens du refus : une `dernière activité` illisible refuse la session, et un jeton de plus de 200 caractères est refusé.

### 6.3 Liste fermée des lectures dans le fichier de comptes (`logique/stockage-regles.js`)

`LECTURES_CARNET_REA` : constante qui décrit les seules lectures permises quand `idFichier` est égal à la propriété `ID_CARNET_REA`.

| Onglet | Fonction du module de stockage | Condition |
|---|---|---|
| `Sessions`, `Utilisateurs`, `Config` | `ongletExiste`, `lireEnTete` | Aucune. |
| `Sessions` | `trouverLigne` | `colonneCle` = `jeton (empreinte)`. |
| `Utilisateurs` | `lireColonnes` | Toutes les colonnes demandées sont parmi `id`, `del`, `actif`, `anon`. |
| `Config` | `trouverLigne` | `colonneCle` = `id` et `valeurCle` = `securite`. |

`verifierLectureAutorisee(idFichier, idCarnetRea, demande)` :

- `demande` = `{ fonction, onglet, colonnes, colonneCle, valeurCle }` (les champs sans objet sont absents) ;
- ne fait rien si `idCarnetRea` est vide ou différent de `idFichier` ;
- sinon lève `lecture_interdite` pour toute demande absente du tableau ci-dessus : autre onglet, `lireOnglet`, `trouverLigne` sur `Utilisateurs`, colonne hors liste, autre clé de `Config`.

Dans `stockage.js`, **chaque fonction de lecture** (`ongletExiste`, `lireEnTete`, `lireOnglet`, `lireColonnes`, `trouverLigne`) commence par `verifierLectureAutorisee`, avec `lirePropriete('ID_CARNET_REA')`. Les écritures restent refusées par `verifierEcritureAutorisee` (lot 301).

**Cette liste ne s'élargit qu'avec l'accord de l'auteur.**

### 6.4 `verifierSession(jeton)` (`session.js`)

Rend l'`ID compte` (texte) ou lève une erreur à code. Déroulé :

1. `jetonBienForme(jeton)` faux → `session_invalide`. Aucun appel Google.
2. `empreinte = empreinteDuJeton(jeton)`.
3. **Mémoire de l'exécution** : si cette empreinte a déjà été vérifiée dans l'exécution en cours, rend l'`ID compte` gardé.
4. **Cache** : `lireCache(cleDeCacheSession(empreinte))` non nul → le garde dans la mémoire de l'exécution et le rend. Une erreur du cache vaut une absence.
5. `idCarnetRea = lirePropriete('ID_CARNET_REA')`. Absente → `configuration_invalide`.
6. Lectures, dans un seul `try/catch` :
   1. `ongletExiste(idCarnetRea, 'Sessions')` faux → `session_invalide` (Carnet Réa ne crée cet onglet qu'à la première connexion) ;
   2. `ligneSession = trouverLigne(idCarnetRea, 'Sessions', 'jeton (empreinte)', empreinte)` ; `null` → `session_invalide`, **sans lire les deux autres onglets** ;
   3. `lignesUtilisateurs = lireColonnes(idCarnetRea, 'Utilisateurs', ['id', 'del', 'actif', 'anon'])` ;
   4. `ligneSecurite = trouverLigne(idCarnetRea, 'Config', 'id', 'securite')`.
   
   Toute erreur autre que `session_invalide` (fichier impossible à ouvrir, onglet `Utilisateurs` ou `Config` absent, colonne absente, lecture interdite) → `journaliserErreur`, puis lève `comptes_indisponibles`.
7. `idCompte = deciderSession({ ligneSession, lignesUtilisateurs, ligneSecurite, maintenantMs: Date.parse(maintenant()) })`.
8. `ecrireCache(cleDeCacheSession(empreinte), idCompte, DUREE_CACHE_SESSION_S)`, dans un `try/catch` muet ; puis mémoire de l'exécution ; rend `idCompte`.

Règles :

- Un refus n'est jamais mis en cache.
- Le jeton n'est jamais écrit : ni dans un fichier, ni dans le cache, ni dans un journal. Seule son empreinte sert de clé.
- La logique des étapes 1 à 8 est écrite dans une fonction pure `verifierSessionAvec(jeton, dependances)` de `logique/session-regles.js`, pour être testée par Node. `dependances` : `empreinteDuJeton`, `memoire` (objet), `lireCache`, `ecrireCache`, `lirePropriete`, `ongletExiste`, `trouverLigne`, `lireColonnes`, `maintenant`, `journaliserErreur`. `session.js` ne fait que lui passer les vraies.

**Conséquences à connaître** (à noter dans `PROGRESS.md`) :

- une déconnexion ou une désactivation dans Carnet Réa s'applique à Microbio en 5 minutes au plus ;
- Microbio ne prolonge pas la session : sans appel à Carnet Réa, elle s'éteint après `sessionJours` (lot 303) ;
- dans une action, `contexte.idCompte` est déjà vérifié par le routeur ; un second appel de `verifierSession` dans la même exécution rend la même valeur sans rien relire.

### 6.5 Droits (`logique/droits-regles.js`, `droits.js`)

Onglet `Profils` du fichier Joueurs. Colonnes lues : `ID compte`, `Droit contenu`, `Droit résultats`. Colonnes écrites (par le § 6.8 seulement) : les mêmes, et `Créé le`.

Fonctions pures :

| Nom | Entrée → sortie |
|---|---|
| `COLONNE_DU_DROIT` | `{ contenu: 'Droit contenu', resultats: 'Droit résultats' }`. |
| `droitsDuCompte(lignesProfils, idCompte)` | → `{ contenu, resultats, doublon }`. Aucune ligne pour ce compte → `false`, `false`, `false`. **Plus d'une ligne** → `false`, `false`, `true`. Une ligne → chaque droit est vrai si `texteDeCellule(cellule)` vaut exactement `oui`. |
| `aLeDroit(droits, droit)` | → `droits[droit] === true`. Lève `erreur_interne` si `droit` n'est pas une clé de `COLONNE_DU_DROIT`. |
| `lireDemandeDeDroits(texte)` | → `{ idCompte, contenu, resultats }` où `contenu` et `resultats` valent `'oui'` ou `'non'`. Format attendu : trois parties séparées par `;`, espaces autour ignorés, `idCompte` non vide. Sinon lève `demande_invalide`. |
| `ligneProfilsNouvelle(enTete, idCompte, contenu, resultats, creeLe)` | → un tableau dans l'ordre de `enTete`, avec `ID compte`, `Droit contenu`, `Droit résultats` et `Créé le` remplis et les autres cellules vides. |

Dans `droits.js` :

| Fonction | Rôle |
|---|---|
| `lireDroits(idCompte)` | `lireColonnes(ID_JOUEURS, 'Profils', ['ID compte', 'Droit contenu', 'Droit résultats'])`, puis `droitsDuCompte`. Si `doublon` est vrai : `journaliserErreur`. → `{ contenu, resultats }`. **Relit la feuille à chaque appel** : ni cache ni mémoire. |
| `exigerDroit(idCompte, droit)` | Lève `droit_refuse` si `aLeDroit(lireDroits(idCompte), droit)` est faux. Ne rend rien. |

**Règle pour tous les lots suivants** : une action réservée aux admins commence par `exigerDroit(contexte.idCompte, '<droit>')`. Si elle écrit, elle le rappelle **sous le verrou**, avant d'écrire. L'interface peut cacher un bouton ; elle ne remplace jamais ce contrôle.

### 6.6 Action `profil`

Non publique. Message : `{ "action": "profil", "session": "<jeton>" }`.

Réponse :

```
{ "ok": true, "idCompte": "compte-A", "droits": { "contenu": false, "resultats": false } }
```

`actionProfil(message, contexte)` rend `contexte.idCompte` et `lireDroits(contexte.idCompte)`. Elle n'écrit rien. Elle sert à l'interface pour proposer ou non le mode test ; elle ne donne aucun accès par elle-même.

Erreurs possibles : `session_invalide`, `comptes_indisponibles`, `configuration_invalide`.

### 6.8 Attribution des droits (`installation-comptes.js`)

`appliquerDroitsDemandes()` se lance depuis l'éditeur Apps Script, par le propriétaire du script. Elle n'est pas dans la table des actions.

Mode d'emploi pour l'auteur : dans les paramètres du projet Apps Script, ajouter la propriété `DROITS_A_ACCORDER` avec la valeur `<ID compte>;<oui ou non>;<oui ou non>` (droit « contenu », puis droit « résultats »), puis lancer la fonction.

Déroulé :

1. Lit `DROITS_A_ACCORDER`. Absente → erreur « rien à faire ». `lireDemandeDeDroits` → `demande_invalide` si le format est faux.
2. Vérifie que le compte existe dans le fichier de comptes : `lireColonnes` des quatre colonnes permises, `trouverCompte`, et le compte n'est ni supprimé ni anonymisé. Sinon erreur « compte inconnu », rien n'est écrit.
3. Sous `sousVerrou` : relit `Profils`.
   - Une ligne pour ce compte → `ecrireLigne` de `Droit contenu` et `Droit résultats`.
   - Aucune ligne → `ajouterLignes` de `ligneProfilsNouvelle(…, maintenant())`.
   - Plusieurs lignes → erreur, rien n'est écrit : **arrête-toi et demande**.
4. `effacerPropriete('DROITS_A_ACCORDER')`.
5. Écrit dans les journaux d'exécution l'`ID compte` et les deux droits écrits.

### 6.9 Fonction d'essai (`installation-comptes.js`)

`essaiSession()`, lancée depuis l'éditeur, hors de la table des actions. Elle lève une erreur si `ENVIRONNEMENT` ne vaut pas `test` ou si `JETON_ESSAI_A` n'existe pas. Elle écrit le résultat de chaque étape dans les journaux d'exécution, **sans jamais y écrire un jeton**.

1. `empreinteDuJeton('abc')` égale le vecteur de contrôle du § 6.1.
2. Pour chaque jeton d'essai, appelle `traiterRequete` avec les vraies dépendances et le message `{ action: 'profil', session: <jeton> }` : A → `ok: true`, `idCompte` = `compte-essai-A` ; B à F → `session_invalide`.
3. Même appel avec `session: null`, puis avec un jeton de 10 caractères → `session_invalide`.
4. Lectures et écritures interdites sur le fichier de comptes : `ajouterLignes` sur `Sessions` → `ecriture_interdite` ; `lireOnglet` sur `Utilisateurs` → `lecture_interdite` ; `lireColonnes` sur `Utilisateurs` avec `['id', 'colonne-fictive-A']` → `lecture_interdite` ; `trouverLigne` sur `Config` avec la clé `autre` → `lecture_interdite`.
5. Écrit `DROITS_A_ACCORDER` = `compte-essai-A;oui;non`, lance `appliquerDroitsDemandes()`, puis vérifie : l'action `profil` rend `contenu: true`, `resultats: false` ; `exigerDroit('compte-essai-A', 'contenu')` ne lève rien ; `exigerDroit('compte-essai-A', 'resultats')` lève `droit_refuse`.
6. Remet `compte-essai-A;non;non` par le même chemin et vérifie que `exigerDroit('compte-essai-A', 'contenu')` lève `droit_refuse` **dans la même exécution** (les droits ne sont pas gardés en mémoire).

## 7. Cas limites

| Cas | Comportement attendu |
|---|---|
| `session` absente, `null`, non textuelle, de moins de 40 ou de plus de 200 caractères | `session_invalide`, sans aucune lecture. |
| Empreinte absente de `Sessions` | `session_invalide` ; `Utilisateurs` et `Config` ne sont pas lus. |
| Onglet `Sessions` absent | `session_invalide`. Microbio ne le crée pas. |
| Deux lignes de `Sessions` de même empreinte | La première décide. |
| Session dont la dernière activité date d'exactement `sessionJours` jours | Valide. Une milliseconde de plus : refusée. |

| Fichier de comptes impossible à ouvrir, onglet `Utilisateurs` absent, colonne `actif` absente | `comptes_indisponibles`, erreur journalisée. Jamais `session_invalide`. |
| `ID_CARNET_REA` absente | `configuration_invalide`. |
| Session valide vérifiée, puis supprimée dans le fichier de comptes | Encore acceptée 5 minutes au plus. |
| Session refusée | Rien en cache : elle est revérifiée à l'appel suivant. |
| Cache indisponible | La vérification lit le fichier de comptes ; aucune erreur ne sort. |
| Compte sans ligne `Profils` | Session valide, aucun droit. |
| `Droit contenu` vaut `Oui`, `OUI`, `x`, `1` ou `true` | Pas de droit : seule la valeur `oui` l'accorde. |
| Deux lignes `Profils` pour un compte | Aucun droit, erreur journalisée. |
| Droit retiré pendant qu'un admin travaille | Refus dès son action suivante. |
| Toute écriture vers le fichier de comptes | `ecriture_interdite`. |
| `installerComptesFictifs` lancée deux fois | Erreur à la seconde, rien n'est créé. |
