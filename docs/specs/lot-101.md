**Règles de `node --test`**, à noter dans `PROGRESS.md` :

- lancé sans argument à la racine, il trouve tout fichier nommé `*.test.js`, dans tous les sous-dossiers ;
- un fichier d'aide des tests (données, doublure, chargeur) ne se termine pas par `.test.js`, ne commence pas par `test-` et ne se trouve pas dans un dossier nommé `test` : sinon Node le lance comme un test ;
- un test importe un module du client par un chemin relatif ;
- un test charge un fichier du serveur par `createRequire(import.meta.url)`, puis `require` ; Node le lit en CommonJS parce que le `package.json` de son dossier le dit.

### 6.4 Garde-fous

**`.gitignore`** — une ligne de commentaire en tête de chaque groupe :

| Groupe | Motifs |
|---|---|
| Contenu réel de travail | `contenu-local/` |
| Tableurs et exports | `*.xlsx`, `*.xlsm`, `*.xls`, `*.ods`, `*.csv`, `*.tsv` |
| Code serveur de Carnet Réa | `Code.gs`, `Defaults.gs` |
| Identifiants et secrets | `.clasprc.json`, `.env`, `.env.*`, `*.pem` |
| Réglages locaux de Claude Code | `.claude/settings.local.json` |
| Outils | `node_modules/`, `.DS_Store`, `Thumbs.db` |

`.clasp.json` n'est **pas** ignoré : il sera versionné au lot 301 (identifiant du projet de test seulement).

**Crochet `.githooks/pre-commit`**, en shell POSIX, sans autre outil que git. Il refuse le commit, avec un message en français qui dit pourquoi, si :

1. la branche courante est `main` ;
2. un fichier ajouté, copié, modifié ou renommé dans le commit se trouve sous `contenu-local/`, a une extension de tableur du tableau ci-dessus, ou s'appelle `Code.gs`, `Defaults.gs`, `.clasprc.json`, `.env` ou `.env.<quelque chose>`.

Il ne fait rien d'autre (il ne lance pas les tests : c'est le rituel du `CLAUDE.md`). Il est rendu exécutable dans git, pas seulement sur le disque. Il ne s'active que par `git config core.hooksPath .githooks`, à refaire après chaque clone : écris-le dans `PROGRESS.md`.

**Règles de permission de Claude Code.** Lis la documentation de Claude Code pour la syntaxe exacte des règles, qui a changé selon les versions, et note dans `PROGRESS.md` la version de Claude Code et la syntaxe retenue.

| Fichier | Règle | Effet |
|---|---|---|
| `.claude/settings.json` | Refus : `git commit` avec `--no-verify` ou `-n` | Le crochet ne peut pas être contourné. |
| `.claude/settings.json` | Refus : `git push` avec `--force`, `-f` ou `--force-with-lease` | L'historique n'est jamais réécrit. |
| `.claude/settings.json` | Refus : `git config` qui modifie `core.hooksPath` | Le crochet ne peut pas être désactivé par la session. |
| `.claude/settings.json` | Demande : `git push` vers `main`, `git merge` et `git checkout` ou `git switch` vers `main`, `git reset --hard`, `git branch -D` | L'auteur confirme lui-même, à chaque fois. |
| `.claude/settings.local.json` | Refus : `Edit` et `Write` dans les copies locales de Carnet Réa et d'EchoLearn (chemins donnés par l'auteur) | Une session Microbio ne peut pas modifier Carnet Réa. |

Les chemins de l'ordinateur de l'auteur ne vont **jamais** dans `.claude/settings.json` : le dépôt est public. Si l'auteur n'a aucune copie locale de Carnet Réa ni d'EchoLearn, `.claude/settings.local.json` n'est pas créé ; note-le.

Ces règles complètent le `CLAUDE.md`, elles ne le remplacent pas : le `CLAUDE.md` reste la consigne, les garde-fous en sont le verrou (plan § 9, lot 4a, décision 11).

## 8. Tests à écrire

`node --test`, sans dépendance, **aucun contenu médical**. Les tests qui appellent git le font par `child_process`, module de Node, et se marquent « ignorés » si git est absent.

2. Le fichier CommonJS d'essai se charge par `createRequire(import.meta.url)` ; son export a la valeur attendue.
3. Chargé par `import()`, le même fichier rend son export sous `default` : Node l'a bien lu en CommonJS.

**`garde-fous.test.js`**

4. `.gitignore` contient chacun des motifs du § 6.4, sur sa propre ligne.
5. Aucun fichier de l'arbre de travail (hors `.git/`, `node_modules/` et `contenu-local/`) n'a une extension de tableur ni l'un des noms interdits du § 6.4.
6. `.githooks/pre-commit` existe et est exécutable (vérification ignorée sous Windows).
7. `git config core.hooksPath` vaut `.githooks`.
8. `package.json` a `type` = `module` et aucun des trois champs de dépendances ; aucun `package-lock.json` n'existe.

**`documents.test.js`**

9. Chaque destination du § 6.6 existe et n'est pas vide, ainsi que `client/images/logo-ios.png` et `client/images/logo-android.png`. `docs/design-system.md` absent : test marqué « à faire », pas en échec.
