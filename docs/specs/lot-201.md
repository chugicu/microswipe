## 1. Objectif

Écrire le moteur de niveaux de la campagne, en fonctions pures et sans interface :

- préparer un niveau à partir du paquet de contenu : questions jouables, questions écartées, réponse attendue de chacune ;
- créer une partie, corriger chaque réponse, calculer le score et les étoiles ;
- produire l'événement de réponse et l'événement de fin de partie, et permettre à d'autres modules de s'y abonner sans que le jeu attende.

Aucun monde, niveau, question ni seuil n'est écrit dans le code : tout vient du paquet.

### 6.3 Lecture du paquet (`lecture.js`)

| Fonction | Entrée → sortie |
|---|---|
| `creerErreurDeJeu(code)` | → `Error` avec `message` et `code`. |
| `texte(valeur)` | → texte vide pour `null` et `undefined` ; sinon `String(valeur)` sans espaces de début et de fin. |
| `lireListe(texteBrut)` | → les parties séparées par `;`, sans espaces autour, sans les parties vides. |
| `lireReferences(texteFait)` | → tableau de `{ onglet, identifiant }`, ou `null`. Chaque partie de `lireListe` a la forme `Onglet:Identifiant` : un seul `:`, deux côtés non vides après retrait des espaces. Aucune partie, ou une partie mal formée → `null`. |
| `lireChamps(texteChamp, nombreDeFaits)` | → tableau de `nombreDeFaits` noms, ou `null`. Un seul nom → répété pour chaque fait. Autant de noms que de faits → ces noms, dans l'ordre. Tout autre nombre → `null`. |
| `lireEntier(texteBrut)` | → l'entier si `texte(texteBrut)` correspond à `^[0-9]+$` ; `null` sinon. |
| `lireReglagesDuNiveau(texteReglages)` | → `{ lisible, correspondances }` (voir ci-dessous). |
| `lireSeuilsEtoiles(reglages)` | → `[s1, s2, s3]` ou `null`. Chaque clé de `CLES_SEUILS_ETOILES` est lue par `lireEntier` ; chaque valeur est un entier de 1 à 100 ; `s1 ≤ s2 ≤ s3`. Section `reglages` absente, clé absente ou règle non tenue → `null`. |
| `indexerPaquet(paquet)` | → l'index (voir ci-dessous). |

**Format de la colonne `Réglages`** (décidé le 15 novembre) : un texte JSON.

```
{
  "v": 1,
  "correspondances": {
    "Faits_fictifs:Colonne A": { "Valeur A1": "Réponse 1", "Valeur A2": "Réponse 1", "Valeur A3": "Réponse 2" },
    "Faits_fictifs:Colonne B": { "Valeur B1": "oui", "Valeur B2": "non" }
  }
}
```

- `correspondances` : une table par couple `Onglet:Champ`. Une table va de la valeur du fait à la réponse du jeu.
- Les autres clés du bloc (directions du swipe, chrono, vies…) appartiennent à d'autres lots : **le moteur les ignore**.

`lireReglagesDuNiveau` :

- texte vide → `{ lisible: true, correspondances: {} }` ;
- sinon le texte doit se décoder en un objet (ni tableau ni `null`) dont `v` vaut le nombre `1`. `correspondances` peut être absent (aucune table). S'il est présent : c'est un objet, chaque table est un objet, chaque réponse est un texte non vide après retrait des espaces ;
- une seule de ces règles non tenue → `{ lisible: false, correspondances: {} }` ;
- dans le résultat, les clés des tables et les réponses sont passées par `texte`. La clé `Onglet:Champ` est reconstruite à partir de ses deux côtés, chacun passé par `texte`.

**Index** rendu par `indexerPaquet` — un objet dont les recherches se font par `Map` :

| Champ | Contenu |
|---|---|
| `type`, `versionContenu` | Ceux du paquet. |
| `reglages` | `paquet.reglages`, ou un objet vide s'il est absent. |
| `mondes`, `niveaux` | Les tableaux du paquet, dans leur ordre. |
| `niveauxParId`, `questionsParId` | `ID` → ligne. Si un `ID` apparaît deux fois, la première ligne est gardée. |
| `compositionParNiveau` | `ID` de niveau → ses lignes de `composition`, dans l'ordre du paquet. |
| `faitsParCle` | `Onglet:ID` → **tableau** des lignes de cet `ID` dans cet onglet (plusieurs lignes = fait en double). |
| `compositionPrevue` | `paquet.compositionPrevue`, ou un objet vide. |
| `etatDesQuestions` | `paquet.etatDesQuestions`, ou `null`. |

### 6.4 Réponse attendue et correction (`reponses.js`)

**`preparerQuestion(question, reglagesDuNiveau, index)`** → `{ jouable: true, question: <question préparée> }` ou `{ jouable: false, motif }`.

`reglagesDuNiveau` est le résultat de `lireReglagesDuNiveau`.

Question préparée :

```
{
  id: "Q-000001",
  mecanique: "swipe",
  forme: "unique",
  faits: [ { onglet: "Faits_fictifs", identifiant: "FF-01", champ: "Colonne A" } ],
  attendu: [ "Réponse 1" ],
  leurres: [ "Réponse 2" ]
}
```

- `attendu` : un seul texte pour la forme `unique` ; un texte par fait, dans l'ordre de `faits`, pour la forme `multiple`.
- La question préparée ne porte **ni énoncé, ni libellé, ni indication qu'elle est simplifiée** : l'écran lit ce qu'il affiche dans le paquet, par l'`ID`.

Contrôles, dans cet ordre ; le premier qui échoue donne le motif :

1. `texte(Mécanique)` n'est pas une propriété propre de `FORMES_PAR_MECANIQUE` → `mecanique_inconnue`.
2. `references = lireReferences(Fait)` vaut `null` → `reference_illisible`.
3. `champs = lireChamps(Champ, references.length)` vaut `null` → `champ_illisible`.
4. Pour chaque couple (référence, champ), dans l'ordre : aucune ligne dans `index.faitsParCle` → `fait_absent` ; plusieurs lignes → `fait_en_double` ; la ligne n'a pas de propriété propre nommée `champ` → `champ_absent`.
5. Forme `unique` :
   - `texte(Réponse propre)` non vide → `attendu = [ce texte]` (le texte entier, **sans le découper**) ;
   - sinon, plus d'un fait → `reponse_indeterminee` ;
   - sinon → correspondance (contrôle 7).
6. Forme `multiple` : `propres = lireListe(Réponse propre)`.
   - `propres` vide → correspondance (contrôle 7), pour chaque fait ;
   - `propres.length` égal au nombre de faits → `attendu = propres` ;
   - sinon → `reponse_propre_illisible`.
7. Correspondance, pour chaque couple concerné :
   - `reglagesDuNiveau.lisible` faux → `reglages_illisibles` ;
   - `valeur = texte(ligne[champ])` ; valeur vide → `valeur_sans_correspondance` ;
   - `table = correspondances["<onglet>:<champ>"]` absente, ou `valeur` n'en est pas une propriété propre → `valeur_sans_correspondance` ;
   - sinon la réponse attendue de ce fait est `table[valeur]`.
8. `leurres = lireListe(Leurres)`. Un leurre égal à un texte de `attendu` → `leurre_egal_reponse`.

**Jamais de repli sur la valeur brute du fait** : sans réponse propre ni correspondance, la question n'est pas jouable (schéma § 3.3 et § 3.5, condition 4).

**`corriger(questionPreparee, reponse)`** → `{ resultat, reponseDonnee, detail }`.

| Forme | `reponse` attendue | `resultat` | `reponseDonnee` | `detail` |
|---|---|---|---|---|
| `unique` | Un texte. | 1 si `texte(reponse)` est égal à `attendu[0]`, 0 sinon. | `texte(reponse)` | `[true]` ou `[false]` |
| `multiple` | Un tableau d'autant de textes que de faits, dans l'ordre de `faits` ; texte vide pour un élément non placé. | Nombre d'éléments égaux à leur attendu, divisé par le nombre de faits. | `JSON.stringify` du tableau des textes passés par `texte`. | Un booléen par fait. |

- La comparaison est exacte, majuscules et accents compris.
- `reponseDonnee` est coupée à `LONGUEUR_MAX_REPONSE_DONNEE` caractères.
- `reponse` d'une autre forme (pas un texte, tableau de mauvaise longueur, élément qui n'est pas un texte) → lève `reponse_mal_formee`.

### 6.5 Préparation d'un niveau (`niveau.js`)

**`preparerNiveau(index, idNiveau)`** →

```
{
  niveau: "NIV-0001",
  type: "normal",
  jouable: true,
  questions: [ <question préparée>, … ],
  ecartees: [ { question: "Q-000004", motif: "valeur_sans_correspondance" } ],
  prevues: 5,
  incomplet: true,
  simplifie: false
}
```

Déroulé :

1. Niveau absent de `index.niveauxParId` → lève `niveau_inconnu`.
2. `type = texte(Type)`. S'il n'est pas dans `TYPES_JOUABLES` : rend `jouable: false`, `questions: []`, `ecartees: []`, `prevues: 0`, `incomplet: false`, `simplifie` selon l'étape 7.
3. `reglages = lireReglagesDuNiveau(Réglages)`.
4. Lignes de composition du niveau, triées par `lireEntier(Ordre)` croissant. Une ligne dont `Ordre` est illisible passe après les autres. À égalité, l'ordre du paquet est gardé.
5. Pour chaque ligne, dans cet ordre :
   - question absente de `index.questionsParId` → écartée, `question_absente` ;
   - question déjà rencontrée dans ce niveau → écartée, `question_en_double` ;
   - sinon `preparerQuestion` : jouable → ajoutée à `questions` ; sinon → écartée avec son motif.
6. `prevues` = `index.compositionPrevue[idNiveau]` si c'est un entier ≥ 0 ; sinon le nombre de lignes de composition du niveau. `incomplet` = `questions.length < prevues`.
7. `simplifie` = `texte(Simplifié)` vaut `oui`, **ou** une question de `questions` a `texte(Simplifiée)` égal à `oui`.
8. `jouable` = `questions.length ≥ 1`.

**Règle du niveau partiellement validé** (décidée le 15 novembre) : un niveau incomplet se joue avec ses questions jouables. Rien ne l'indique à l'interne. Seul un niveau sans aucune question jouable est fermé.

**`estSimplifiee(question)`** → `texte(question['Simplifiée']) === 'oui'`. Elle sert aux lots des autres modes (404 à 408), qui ne doivent jamais servir une question simplifiée (règle pédagogique 4).

**Annonce d'une version simplifiée** (règle pédagogique 3) : le moteur ne donne que le booléen `simplifie` du niveau. L'écran (lot 203) affiche le texte type du briefing § 2. Le moteur ne dit jamais quelles questions sont simplifiées.

### 6.6 Partie (`partie.js`)

| Fonction | Entrée → sortie |
|---|---|
| `genererIdPartie(octets)` | `octets` : 9 octets aléatoires. → `p` suivi de 9 caractères ; chacun est `ALPHABET_ID_PARTIE[octet % 36]`. Conforme à `^p[a-z0-9]{9}$`. |
| `tirerSansRemise(elements, nombre, aleatoire)` | `aleatoire()` rend un nombre de 0 inclus à 1 exclu. Sur une copie du tableau, pour `i` de 0 à `nombre − 1` : `j = i + Math.floor(aleatoire() × (longueur − i))`, échange des positions `i` et `j`. → les `nombre` premiers éléments. `nombre` < 1 ou > longueur → lève `tirage_impossible`. |
| `optionsDuNiveau(index, idPartie)` | → les options d'un niveau normal : `{ idPartie, seuilsEtoiles, seuilDeReussite: seuilsEtoiles[0], tirage: null, reTestAutorise: true, modeTest: false }`, avec `seuilsEtoiles = lireSeuilsEtoiles(index.reglages)`. Seuils illisibles → lève `reglage_invalide`. **Aucune valeur de secours.** |
| `creerPartie(niveauPrepare, options)` | → l'état d'une partie. |
| `questionCourante(etat)` | → la question préparée à jouer, ou `null` si toutes ont une réponse. |
| `estTerminee(etat)` | → `etat.reponses.length === etat.questions.length`. |
| `estNombreDeReponsesProposees(n)` | → `Number.isInteger(n)` et `REPONSES_PROPOSEES_MIN ≤ n ≤ REPONSES_PROPOSEES_MAX`. |
| `controlerSaisie(saisie)` | → rien si la saisie est bonne ; lève sinon (voir ci-dessous). Ne contrôle pas `reponse` : c'est `corriger` qui le fait. |
| `repondre(etat, saisie)` | → `{ etat, correction, evenementReponse, evenementFin }`. |
| `questionsARetester(etat)` | → les `id` à re-tester. |
| `repondreReTest(etat, idQuestion, saisie)` | → `{ etat, correction, evenementReponse }`. |
| `calculerScore(etat)` | → somme des `resultat` de `etat.reponses`, divisée par `etat.questions.length`. |
| `calculerEtoiles(score, seuils)` | → 0 si `seuils` vaut `null` ; sinon le nombre de seuils `s` tels que `score × 100 ≥ s − TOLERANCE_SCORE`. |
| `estReussie(score, seuilDeReussite)` | → `score × 100 ≥ seuilDeReussite − TOLERANCE_SCORE`. |
| `resumerPartie(etat)` | → l'événement de fin de partie (§ 6.7). Partie non terminée → lève `partie_en_cours`. |

**Options de `creerPartie`**

| Option | Règle |
|---|---|
| `idPartie` | Texte conforme à `^p[a-z0-9]{9}$`. |
| `seuilsEtoiles` | `null` (partie sans étoiles), ou trois entiers de 1 à 100, croissants. |
| `seuilDeReussite` | Entier de 1 à 100. |
| `tirage` | `null` : toutes les questions du niveau, dans leur ordre. Ou `{ nombre, aleatoire }` : `tirerSansRemise` sur les questions du niveau. |
| `reTestAutorise` | Booléen. |
| `modeTest` | Booléen. |

Une option absente ou hors règle → lève `option_invalide`. `niveauPrepare.jouable` faux → lève `niveau_non_jouable`. Plus de `QUESTIONS_MAX_PAR_PARTIE` questions dans la partie → lève `niveau_trop_long`.

Les lots 204 et 207 passent `optionsDuNiveau`. Le lot 208 remplace ces options pour un boss ; le lot 213 pose `modeTest`.

```
  mode: "campagne",
  niveau: "NIV-0001",
  type: "normal",
  modeTest: false,
  simplifie: false,
  seuilsEtoiles: [60, 80, 100],
  seuilDeReussite: 60,
  reTestAutorise: true,
  questions: [ <question préparée>, … ],
  reponses: [ { resultat: 1, reponseDonnee: "Réponse 1", temps: 2400 } ],
  reTests: []
}
```

- `questions` : celles de la partie, dans l'ordre joué (après tirage s'il y en a un).
- `reponses` : une entrée par question déjà répondue, dans le même ordre.
- `reTests` : les `id` des questions déjà re-testées.
- Les nombres 60, 80, 100 de cet exemple viennent du paquet fictif, pas du code.
- `reponsesProposees` n'est pas dans l'état : seul l'événement de réponse le porte.

**Saisie** (décision 8) — ce que la mécanique transmet pour une réponse :

```
{
  reponse: "Réponse 1",      // un texte (forme « unique ») ou un tableau de textes (forme « multiple »), § 6.4
  temps: 2400,               // entier ≥ 0, en millisecondes
  reponsesProposees: 2       // entier de 2 à 100 : nombre de réponses que la mécanique a montrées
}
```

`controlerSaisie(saisie)`, contrôles dans cet ordre :

1. `saisie` n'est pas un objet simple (`null`, `undefined`, tableau, texte, nombre) → lève `saisie_mal_formee`.
2. `saisie.temps` n'est pas un entier ≥ 0 → lève `temps_invalide`.
3. `estNombreDeReponsesProposees(saisie.reponsesProposees)` faux → lève `reponses_proposees_invalides`.

Un champ en trop dans la saisie est ignoré. La fonction ne modifie pas la saisie.

**`repondre(etat, saisie)`**

1. Partie terminée → lève `partie_terminee`. Puis `controlerSaisie(saisie)`.
2. `correction = corriger(questionCourante(etat), saisie.reponse)`, complétée du champ `attendu` (copie de celui de la question).
3. Nouvel état : `reponses` reçoit `{ resultat, reponseDonnee, temps: saisie.temps }`.
4. `evenementReponse` : § 6.7, avec `reTest: false`, `temps` et `reponsesProposees` pris dans la saisie.
5. `evenementFin` : `resumerPartie(nouvelEtat)` si la partie vient de se terminer, `null` sinon.

**Nombre de réponses proposées** (décision 7) : c'est la mécanique qui sait combien de réponses elle a montrées (contrat des lots 204 à 206). **Le moteur ne le calcule pas** et ne le compare ni aux leurres, ni à la forme, ni aux directions du swipe. Il ne lui donne jamais de valeur par défaut : une saisie sans nombre valide est une erreur de la mécanique, levée avant toute modification.

**Re-test** (briefing § 5 et § 8)

- `questionsARetester(etat)` : tableau vide si la partie n'est pas terminée ou si `reTestAutorise` est faux. Sinon les `id` des questions dont le `resultat` est inférieur à 1, dans l'ordre de la partie, moins ceux de `reTests`.
- `repondreReTest(etat, idQuestion, saisie)` : `idQuestion` absent de `questionsARetester(etat)` → lève `re_test_refuse`. Puis `controlerSaisie(saisie)`. Sinon corrige `saisie.reponse`, ajoute l'`id` à `reTests`, et rend l'événement de réponse avec `reTest: true`, et le `temps` et le `reponsesProposees` de la saisie. **`reponses`, le score et les étoiles ne changent pas.** Une question n'est re-testée qu'une fois.
- L'enchaînement à l'écran est le lot 207.

### 6.8 Émetteur et conduite (`evenements.js`, `conduite.js`)

`creerEmetteur()` rend :

| Membre | Rôle |
|---|---|
| `abonnerAuxReponses(fn)` | Ajoute un abonné. → une fonction qui le retire. |
| `abonnerAuxFinsDePartie(fn)` | Même chose pour les fins de partie. |
| `emettreReponse(evenement)` | Appelle chaque abonné, dans l'ordre d'abonnement. |
| `emettreFinDePartie(evenement)` | Même chose. |

Règles d'émission :

- chaque abonné reçoit une copie gelée (`Object.freeze`) de l'événement ;
- chaque appel est dans un `try/catch` : l'erreur d'un abonné est écrite par `console.error` et n'empêche ni les abonnés suivants ni le jeu ;
- **la valeur rendue par un abonné n'est jamais attendue**. Si c'est une promesse, un `catch` lui est attaché pour qu'un rejet ne remonte pas ;
- `emettre…` rend `undefined`, tout de suite.

`emetteurDuJeu` : l'instance unique du jeu, exportée par `evenements.js`. Les lots 208 et 309 s'y abonnent.

`conduite.js` — les deux seules fonctions que les écrans appellent pour faire avancer une partie :

| Fonction | Rôle |
|---|---|
| `appliquerReponse(etat, saisie, emetteur)` | Appelle `repondre(etat, saisie)`, puis `emetteur.emettreReponse(evenementReponse)`, puis `emetteur.emettreFinDePartie(evenementFin)` s'il n'est pas nul. → `{ etat, correction, fin }` (`fin` : l'événement de fin, ou `null`). `emetteur` vaut `emetteurDuJeu` s'il est absent. |
| `appliquerReTest(etat, idQuestion, saisie, emetteur)` | Appelle `repondreReTest(etat, idQuestion, saisie)`, puis `emettreReponse`. → `{ etat, correction }`. |

Si `repondre` ou `repondreReTest` lève une erreur, rien n'est émis.

| Trois questions de `resultat` 1/3 chacune (forme `multiple`) | La tolérance évite qu'une erreur d'arrondi fasse manquer un seuil. |
| `repondre` sur une partie terminée | Lève `partie_terminee`. |
| Saisie absente, `null`, tableau ou texte | Lève `saisie_mal_formee` ; l'état n'a pas changé ; rien n'est émis. |

| Champ inconnu dans la saisie | Ignoré. |

| Un abonné lève une erreur, ou rend une promesse rejetée | Les autres abonnés sont appelés ; `appliquerReponse` rend son résultat normalement. |
| `reponseDonnee` de plus de 2000 caractères | Coupée à 2000. |
