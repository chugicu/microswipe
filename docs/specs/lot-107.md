### 6.2 Fonctions pures (`regles.js`)

Aucun accès à `indexedDB`, `fetch`, `window`, `document`, `Date`, `Math.random`. Aucune fonction ne modifie ce qu'elle reçoit.

| Constante ou fonction | Valeur, ou entrée → sortie |
|---|---|
| `TYPES_RANGES` | `internes` |
| `TYPES_DE_PAQUET_DEMANDABLES` | `internes`, `admin` |
| `MAGASIN_CONTENU` | `contenu` |
| `lireEnregistrement(valeur, type)` | → l'enregistrement s'il est utilisable, `null` sinon : `valeur` est un objet simple ; `type` égal au type demandé ; `versionContenu` entier ≥ 0 ; `recuLe` texte ; `controlerFormeDuPaquet(paquet)` sans défaut ; `paquet.type` égal à `type` ; `paquet.versionContenu` égal à `versionContenu`. |
| `deciderApresReponse(reponse, type)` | → `{ action, motif, erreur }` : voir ci-dessous. `erreur` n'est rempli que pour le motif `refus`. |
| `creerEnregistrement(paquet, recuLe)` | → `{ type: paquet.type, versionContenu: paquet.versionContenu, recuLe, paquet }`. |
| `gelerEnProfondeur(objet)` | → le même objet, gelé (`Object.freeze`) à tous les niveaux. |

**`deciderApresReponse`**, dans cet ordre ; le premier cas qui s'applique donne la décision :

| Cas | `action` | `motif` |
|---|---|---|
| `reponse` n'est pas un objet simple, ou `reponse.ok` n'est pas un booléen | `garder` | `reponse_illisible` |
| `reponse.ok` vaut `false` | `garder` | `refus` (avec `erreur` = `reponse.erreur` si c'est un texte, sinon texte vide) |
| `reponse.aJour` vaut `true` | `garder` | `a_jour` |
| `reponse.aJour` n'est pas `false`, ou `reponse.paquet` absent | `garder` | `reponse_illisible` |
| `controlerFormeDuPaquet(reponse.paquet)` rend au moins un défaut | `garder` | `paquet_mal_forme` |
| `reponse.paquet.type` différent de `type` | `garder` | `type_inattendu` |
| `reponse.versionContenu` n'est pas un entier ≥ 0, ou diffère de `reponse.paquet.versionContenu` | `garder` | `version_incoherente` |
| Sinon | `remplacer` | `nouvelle_version` |

Une version reçue **plus petite** que la version locale remplace quand même : le serveur est la référence (`CLAUDE.md`, règle d'architecture 5 ; `lot-306.md` § 7, `versionLocale` plus grande que la version courante).

### 6.3 Chargeur (`chargeur.js`)

**`creerChargeurDeContenu(dependances)`** — `dependances` :

| Dépendance | Rôle |
|---|---|
| `obtenirBase()` | Rend une promesse de la base (lot 104). Peut rejeter : le chargeur travaille alors sans stockage. |
| `source(type, versionLocale)` | Rend une promesse d'une réponse de la forme de `lot-306.md` § 6.1. Peut rejeter (réseau, délai). |
| `maintenant()` | Texte ISO 8601 en UTC. |

Rend :

| Membre | Rôle |
|---|---|
| `pret` | Promesse résolue quand le paquet rangé a été relu, ou trouvé absent ou inutilisable. **Ne rejette jamais.** |
| `lirePaquet(type)` | Synchrone. → le paquet en cours de ce type, gelé en profondeur, ou `null`. `type` vaut `internes` s'il est absent. Rend le même objet tant qu'il n'est pas remplacé. |
| `versionContenuLocale(type)` | Synchrone. → `versionContenu` du paquet en cours, ou `null` s'il n'y en a pas. `type` vaut `internes` s'il est absent. |
| `etat(type)` | Synchrone. → `{ present, versionContenu, range, dernierResultat }` : `range` dit si le paquet en cours est enregistré dans IndexedDB ; `dernierResultat` est le dernier résultat de `charger`, ou `null`. |
| `charger(type)` | Promesse ; voir ci-dessous. `type` vaut `internes` s'il est absent. |
| `evenements` | Un `EventTarget` qui émet `contenu-change`, avec `detail` = `{ type, versionContenu }`. |

**Au démarrage** (`pret`) :

1. `base = await obtenirBase()` ; rejet → pas de stockage pour toute la durée de vie du chargeur (`range` reste faux), sans erreur remontée.
2. Pour chaque type de `TYPES_RANGES` : `lireEnregistrement(await base.lire('contenu', type), type)`. Utilisable → le paquet devient le paquet en cours (gelé), `range` vrai, `contenu-change` émis. `null` → aucun paquet ; **l'enregistrement inutilisable n'est pas supprimé** : il sera remplacé au prochain paquet reçu.
3. Une erreur de lecture est traitée comme « aucun paquet », écrite par `console.error` avec son code seulement.

**`charger(type)`** :

1. `type` absent de `TYPES_RANGES` → rejet `type_non_range`. (Le mode test charge le paquet « admin » par son propre chargeur, `lot-213.md` § 6.1.)
2. Un seul chargement à la fois par type : un appel pendant un chargement rend la promesse en cours.
3. `await pret`.
4. `reponse = await source(type, versionContenuLocale(type))`. Rejet → résultat `{ resultat: 'garde', motif: 'source_indisponible' }`.
5. `decision = deciderApresReponse(reponse, type)`. `garder` → résultat `{ resultat: decision.motif === 'a_jour' ? 'a_jour' : 'garde', motif, erreur }`.
6. `remplacer` :
   1. `enregistrement = creerEnregistrement(reponse.paquet, maintenant())` ;
   2. s'il y a une base : `base.ecrire('contenu', enregistrement)` ; un échec → un second essai ; un second échec → `range` faux, `console.error` avec le code seulement ;
   3. le paquet en cours est remplacé par `reponse.paquet`, gelé ; `contenu-change` est émis ;
   4. résultat `{ resultat: 'remplace', motif: 'nouvelle_version' }`.
7. Le résultat devient `dernierResultat` et la promesse le rend. **`charger` ne rejette que pour `type_non_range`.**

Rien de ce que journalise le chargeur ne contient une valeur du paquet : seulement des codes, des types et des versions.

**Partie en cours** : le chargeur remplace le paquet dès qu'il l'a reçu. Une partie déjà créée garde ses questions préparées (`lot-201.md` § 6.6) ; choisir de recharger seulement entre deux parties est le rôle du lot 307.

## 7. Cas limites

| Cas | Comportement attendu |
|---|---|
| Première ouverture, rien de rangé | `pret` sans paquet ; `charger` reçoit le paquet fictif, le range, émet `contenu-change`. |
| Ouverture suivante, même version | Paquet relu dans IndexedDB et émis tout de suite ; la source répond `aJour` ; rien n'est réécrit. |
| Jeu fictif modifié avec une version augmentée (lot 102, choix 9) | Le nouveau paquet remplace l'ancien à l'ouverture suivante. |
| Jeu fictif modifié **sans** augmenter la version | L'ancien paquet reste : c'est voulu, la version fait foi. |
| Version reçue plus petite que la version locale | Le paquet reçu remplace l'ancien. |
| Source qui rejette | Le paquet en cours reste ; résultat `garde`, `source_indisponible`. |
| Source qui répond `ok: false` (`reglage_invalide`, `paquet_refuse`…) | Le paquet en cours reste ; résultat `garde`, motif `refus`, avec le code. |
| Paquet reçu mal formé, d'un autre type, ou de version incohérente | Le paquet en cours reste ; motif correspondant ; rien n'est écrit. |
| Enregistrement rangé inutilisable (forme ancienne, champ manquant) | Ignoré au démarrage, remplacé au prochain paquet reçu ; jamais supprimé à part. |
| IndexedDB indisponible (`ouvrirBaseDuJeu` rejette) | Le paquet reçu reste en mémoire ; `range` faux ; aucune erreur visible ; rechargé à chaque ouverture. |
| Écriture refusée deux fois (quota) | Même chose. |
| `charger('admin')` | Rejet `type_non_range`. |
| Deux `charger()` simultanés | Une seule demande à la source. |
| Un module modifie le paquet rendu par `lirePaquet` | Impossible : le paquet est gelé ; en mode strict, une erreur. |
| `versionContenuLocale()` avant tout paquet | `null`. Le lot 308 refuse une réponse dont `versionContenu` n'est pas un entier : aucune partie ne doit être jouée sans contenu (point signalé de l'index). |
| Deux onglets ouverts | Chacun a son chargeur ; le dernier qui écrit l'emporte ; même version, donc même paquet. |

13. **Stockage indisponible** : `obtenirBase` rejette → `pret` résolu ; `charger()` → `remplace`, `etat().range` faux, `lirePaquet()` non nul.
14. **Écriture en échec** : base dont `ecrire` rejette deux fois → paquet en mémoire, `range` faux, `contenu-change` émis ; base dont `ecrire` rejette une fois → `range` vrai.

19. **Rien de journalisé qui vienne du contenu** : avec un paquet fictif où une cellule vaut `Valeur repérable 42` et une base dont `ecrire` rejette, aucun message passé à `console.error` ne contient ce texte (doublure de `console.error`).
