## 1. Objectif

Permettre à un admin de contenu de parcourir et de jouer tout le jeu, sans que rien ne compte :

- tous les mondes, niveaux et boss ouverts, mondes invisibles compris ;
- les questions non validées jouables, depuis le paquet « admin » ;
- une bannière permanente, pour ne jamais confondre avec le jeu réel ;
- aucune trace : ni progression, ni étoiles, ni file de synchronisation, ni reprise ; la progression réelle de l'admin reste intacte.

### 6.3 État du mode test (`mode-test.js`)

`creerModeTest(dependances)` — `dependances` : `lireDroits`, `chargerPaquetAdmin`, `indexerPaquet`.

| Membre | Rôle |
|---|---|
| `estActif()` | → booléen. Faux au démarrage. |
| `entrer()` | Promesse. Voir le déroulé ci-dessous. |
| `quitter()` | Passe à inactif, oublie l'index du paquet « admin », émet `mode-test-change`. Sans effet si déjà inactif. |
| `indexAdmin()` | → l'index du paquet « admin » quand le mode est actif ; `null` sinon. |
| `evenements` | Un `EventTarget` qui émet `mode-test-change`. |

`modeTestDuJeu` : l'instance unique, créée avec `lireDroits` et `chargerPaquetAdmin` de `acces.js`.

Déroulé de `entrer()` :

1. Déjà actif → ne fait rien.
2. `droits = await lireDroits()`. `droits.contenu` différent de `true` → rejet `droit_refuse` ; rien ne change.
3. `paquet = await chargerPaquetAdmin()`. Échec → rejet `paquet_admin_indisponible`.
4. `paquet.type` différent de `admin` → rejet `paquet_inattendu`.
5. `indexerPaquet(paquet)` ; le mode devient actif ; `mode-test-change` est émis.

**L'état n'est écrit nulle part** : ni IndexedDB, ni `localStorage`, ni adresse de la page. Un rechargement revient au jeu normal. L'index du paquet « admin » ne vit qu'en mémoire.

### 6.4 Entrée, écran Admin et bannière

**Entrée « Admin »** de la navigation du bas : présente si `lireDroits()` a rendu `contenu: true`, absente sinon et tant que la réponse n'est pas arrivée. Le contrôle est refait au démarrage de l'appli ; le lot 303 le refera à chaque connexion.

**Écran Admin** : son seul contenu, dans ce lot, est le bouton d'entrée dans le mode test. Un appui appelle `modeTestDuJeu.entrer()` :

- réussite → la carte du mode test s'affiche ;
- `droit_refuse`, `paquet_admin_indisponible`, `paquet_inattendu` → un message sur l'écran, et le jeu normal reste en place.

**Bannière** (`banniere.js`) :

- visible sur **tous** les écrans tant que `estActif()` est vrai, écrans de jeu et de fin de niveau compris ; absente sinon ;
- porte le texte du mode et un bouton de sortie ; une seconde ligne, vide par défaut, reçoit le texte du § 6.8 ;
- ne recouvre aucune commande de jeu : les écrans se décalent, selon `docs/design-system.md` ;
- se met à jour sur `mode-test-change`.

**Sortie** : le bouton de la bannière appelle `quitter()`, puis affiche la carte normale. Une partie de test en cours est abandonnée sans rien enregistrer.

**Textes** — **confirmés par l'auteur le 16 novembre** (conversation C ; design system § 12.2) :

| Bouton de l'écran Admin | « Entrer en mode test » |

### 6.8 Affichage réservé à l'admin (`regles.js`)

**`texteEtatDeLaQuestion(idQuestion, etatDesQuestions)`** → le texte de la seconde ligne de la bannière pendant une question :

| Cas | Texte |
|---|---|
| `etatDesQuestions[idQuestion].servie` vaut `true` | `<ID> · servie aux internes` |
| `servie` vaut `false` | `<ID> · non servie : <motifs séparés par une virgule et une espace>` |
| `etatDesQuestions` nul, ou sans entrée pour cette question | `<ID> · état inconnu` |

Les motifs sont les codes de `lot-306.md` § 6.3, affichés tels quels (par exemple `question_non_validee`).

**`resumeDuNiveauPourAdmin(niveauPrepare, etatDesQuestions)`** → `{ servies, prevues, ecartees }` pour la fiche de niveau :

- `prevues` = `niveauPrepare.prevues` ;
- `servies` = nombre de questions de `niveauPrepare.questions` dont `etatDesQuestions` dit `servie: true` ;
- `ecartees` = `niveauPrepare.ecartees`, tel quel.

La fiche de niveau, en mode test seulement, ajoute un bloc de texte secondaire :

- `Internes : <servies> questions servies sur <prevues> prévues` ;
- puis une ligne par question écartée : `<ID> : <motif>` (motifs du `lot-201.md` § 6.2) ;
- puis une ligne par anomalie du monde quand la fiche est celle du boss : le code de l'anomalie (`lot-208.md` § 6.3).

Aucune de ces lignes n'apparaît hors du mode test. Elles n'affichent **ni énoncé, ni réponse, ni valeur d'un fait** : seulement des identifiants, des nombres et des codes.

## 7. Cas limites

| Cas | Comportement attendu |
|---|---|
| Compte sans droit « contenu » | Pas d'entrée « Admin ». `entrer()` appelé quand même → `droit_refuse`. |
| Fournisseur de droits absent, lent ou en échec | Aucun droit : pas d'entrée « Admin ». |
| Page servie depuis l'adresse publique, en phase 2 | Droit provisoire refusé. |
| Chargeur du paquet en échec | `paquet_admin_indisponible` ; le jeu normal reste en place. |
| Le chargeur rend un paquet de type `internes` | `paquet_inattendu` ; le mode test ne s'ouvre pas. |
| Rechargement de la page en mode test | Retour au jeu normal, sans bannière. |
| Sortie pendant une partie de test | Partie abandonnée ; rien n'est enregistré ; retour à la carte normale. |
| Partie réelle interrompue, puis mode test, puis sortie | La reprise de la partie réelle est proposée comme avant. |
| Monde invisible | Présent et ouvert sur la carte de test ; absent de la carte normale. |
| Question non validée | Jouable en mode test ; la bannière dit `non servie` et pourquoi. |
| Question dont la valeur n'a pas de correspondance | Non jouable, même en mode test : elle figure dans les questions écartées de la fiche. C'est par là qu'elle remonte à l'admin. |
| Niveau sans aucune question jouable | Non jouable ; sa fiche liste les questions écartées. |
| Boss dont la réserve est plus petite que `Questions du boss` | Jouable en mode test avec toute la réserve ; anomalie `reserve_insuffisante` sur sa fiche. |
| Boss dont les règles sont illisibles | Jouable avec toute sa réserve ; anomalie `regles_du_boss_illisibles` sur sa fiche. |
| Niveau jamais débloqué dans la progression réelle | Jouable en mode test ; toujours verrouillé sur la carte normale après la sortie. |
| Fin d'une partie de test | Aucune ligne de progression créée ni modifiée ; la carte normale est identique à ce qu'elle était. |
| Re-test en mode test | L'événement porte `reTest: true` et `modeTest: true`. |
| Droit retiré pendant le mode test | Le mode reste actif jusqu'à la sortie ou au rechargement : il ne contient que ce que le serveur a déjà servi. Les lots 303 et 307 traiteront l'effacement du paquet. |

## 9. Critères d'acceptation

1. `node --test` passe en entier ; les tests 1 à 21 existent.
2. `client/mode-test/regles.js` n'accède ni à `document`, ni à `location`, ni à `indexedDB`, ni à `Date`, ni à `Math.random`.
