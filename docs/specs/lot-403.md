# Lot 403 — Recalcul complet de l'ELO, par tranches

Phase 4. Dépend des lots 213 et 402 (et, par eux, des lots 301, 302, 308, 309 et 401). Domaine de tests obligatoire : **moteur ELO**.
Spec écrite en phase 0, lot 4b, conversation 5 (16 novembre 2026). **Lis d'abord `docs/specs/lot-401.md` et `docs/specs/lot-402.md` en entier** : le moteur, les onglets et les conversions n'y sont pas recopiés.

Décisions de l'auteur du 16 novembre 2026 appliquées ici :

1. **Le lot ne recalcule que l'ELO** : les quatre colonnes ELO de `Scores`, tout `Etalonnage`, la clé `vues` de `Suivi`. Ni `Progression`, ni `Étoiles`, ni `Records`, ni les autres clés de `Suivi`.
2. **Lancement par un bouton de l'espace Admin**, entrée « Recalcul de l'ELO » de l'écran Admin. L'écran appelle le serveur en boucle, une tranche par appel. La même opération se lance aussi depuis l'éditeur Apps Script, en secours.

5. **Réglages figés** : si un réglage ELO, ou le palier, le plancher ou la mention « simplifiée » d'une question déjà lue change avant la fin, le recalcul repart de zéro tout seul.
6. **Bascule** d'un seul coup, sous le verrou, à la fin. Pendant le recalcul, le jeu et la synchronisation continuent sur l'ELO actuel.
7. Les autres choix par défaut et les textes de l'écran, acceptés le même jour (§ 6.9).

## 1. Objectif

Recalculer l'ELO de tous les internes et de toutes les questions depuis le journal, avec les réglages actuels :

- après la simulation du lot 5, quand l'auteur saisit les valeurs ELO ;
- après tout changement de réglage ELO ;
- pour rattraper les réponses reçues avant le lot 402, ou sans réglages valides ;
- pour réparer un paquet compté deux fois après une exécution interrompue (`lot-402.md` § 7).

Le travail tient dans plusieurs exécutions Apps Script (limite de 6 minutes chacune), reprend après une interruption, et donne **exactement** le résultat du calcul au fil de l'eau quand les réglages n'ont pas changé.

## 6. Interfaces

### 6.1 Vocabulaire

- **Tranche** : un appel de `eloRecalculTranche`. Il lit des **blocs** de lignes du journal tant que sa durée de travail n'est pas écoulée.
- **Position** : l'année en cours de lecture (son rang dans la liste des années) et le numéro de la prochaine ligne à lire.
- **État du recalcul** : l'objet du § 6.3, gardé dans un fichier texte privé du dossier des données entre deux tranches.
- **Bascule** : la dernière étape, sous le verrou, qui lit les dernières lignes et écrit les résultats.

### 6.3 État du recalcul

Un objet JSON simple :

```
{
  v: 1,
  empreinte: "<empreinteDesReglagesElo au départ>",
  annees: [ 2027, 2028 ],
  position: { rang: 0, ligne: 2 },
  phase: "lecture",
  elo: <état du lot 401 : internes, questions, vues, sansEffet>,
  derniers: { "<ID compte>|<installation>": <dernier numéro lu> },
  infosLues: { "<ID question>": "<palier>|<plancher>|<oui ou non>" },
  lignesLues: 0,
  doublons: 0,
  lignesIllisibles: 0,
  redemarrages: 0,
  lanceLe: "<ISO 8601>",
  lancePar: "<ID compte>"
}
```

**Fonctions pures**

| Fonction | Entrée → sortie |
|---|---|
| `listerAnneesDuJournal(noms)` | `noms` : les noms des propriétés du script. → les années de `MODELE_PROPRIETE_JOURNAL`, en entiers, triées par ordre croissant, sans doublon. |
| `creerEtatDeRecalcul(empreinte, annees, lanceLe, lancePar, redemarrages)` | → l'objet ci-dessus, `position` = `{ rang: 0, ligne: 2 }`, `phase` = `lecture`, `elo` = `creerEtatElo()`, compteurs à 0 sauf `redemarrages`. |
| `completerLesAnnees(etat, annees)` | Ajoute à `etat.annees`, en fin de liste, les années plus grandes que la dernière connue. Une année plus petite que la dernière connue, absente de la liste → lève `journal_inattendu`. Modifie `etat`. |
| `signatureDeLaQuestion(info)` | → `"<palier>|<plancher>|<oui ou non>"`. |
| `questionsChangees(etat, questions)` | → vrai si une clé de `etat.infosLues` a une signature différente dans `questions`, ou en est absente alors qu'elle y était. Une question absente au départ et toujours absente ne compte pas. |
| `estALaFin(etat)` | → vrai si `position.rang` ≥ `annees.length`. |

`infosLues` garde une entrée par question lue, présente ou non dans `questions` (valeur `absente` dans ce cas).

### 6.4 Lecture des lignes du journal

**`appliquerLignesDuJournal(etat, lignes, questions, reglagesLus)`** — modifie `etat`, comme `appliquerReponseElo`. `lignes` : objets aux noms de `COLONNES_LUES_DU_JOURNAL`, dans l'ordre du journal.

Pour chaque ligne, dans l'ordre :

1. `etat.lignesLues` + 1.
2. `ID` ne tient pas `MODELE_ID_REPONSE`, ou `ID compte` est vide → `lignesIllisibles` + 1, ligne ignorée.
3. `cle` = `<ID compte>|<installation>`. Numéro inférieur ou égal à `derniers[cle]` → `doublons` + 1, ligne ignorée. **C'est la règle de la synchronisation** (`lot-308.md` § 6.6) : un numéro déjà dépassé est un doublon.
4. `derniers[cle]` = le numéro.
5. Si `infosLues` n'a pas la question : y ranger sa signature, ou `absente`.
6. `appliquerReponseElo(etat.elo, reponse, questions, reglagesLus)`, avec `reponse` :
   - `idCompte`, `question`, `mode` : les textes des cellules ;
   - `reTest` : la cellule vaut `oui` ;
   - `resultat` : `Number(cellule)` si la cellule n'est pas vide, `null` sinon ;
   - `reponsesProposees` : l'entier si la cellule tient `^[0-9]+$`, `null` sinon.

Une ligne d'une valeur inattendue ne lève jamais : elle finit en réponse sans effet (lot 401), comptée dans `elo.sansEffet`.

**`avancerLaPosition(etat, nombreLu, tailleDuBloc)`** — modifie `etat` : `position.ligne` + `nombreLu` ; si `nombreLu` < `tailleDuBloc`, l'année est finie : `position.rang` + 1 et `position.ligne` = 2.

### 6.5 Bascule et résumé

**`ecrituresDeLaBascule(etat, scores, etalonnage, suivi, reglagesLus, maintenant)`** — fonction pure.

Entrée : `scores` et `etalonnage` = `{ enTete, lignes }` rendus par `lireOnglet` (ou `null` si l'onglet manque) ; `suivi` = tableau de `{ idCompte, numero, etatSuivi }` déjà décodés.

Sortie :

```
{
  scores:     { entieres: [ { numero, valeurs } ], nouvelles: [ [ … ] ] },
  etalonnage: { entieres: [ { numero, valeurs } ], nouvelles: [ [ … ] ] },
  suivi:      [ { idCompte, numero, etatSuivi } ],     // numero nul : ligne à créer
  resume:     <resumeDuRecalcul>
}
```

Règles :

- **`Scores`** — pour chaque ligne existante, la ligne entière dans l'ordre de son en-tête :
  - compte présent dans `etat.elo.internes` : les quatre colonnes de `cellulesDeScores(interne, estProvisoire(…), maintenant)` remplacent les siennes ;
  - compte absent : ses quatre colonnes ELO sont vidées (texte vide) ;
  - **`ID compte`, `Étoiles`, `Records` et toute autre colonne gardent leur valeur** ;
  - ligne de même `ID compte` qu'une ligne précédente : vidée comme un compte absent (seule la première porte l'ELO).
  - Chaque compte de l'état sans ligne → une ligne `nouvelles`, par `ligneSelonEnTete`.
- **`Etalonnage`** — même règle, colonne `Question` :
  - question présente dans `etat.elo.questions` : les cinq cellules de `ligneDEtalonnage(…, maintenant)` ;
  - question absente : ses quatre cellules autres que `Question` sont vidées ;
  - chaque question de l'état sans ligne → une ligne `nouvelles`.
- **`Suivi`** — pour chaque entrée de `suivi` : `ecrireVuesDansLeSuivi(etatSuivi, <numéros des questions de etat.elo.vues[idCompte], ou tableau vide>)`. Chaque compte de `etat.elo.internes` sans entrée → une entrée à créer, à partir de `{ v: 1, installations: {} }`. **Les autres clés de chaque état sont gardées telles quelles.**
- Onglet `Scores` ou `Etalonnage` nul : toutes ses lignes sont `nouvelles`, avec l'en-tête du lot 402 (l'onglet sera créé).

Seules les lignes dont une valeur change sont dans `entieres`.

**`resumeDuRecalcul(etat)`** → `{ reponses, internes, questions, doublons, lignesIllisibles, redemarrages, sansEffet }`, où `reponses` = `lignesLues − doublons − lignesIllisibles`, `internes` et `questions` les nombres de clés de `etat.elo.internes` et `etat.elo.questions`. **Des nombres seulement.**

### 6.6 Service (`logique/elo-recalcul-service.js`)

**Messages**

```
{ "action": "eloRecalculEtat", "session": "<jeton>" }
{ "action": "eloRecalculTranche", "session": "<jeton>", "ordre": "lancer" }
```

**`traiterEtatDuRecalcul(idCompte, dependances)`** → :

```
{
  ok: true,
  etat: "aucun",                        // ou "en_cours"
  reglages: { valide: false, defauts: [ { cle, defaut } ] },
  aRecalculer: { raison, depuis },      // ou null
  dernier: <resume> et "termineLe",     // ou null
  avancement: { annee, rang, annees, lignesLues, phase }   // ou null
}
```

Elle commence par `exigerDroit(idCompte, 'contenu')` et n'écrit rien. **Aucune valeur de réglage ni de contenu n'est rendue** : seulement des noms de clés, des raisons, des dates et des nombres.

**`traiterTrancheDeRecalcul(message, idCompte, dependances)`** → `{ ok: true, termine, avancement, resume }` (`resume` seulement quand `termine` est vrai), ou une erreur.

`dependances` : `exigerDroit`, `maintenant`, `tempsEcouleMs`, `sousVerrou(fn, attenteMs)`, `lireReglagesBruts`, `lireQuestions`, `listerNomsDeProprietes`, `lireEtatDuRecalcul`, `ecrireEtatDuRecalcul`, `lirePropriete`, `ecrirePropriete`, `effacerPropriete`, `lireBlocDuJournal(annee, premiereLigne, nombre)`, `lireOngletsDeLaBascule()`, `ecrireLaBascule(ecritures)`, `journaliserErreur`. `tempsEcouleMs` rend les millisecondes depuis le début de l'appel.

Propriétés (noms de la cible réelle ; la cible d'essai les préfixe de `ESSAI_`) : `RECALCUL_ELO_ETAT` (`aucun` ou absente, `en_cours`), `RECALCUL_ELO_ID_FICHIER` (fichier de l'état), `RECALCUL_ELO_TRANCHE` (JSON `{ debut }` de la tranche en cours), `RECALCUL_ELO_DERNIER` (JSON du dernier résumé, avec `termineLe`).

Déroulé :

1. `exigerDroit(idCompte, 'contenu')`. `ordre` hors de `ORDRES_DE_RECALCUL` → `message_invalide`.
2. **Prise de la tranche**, sous `sousVerrou` (attente habituelle) :
   1. `RECALCUL_ELO_TRANCHE` présente et `debut` à moins de `DUREE_MAX_D_UNE_TRANCHE_MS` de `maintenant()` → `recalcul_deja_en_cours`. Une tranche plus ancienne est une exécution tuée : elle ne bloque plus.
   2. `ordre` = `lancer` et `RECALCUL_ELO_ETAT` = `en_cours` → `recalcul_deja_en_cours`.
   3. `ordre` = `continuer` et état différent de `en_cours` → `recalcul_non_lance`.
   4. `ordre` = `lancer` : `lus = lireReglagesElo(lireReglagesBruts())` ; non valide → erreur `reglages_invalides`, avec `defauts`. Sinon `creerEtatDeRecalcul(empreinte, listerAnneesDuJournal(…), maintenant(), idCompte, 0)`, `ecrireEtatDuRecalcul`, puis `RECALCUL_ELO_ETAT` = `en_cours` **en dernier**.
   5. `RECALCUL_ELO_TRANCHE` = `{ debut: maintenant() }`.
3. Dans un `try` / `finally` qui efface `RECALCUL_ELO_TRANCHE` :
   1. `etat = lireEtatDuRecalcul()`. `completerLesAnnees(etat, listerAnneesDuJournal(…))`.
   2. **Contrôle des réglages et des questions** : `bruts = lireReglagesBruts()` ; `lus = lireReglagesElo(bruts)` ; non valide → `ecrireEtatDuRecalcul(etat)`, erreur `reglages_invalides` (le recalcul reste en cours ; il reprendra quand les réglages seront corrigés). `questions = indexerQuestionsElo(lireQuestions())`. Si `empreinteDesReglagesElo(bruts)` diffère de `etat.empreinte`, ou si `questionsChangees(etat, questions)` : **redémarrage** — `etat = creerEtatDeRecalcul(<nouvelle empreinte>, <années>, etat.lanceLe, etat.lancePar, etat.redemarrages + 1)`.
   3. **Lecture**, si `etat.phase` = `lecture` : tant que `estALaFin(etat)` est faux et `tempsEcouleMs()` < `DUREE_TRAVAIL_PAR_TRANCHE_MS` : `lignes = lireBlocDuJournal(annee, ligne, TAILLE_BLOC_RECALCUL)` ; `appliquerLignesDuJournal` ; `avancerLaPosition`. Après un bloc, si `INTERVALLE_SAUVEGARDE_MS` s'est écoulé depuis la dernière sauvegarde : `ecrireEtatDuRecalcul(etat)`.
   4. Pas à la fin → `ecrireEtatDuRecalcul(etat)`, rend `{ termine: false, avancement }`.
   5. **Bascule**, à la fin de la lecture ou si `etat.phase` vaut déjà `bascule`. Sous `sousVerrou(…, ATTENTE_VERROU_BASCULE_MS)` :
      1. relit `bruts` et `questions` ; empreinte ou questions changées → redémarrage comme à l'étape 3.2, `ecrireEtatDuRecalcul`, rend `{ termine: false }` ;
      2. `completerLesAnnees`, puis lit, bloc après bloc, les lignes arrivées depuis la position (sans limite de durée) ;
      3. `etat.phase` = `bascule` ; `ecrireEtatDuRecalcul(etat)` ;
      4. `ecritures = ecrituresDeLaBascule(etat, …lireOngletsDeLaBascule(), lus, maintenant())`. Un état de `Suivi` illisible → erreur `suivi_illisible`, **rien n'est écrit** ;
      5. `ecrireLaBascule(ecritures)` : `Etalonnage`, puis `Scores`, puis `Suivi` ;
      6. `ELO_EMPREINTE` = l'empreinte ; `effacerPropriete(ELO_A_RECALCULER)` ;
      7. `RECALCUL_ELO_DERNIER` = le résumé et `termineLe` ; `ecrireEtatDuRecalcul({})` ; `RECALCUL_ELO_ETAT` = `aucun` **en dernier**.
   6. Rend `{ termine: true, avancement, resume }`.
4. Une erreur est passée à `journaliserErreur` puis relancée.

**Reprise** : une tranche coupée repart de la dernière sauvegarde de l'état. Les lignes relues ne comptent pas deux fois : l'état sauvegardé et sa position vont ensemble. Une bascule coupée est refaite en entier à l'appel suivant (`phase` = `bascule`) : ses écritures remplacent des lignes entières, elles peuvent être refaites sans dommage.

**Pourquoi la bascule tient le verrou** : sinon une synchronisation pourrait écrire l'ELO au fil de l'eau entre la lecture des dernières lignes et l'écriture des résultats. Pendant la bascule, une synchronisation reçoit `occupe` et le téléphone la renvoie plus tard (`lot-309.md` § 6.6).

### 6.7 Branchements (`serveur/elo-recalcul.js`, `stockage.js`)

**Opérations ajoutées au module de stockage**

| Fonction | Rôle |
|---|---|
| `lireIntervalle(idFichier, onglet, colonnes, premiereLigne, nombre)` | → les lignes `premiereLigne` à `premiereLigne + nombre − 1`, bornées à la dernière ligne remplie, en tableau d'objets nom de colonne → valeur. Une seule lecture de plage. Colonne absente → `colonne_introuvable`. Commence par `verifierLectureAutorisee`. |
| `listerNomsDeProprietes()` | → les noms des propriétés du script, sans leurs valeurs. |

**Cibles**

| Champ | `CIBLE_RECALCUL_REELLE` | `CIBLE_RECALCUL_ESSAI` |
|---|---|---|
| `cibleElo` | `CIBLE_ELO_REELLE` | `CIBLE_ELO_ESSAI` |
| `journal(annee)` | fichier de la propriété `JOURNAL_<annee>`, onglet `Reponses` | fichier `ID_ELO_FICTIF`, onglet `Reponses <annee>` |
| `annees()` | `listerAnneesDuJournal(listerNomsDeProprietes())` | les années des onglets `Reponses <AAAA>` du fichier fictif |
| `prefixe` | (aucun) | `ESSAI_` |
| `nomDuFichierDEtat` | `recalcul-elo-etat.json` | `recalcul-elo-essai-etat.json` |

- `lireBlocDuJournal` : propriété `JOURNAL_<annee>` absente, ou fichier qui ne s'ouvre pas → `journal_introuvable`. En-tête sans une des colonnes de `COLONNES_LUES_DU_JOURNAL` → `journal_incomplet`. **Une année n'est jamais sautée.**

## 7. Cas limites

| Cas | Comportement attendu |
|---|---|
| Réglages inchangés depuis le fil de l'eau | `Scores`, `Etalonnage` et `vues` identiques, sauf `Calculé le`. |
| Palier modifié après le premier étalonnage d'une question | Le recalcul repart du nouveau palier : **écart voulu** avec le fil de l'eau (`lot-401.md` § 7). |
| Paquet compté deux fois après une exécution tuée (`lot-402.md` § 7) | Les lignes en double du journal sont des doublons : comptées une fois. **Le recalcul répare l'écart.** |
| Réponses reçues sans réglages valides, ou avant le lot 402 | Comptées : le recalcul lit tout le journal. |
| Réglages invalides au lancement | `reglages_invalides`, rien ne démarre, rien ne change. |
| Réglages rendus invalides pendant le recalcul | La tranche s'arrête avec `reglages_invalides` ; le recalcul reste en cours et reprend une fois corrigés. |
| Réglage valide modifié pendant le recalcul | Redémarrage depuis zéro ; `redemarrages` + 1. |
| Palier, plancher ou « simplifiée » d'une question déjà lue modifié pendant le recalcul | Redémarrage. Une question encore jamais lue peut changer sans redémarrage. |
| Réponses reçues pendant le recalcul | Au journal ; lues par les tranches suivantes ou par la bascule. Le fil de l'eau continue sur l'ancien état. |
| Nouveau fichier Journal créé pendant le recalcul (1er janvier) | Ajouté à la liste des années ; lu. |
| Propriété `JOURNAL_<AAAA>` d'une année passée apparue après coup | `journal_inattendu` : arrête-toi et demande. |
| Fichier Journal introuvable ou sans `Réponses proposées` | Arrêt avec l'erreur. Aucune année n'est sautée. |
| Ligne à `Réponses proposées` vide (réponse reçue avant l'amendement) | Sans effet (`hasard_inconnu`), comptée dans le résumé. La question est marquée « vue » si le mode le dit. |
| Aucune année de journal | Le recalcul va droit à la bascule : toutes les colonnes ELO sont vidées. |
| Tranche tuée par la limite de 6 minutes | La suivante repart de la dernière sauvegarde ; `RECALCUL_ELO_TRANCHE` ne bloque plus après 6 minutes. |
| Écran fermé pendant le recalcul | Le recalcul reste en cours ; l'écran propose `Reprendre` à la prochaine ouverture, à n'importe quel admin. |
| Deux admins appuient en même temps | Le second reçoit `recalcul_deja_en_cours`. |
| Bascule tuée en cours d'écriture | Refaite en entier à l'appel suivant. |
| Synchronisation pendant la bascule | `occupe` ; le téléphone renvoie plus tard. |
| Compte avec une ligne `Scores` mais aucune ligne au journal | Colonnes ELO vidées ; `Étoiles` et `Records` intacts. |
| Question avec une ligne `Etalonnage` mais plus étalonnée (simplifiée, interne provisoire après changement de réglage) | Ses quatre cellules sont vidées ; la ligne reste. |
| État de `Suivi` illisible | `suivi_illisible`, rien n'est écrit. |
| Réponse du mode test | Jamais dans le journal : rien à faire. |
