### 6.4 Lecture du tableur (`logique/conversion-regles.js`)

Le **tableur lu**, donné aux fonctions pures :

```
{
  noms: [ 'Lisez-moi', 'Sources', … ],            // tous les onglets, dans l'ordre du classeur
  matrices: { 'Sources': [ [ … ], [ … ] ], … }    // valeurs brutes, seulement pour les onglets du plan qui existent
}
```

Une matrice est un tableau de lignes ; la ligne d'indice 0 est la ligne 1 de la feuille. Les valeurs sont celles de `getValues()` : texte, nombre, booléen ou date.

| Fonction | Entrée → sortie |
|---|---|
| `classerLesOnglets(noms)` | → `{ repris, nonRepris, inconnus, manquants }`, quatre tableaux de noms. `repris` : dans le plan et dans `noms`. `nonRepris` : dans `ONGLETS_NON_REPRIS` et dans `noms`. `inconnus` : dans `noms`, ni dans le plan ni dans `ONGLETS_NON_REPRIS`. `manquants` : dans le plan, absents de `noms`. |
| `lireOngletDuTableur(matrice)` | → `{ enTete, enDouble, lignes }` (voir ci-dessous). |
| `estUneDate(valeur)` | → vrai si `Object.prototype.toString.call(valeur)` vaut `[object Date]`. |

`lireOngletDuTableur(matrice)` :

- `enTete` : les textes de la ligne `LIGNE_D_EN_TETE_DU_TABLEUR`, passés par `texteDeCellule`, **à leur position** (un texte vide pour une cellule vide). Matrice plus courte que cette ligne → `enTete` vide.
- `enDouble` : les noms d'en-tête non vides présents plus d'une fois.
- `lignes` : une entrée par ligne de la feuille située après l'en-tête : `{ numero, vide, cellules }`. `numero` est le numéro de la ligne dans la feuille (5 pour la première). `cellules` : objet nom d'en-tête non vide → **valeur brute**. `vide` est vrai si `texteDeCellule` de chaque cellule de la ligne est un texte vide.
- Les lignes 1 à 3 du tableur (titre, description) ne sont pas lues.

### 6.5 Identifiants et rapprochements (`logique/conversion-regles.js`)

| Fonction | Entrée → sortie |
|---|---|
| `formaterIdentifiant(prefixe, chiffres, numero)` | → `prefixe` suivi de `numero` complété par des zéros à gauche jusqu'à `chiffres` caractères. Un numéro plus long est écrit en entier (`ABL-1000`). `numero` qui n'est pas un entier ≥ 1 → lève `erreur_interne`. |
| `prochainNumero(identifiants, prefixe)` | → 1 + le plus grand numéro parmi les textes de `identifiants` qui ont la forme `prefixe` suivi de chiffres seuls ; 1 s'il n'y en a aucun. Les autres textes sont ignorés. **Fournie pour les lots 505 et 506** ; ce lot ne l'appelle que dans ses tests. |
| `aLaFormeDUnIdentifiant(texte)` | → vrai si `texte` correspond à `FORME_D_IDENTIFIANT`. |
| `motsDUneCellule(texte)` | → les suites de lettres non accentuées et de chiffres de `texte` (découpage sur l'expression `[^A-Za-z0-9]+`), sans les suites vides. |
| `indexerLesEspeces(lignesConverties)` | `lignesConverties` : les lignes converties de l'onglet `REFERENCE_DES_ESPECES.onglet`, sous forme d'objets en-tête → texte. → `{ parLibelle, identifiants }`. `parLibelle` : libellé → tableau des identifiants des lignes qui portent ce libellé exact. `identifiants` : tous les identifiants. |
| `lireLesIdEspece(texte)` | → les parties de `texte` séparées par `SEPARATEUR_DES_ID_ESPECE`, sans espaces autour, sans les parties vides. |
| `chercherIdEspece(libelle, indexDesEspeces)` | → l'identifiant si `parLibelle[libelle]` contient **exactement un** identifiant ; `null` sinon (aucun, ou plusieurs). Test par propriété propre. |

**Règle de `ID espèce`** pour une ligne d'un onglet dont `taxon` n'est pas nul :

1. `saisi = texteDeCellule(cellules['ID espèce'])` (texte vide si la colonne n'existe pas dans le tableur).
2. Si `saisi` n'est pas vide : la cellule cible vaut `saisi`, **tel quel**. Si au moins une partie de `lireLesIdEspece(saisi)` est absente de `index.identifiants` → un signalement `id_espece_inconnu` (la valeur est gardée).
3. Sinon `trouve = chercherIdEspece(texteDeCellule(cellules[taxon]), index)`. Non nul → la cellule cible vaut `trouve`.
4. Sinon la cellule cible est vide → signalement `id_espece_vide`.

Aucune autre règle : ni « spp. », ni casse, ni début de libellé, ni groupe. **N'en ajoute pas.**

**Règle des sources** pour une ligne d'un onglet dont `sources` n'est pas vide : `mots` = la réunion de `motsDUneCellule` sur le texte converti de chaque colonne de `sources`.

- aucun mot n'est un identifiant converti de l'onglet `Sources` → signalement `source_absente` ;
- un mot est dans `lignesEcartees` de l'entrée `Sources` du plan → signalement `source_ecartee_citee`.

Les deux peuvent s'appliquer à la même ligne. La valeur de la cellule n'est jamais modifiée.

### 6.6 Conversion d'un onglet (`logique/conversion-regles.js`)

`convertirUnOnglet(entree, ongletLu, contexte)` → `{ onglet, enTete, lignes, compte, signalements, colonnesIgnorees, colonnesEcartees }`.

- `entree` : une entrée du plan. `ongletLu` : le résultat de `lireOngletDuTableur`.
- `contexte` : `{ maintenant, idsDesSources, sourcesEcartees, especes }`. `idsDesSources` et `sourcesEcartees` sont des tableaux de textes ; `especes` est le résultat de `indexerLesEspeces`, ou `null` tant que l'onglet des espèces n'est pas converti.
- `enTete` : l'en-tête cible du § 6.3. `lignes` : un tableau de tableaux de textes, dans l'ordre de `enTete`.
- `compte` : `{ lues, vides, converties, ecartees, enAnomalie }`. `lues` = lignes non vides. `converties` = lignes de `lignes`. `ecartees` = `lues − converties`. `enAnomalie` = lignes converties portant au moins un signalement de gravité `anomalie`.
- `signalements` : tableau de `{ gravite, onglet, ligne, id, type, colonne, detail }` (§ 6.7).

Déroulé :

1. **Colonnes du tableur.** Pour chaque nom non vide de `ongletLu.enTete` qui n'est pas dans `entree.colonnes` : s'il finit par `SUFFIXE_DE_COLONNE_CALCULEE` → `colonnesEcartees` ; sinon → `colonnesIgnorees`. Pour un identifiant créé, une colonne `ID` présente dans le tableur va dans `colonnesIgnorees`. **Ni l'une ni l'autre liste ne produit d'erreur.**
2. **Défauts bloquants de structure** (un signalement `bloquant` chacun) :
   - `en_tete_en_double` : un nom de `ongletLu.enDouble` ;
   - `colonne_manquante` : une colonne de `entree.colonnes` absente de l'en-tête du tableur, sauf si elle est dans `entree.facultatives` ou si c'est la colonne d'un identifiant créé.

   S'il y en a au moins un, la fonction s'arrête là et rend `lignes` vide et un `compte` à zéro.
3. **Chaque ligne**, dans l'ordre de la feuille :
   1. `vide` vrai → comptée dans `vides`, rien d'autre.
   2. Identifiant repris : `id = texteDeCellule(cellules[colonne])`.
      - vide → ligne écartée, signalement `identifiant_absent` ;
      - dans `entree.lignesEcartees` → ligne écartée, signalement `ligne_ecartee_par_le_plan` ;
      - déjà rencontré dans l'onglet → signalement **bloquant** `identifiant_en_double` (la ligne est quand même comptée comme convertie ; rien ne sera écrit) ;
      - `aLaFormeDUnIdentifiant(id)` faux → signalement `identifiant_inattendu` (la ligne est convertie).
   3. Identifiant créé : `id = formaterIdentifiant(prefixe, chiffres, rang)`, où `rang` est le rang de la ligne parmi les lignes non vides de l'onglet, à partir de 1.
   4. `cleNaturelle` non nulle : si le couple de textes de ces colonnes a déjà été rencontré → signalement `cle_en_double` (la ligne est convertie).
   5. Chaque colonne de `entree.colonnes`, hors identifiant créé et hors `ID espèce` : `texteDeCellule(cellules[colonne])` ; texte vide si la colonne est facultative et absente du tableur.
      - valeur brute pour laquelle `estUneDate` est vrai → signalement `date_convertie` ;
      - valeur brute de type nombre dont le texte contient `e` ou `E` → signalement `nombre_en_notation_scientifique`.
   6. `ID espèce` : règle du § 6.5, si `entree.taxon` n'est pas nul.
   7. Sources : règle du § 6.5, si `entree.sources` n'est pas vide.
   8. Si `entree.validation` : `Statut` hors de `STATUTS_DU_TABLEUR` (texte vide compris) → signalement `statut_inconnu`. **La valeur est gardée telle quelle.**
   9. Colonnes ajoutées : `Champs validés` = texte vide ; `Archivé le` = texte vide ; `Modifié le` = `contexte.maintenant` ; `Modifié par` = `AUTEUR_DE_LA_CONVERSION`.

Les quatre colonnes de validation sont recopiées comme les autres colonnes. **La conversion ne passe jamais une ligne à « Validé » et ne retire jamais ce statut.**

### 6.7 Préparation complète et signalements (`logique/conversion-regles.js`)

**`preparerConversion(tableur, maintenant)`** → `{ convertible, onglets, classement, signalements, libellesSansEspece }`.

1. `classement = classerLesOnglets(tableur.noms)`. Chaque onglet de `manquants` → signalement bloquant `onglet_manquant`.
2. Convertit les onglets du plan présents, **dans l'ordre du plan**. Après l'entrée `Sources` : `idsDesSources` = les identifiants de ses lignes converties, `sourcesEcartees` = son `lignesEcartees`. Après l'entrée `Especes` : `especes = indexerLesEspeces(…)`.
3. `signalements` : ceux de tous les onglets, dans l'ordre du plan puis de la feuille, précédés de ceux de l'étape 1.
4. `libellesSansEspece` : pour chaque signalement `id_espece_vide`, regroupés : `{ onglet, libelle, lignes }` (nombre de lignes), dans l'ordre de première apparition.
5. `convertible` = aucun signalement de gravité `bloquant`.
6. `onglets` : les résultats de `convertirUnOnglet`, dans l'ordre du plan.

La fonction ne modifie pas `tableur` et ne lève pas pour un défaut du tableur : tout défaut est un signalement.

**Types de signalement**

| `type` | `gravite` | Sens | `detail` |
|---|---|---|---|
| `onglet_manquant` | `bloquant` | Un onglet du plan est absent du tableur. | vide |
| `colonne_manquante` | `bloquant` | Une colonne attendue est absente de la ligne d'en-tête. | vide (le nom est dans `colonne`) |
| `en_tete_en_double` | `bloquant` | Un nom de colonne apparaît deux fois. | vide |
| `identifiant_en_double` | `bloquant` | Deux lignes de l'onglet ont le même identifiant. | vide |
| `identifiant_absent` | `ecart` | Ligne non vide sans identifiant : non convertie. | vide |
| `ligne_ecartee_par_le_plan` | `ecart` | Ligne que le plan écarte (`S7`) : non convertie. | vide |
| `identifiant_inattendu` | `anomalie` | Identifiant qui n'a pas la forme lettres, tiret facultatif, chiffres. | vide |
| `cle_en_double` | `anomalie` | Deux lignes ont la même clé naturelle. | vide |
| `id_espece_vide` | `anomalie` | Aucun libellé exact unique dans `Especes`. | le libellé |
| `id_espece_inconnu` | `anomalie` | Identifiant saisi par l'auteur, absent de `Especes`. | la valeur saisie |
| `source_absente` | `anomalie` | La ligne ne cite aucun identifiant de `Sources`. | vide |
| `source_ecartee_citee` | `anomalie` | La ligne cite une source écartée. | l'identifiant de la source |
| `statut_inconnu` | `anomalie` | `Statut` hors des trois valeurs du tableur. | vide |
| `date_convertie` | `anomalie` | Une cellule date est devenue un texte ISO 8601. | vide |
| `nombre_en_notation_scientifique` | `anomalie` | Un nombre s'écrit avec un exposant. | vide |

`ligne` : numéro de la ligne dans le tableur, ou 0 pour un défaut d'onglet ou de colonne. `id` : l'identifiant de la ligne, ou un texte vide. `colonne` : le nom de la colonne concernée, ou un texte vide.

**Un `detail` peut contenir du contenu réel** (un libellé). Il ne va que dans le rapport, jamais dans le journal d'exécution, dans une erreur, dans `PROGRESS.md` ni dans un commit.

Toutes les lignes manquantes partent en un seul `ajouterReglages`. **Une clé déjà présente n'est jamais modifiée.**

11. `ecrireRapport(preparation, 'conversion', true)`, puis `journaliser(resumerPourLeJournal(preparation))`.

Les erreurs `relecture_differente` et `reprise_impossible` portent une propriété `ecarts` (onglet, lignes et colonnes, sans valeur) passée à `journaliserErreur`. Après l'une d'elles, l'état reste `en_cours` : **arrête-toi et demande** (§ 10).

## 7. Cas limites

| Cas | Comportement attendu |
|---|---|
| Onglet inconnu dans le tableur | Ignoré, non lu, cité dans `Resume` avec l'état `inconnu`. Aucune erreur. |
| Colonne inconnue dans un onglet repris | Non reprise, citée dans `Colonnes ignorées`. Aucune erreur, aucun signalement. |
| Colonne dont le nom finit par `(formule)` | Non reprise, citée dans `Colonnes calculées écartées`. |
| Colonnes du tableur dans un autre ordre | Sans effet : l'en-tête cible est celui du plan. |
| Colonne attendue absente ou renommée | `colonne_manquante`, bloquant : rien n'est écrit. |
| Onglet du plan absent | `onglet_manquant`, bloquant. |
| `ID espèce` absente du tableur | Colonne créée quand même ; remplie par libellé exact, vide sinon. |
| `Source` absente de `Phenotypes` ou de `Regles` | Colonne créée vide ; chaque ligne reçoit `source_absente`. |
| Ligne entièrement vide | Comptée dans `Lignes vides`. Ni écart ni anomalie. |
| Ligne non vide sans identifiant | Écartée, `identifiant_absent`. |
| Même identifiant sur deux lignes d'un onglet | `identifiant_en_double`, bloquant. |
| Même identifiant dans deux onglets différents | Sans effet : l'unicité se juge par onglet. |
| Ligne `S7` de `Sources` | Écartée, `ligne_ecartee_par_le_plan`. |
| Ligne de faits qui cite `S7` et une autre source | Convertie, `source_ecartee_citee`. |
| Ligne qui ne cite que `S7` | Convertie, `source_ecartee_citee` et `source_absente`. |
| `Source` vaut `S1 p.34`, ou `S1 ; S8` | Le mot `S1` est reconnu. |
| `Source` vaut `S10` alors que seul `S1` existe | Non reconnu : `source_absente`. |
| Libellé de taxon égal à celui de deux lignes de `Especes` | Aucun rapprochement : `id_espece_vide`. |
| Libellé qui ne diffère que par une majuscule ou un espace intérieur | Aucun rapprochement : `id_espece_vide`. |
| `ID espèce` saisie par l'auteur avec un identifiant inconnu | Valeur gardée telle quelle, `id_espece_inconnu`. |
| Ligne d'antibiogramme vide entre deux lignes | Elle ne consomme pas de numéro : les `ABL-` se suivent sans trou. |
| Colonne `ID` déjà présente dans `Antibiogrammes_types` ou `Vocabulaire` du tableur | Ignorée (`Colonnes ignorées`) : l'identifiant est créé par la conversion. |
| Deux lignes d'antibiogramme de même `Profil` et même `Antibiotique` | Deux identifiants différents, `cle_en_double`. |
| `Statut` vide, ou écrit `validé` | Gardé tel quel, `statut_inconnu`. Le lot 306 le traitera comme non validé. |
| Ligne « Validé » dans le tableur | Recopiée « Validé », avec son validateur et sa date. |
| Nombre (page, concentration) | Texte rendu par `texteDeCellule` : `34`, `0.5`. Aucun arrondi. |
| Cellule date | Texte ISO 8601 rendu par `texteDeCellule`, `date_convertie`. |
| Texte qui commence par `=` | Écrit précédé de `'` ; la relecture doit rendre le texte d'origine. |
| Texte avec des espaces autour | Espaces retirés (`texteDeCellule`), sans signalement. |

## 10. Points à me demander

Arrête-toi et pose la question, une à la fois, si :

- un prérequis du § 4 manque ou diffère, en particulier si `lireOnglet` ne rend pas les lignes telles qu'elles ont été écrites, ou si `ajouterLignes` refuse des lignes plus larges que la ligne 1 d'un onglet ;

- Sheets transforme une valeur à l'écriture (nombre, date, zéros de tête) alors que l'onglet est au format texte ;
- tu veux assouplir le rapprochement de `ID espèce`, déduire une source, corriger un statut ou compléter une valeur : ne le fais pas ;
- tu veux ajouter une colonne, un onglet ou un format d'identifiant que cette spec ne liste pas ;
- un nom de ce lot entre en collision avec un nom déjà déclaré dans le serveur ;
- la conversion du tableur fictif approche de la durée maximale d'une exécution Apps Script, ou un seul `ajouterLignes` par onglet ne passe pas ;
- quoi que ce soit demande d'ouvrir le tableur réel, de lancer `analyserTableur` ou `convertirTableur`, d'écrire dans le fichier Contenu de test hors de l'essai, ou de toucher à un fichier de production.
