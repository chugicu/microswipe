# Lot 506 — Import annuel : conflits et appliquer

Phase 5. Dépend des lots 505 et 315 (et, par eux, des lots 305 et 306). Domaines de tests obligatoires : **import** et **filtre des questions non validées**.
Spec écrite en phase 0, lot 4b, conversation 4 (16 novembre 2026). Le lot 505 prépare et compare : **lis `docs/specs/lot-505.md` § 6.1 à § 6.8 avant de commencer**, la forme de la comparaison n'est pas recopiée ici.

Décisions de l'auteur du 16 novembre 2026 appliquées ici :

1. **Un choix par conflit** : « production » ou « copie », pour la ligne entière.
2. **Comparaison refaite sous verrou** : si la production ou la copie a changé depuis le récapitulatif, l'application est refusée.
3. **Une sauvegarde** du fichier Contenu est faite juste avant la première écriture.
4. **Une ligne retirée est archivée, jamais effacée.** Aucune fonction de ce lot ne supprime une ligne, un onglet ni un fichier.
5. **Identifiants** : une ligne ajoutée reçoit le numéro suivant de son onglet, lignes archivées comprises. Une espèce nouvelle reçoit le préfixe `ESP-`. Une question ajoutée reçoit `Origine` = `import AAAA`.
6. **Le statut de validation vient de la copie**, comme toute autre colonne comparée.
7. **Question à réponse propre** : elle repasse à « À valider » quand la colonne qu'elle teste change, sauf si sa propre ligne est reprise de la copie.
8. **Historique** : une ligne par cellule modifiée, une par ligne ajoutée, une par ligne archivée ; canal `import`, auteur = l'`ID compte` de l'admin.
9. **Interruption** : le plan d'application est enregistré avant la première écriture ; la reprise le poursuit. Tant que l'application n'est pas finie, toute autre écriture de contenu est refusée et `contenu.version` ne bouge pas.
10. **Fin** : `contenu.version` + 1, puis reconstruction immédiate des paquets par le lot 306.
11. **ELO** : l'import n'a aucun accès au fichier Joueurs ni au Journal, et ne change aucun identifiant.

## 1. Objectif

Appliquer au fichier Contenu les différences que le lot 505 a montrées :

- faire choisir à l'admin, pour chaque conflit, la version à garder ;
- vérifier sous verrou que rien n'a changé depuis le récapitulatif ;
- écrire les lignes modifiées, ajouter les lignes nouvelles, archiver les lignes retirées, repasser à « À valider » les questions à réponse propre dont le fait change ;
- tracer chaque changement dans `Historique` ;
- augmenter la version du contenu et faire reconstruire les paquets ;
- reprendre proprement après une interruption.

## 6. Interfaces

### 6.1 Message et réponse

Message, quand l'import est dans l'état `preparee` :

```
{ "action": "importAppliquer", "session": "<jeton>", "empreinte": "1234-0a1b2c3d",
  "choix": { "RN_specifiques:RNS-253": "copie", "Regles:REG-012": "production" } }
```

- `empreinte` : celle du récapitulatif que l'admin a vu (`lot-505.md` § 6.8).
- `choix` : une entrée par conflit ; la clé est la `cle` de la ligne ; la valeur est `production` ou `copie`. Objet vide s'il n'y a aucun conflit.

Dans l'état `en_application` (reprise), `empreinte` et `choix` sont ignorés : le plan enregistré fait foi.

Réponse :

```
{ "ok": true, "termine": true,
  "etapes": { "faites": 6, "total": 6 },
  "resume": { "parOnglet": [ { "onglet": "RN_specifiques", "modifiees": 14, "ajoutees": 2, "archivees": 1 } ],
              "questionsRevalidees": 3, "lignesDHistorique": 41 },
  "versionContenu": 38,
  "paquets": { "ok": true, "erreur": "" } }
```

- `termine` faux : l'exécution s'est arrêtée avant la fin pour ne pas dépasser sa durée ; le téléphone rappelle l'action. `versionContenu` et `paquets` valent alors `null`.
- `paquets` : résultat de la reconstruction (§ 6.7) ; `{ ok: false, erreur: "<code>" }` si elle a échoué. **L'import reste appliqué dans les deux cas.**

Échecs : `{ "ok": false, "erreur": "<code>" }`.

| Code | Cause |
|---|---|
| `session_invalide`, `comptes_indisponibles`, `droit_refuse` | Comme au lot 505. |
| `message_invalide` | `empreinte` absente ou vide, `choix` qui n'est pas un objet (état `preparee` seulement). |
| `import_non_prepare` | État `aucun`. |
| `comparaison_perimee` | L'empreinte recalculée sous verrou diffère de celle du message. |
| `import_bloque` | La comparaison a au moins un blocage. |
| `choix_incomplet` | Un conflit n'a pas de choix. |
| `choix_invalide` | Une clé de `choix` n'est pas un conflit, ou sa valeur n'est ni `production` ni `copie`. |
| `rien_a_appliquer` | Le plan ne contient aucune écriture. |
| `contenu_incomplet` | Un onglet à écrire n'a pas de colonne `Archivé le`, `Modifié le` ou `Modifié par`. |
| `plan_illisible` | Reprise : le plan enregistré est absent ou ne se décode pas. |
| `ligne_introuvable` | Une ligne à écrire n'existe pas exactement une fois dans la production. |
| `relecture_differente` | Une cellule relue après écriture diffère de ce qui devait être écrit. |
| `occupe` | Verrou non obtenu. |

### 6.3 Plan d'application (`logique/import-application.js`)

**`construireLePlan(comparaison, choix, etats, contexte)`** → le plan. `contexte` : `{ importId, auteur, date, annee, versionAvant, identifiants }` — `auteur` est l'`ID compte` de l'admin, `date` vaut `maintenant()`, `annee` ses quatre premiers caractères, `versionAvant` la valeur de `contenu.version` lue sous le verrou, `identifiants` un objet onglet → `{ prefixe, chiffres }` (`IDENTIFIANTS_DES_LIGNES_AJOUTEES` en vrai).

```
{
  v: 1, importId, auteur, date, versionAvant,
  etapes: [
    { onglet: "Faits_fictifs",
      ecritures: [ { id: "FF-02", valeurs: { "Colonne A": "Valeur A2 bis", "Modifié le": "<date>", "Modifié par": "<auteur>" } } ],
      ajouts:    [ { id: "FF-14", valeurs: { "ID": "FF-14", "Libellé": "Bactérie N", … } } ],
      historique: [ [ <neuf cellules> ], … ] }
  ],
  resume: { parOnglet: [ { onglet, modifiees, ajoutees, archivees } ], questionsRevalidees, lignesDHistorique }
}
```

Une étape par onglet qui a au moins une écriture ou un ajout, **dans l'ordre du périmètre** (`Questions` en dernier). Le plan est un objet JSON simple : il est enregistré tel quel.

Pour chaque ligne de la comparaison, selon sa catégorie :

| Catégorie | Effet dans le plan |
|---|---|
| `modifiee` ; `conflit` de motif `modifiee_des_deux_cotes` avec le choix `copie` | Une écriture : pour chaque colonne de `colonnesChangees`, la valeur de `copie`. Une ligne d'historique par colonne : `avant` = valeur de `production`, `apres` = valeur de `copie`. Comptée dans `modifiees`. |
| `retiree` ; `conflit` de motif `retiree_dans_la_copie` avec le choix `copie` | Une écriture : `Archivé le` = `date`. Une ligne d'historique : colonne `Archivé le`, `avant` vide, `apres` = `date`. Comptée dans `archivees`. |
| `ajoutee` | Un ajout (voir ci-dessous). Une ligne d'historique : colonne `ID`, `avant` vide, `apres` = le nouvel identifiant. Comptée dans `ajoutees`. |
| `conflit` avec le choix `production` ; `retrait_refuse` ; `gardee_de_la_production` ; `creee_en_production` ; `identique_des_deux_cotes` ; `deja_archivee` ; `inchangee` | **Rien.** |

Règles communes :

- Chaque écriture porte aussi `Modifié le` = `date` et `Modifié par` = `auteur`. Ces deux colonnes n'ont pas de ligne d'historique.
- Une ligne d'historique = `construireLigneDHistorique({ date, auteur, canal: CANAL_DE_L_IMPORT, onglet, ligne: <identifiant>, colonne, avant, apres, motif: importId })`.
- L'en-tête de production de l'onglet doit porter `Archivé le`, `Modifié le` et `Modifié par` ; sinon lève `contenu_incomplet`.
- Aucune écriture → lève `rien_a_appliquer`.

**Lignes ajoutées.** Pour un onglet, dans l'ordre de la copie :

1. `numero = prochainNumero(<tous les identifiants de l'onglet en production, lignes archivées comprises>, prefixe)` pour la première ; `numero + 1` pour la suivante, etc.
2. `id = formaterIdentifiant(prefixe, chiffres, numero)`.
3. `valeurs` : une entrée par colonne de l'en-tête de **production** : la valeur de `copie` si la ligne la porte ; `ID` = `id` ; `Archivé le` = texte vide ; `Modifié le` = `date` ; `Modifié par` = `auteur` ; texte vide pour toute autre colonne.
4. Onglet `Questions` : `Origine` = `import ` suivi de `annee`, quoi que dise la copie.

Le statut d'une ligne ajoutée est celui que l'auteur a écrit dans la copie, vide compris. **Le code n'écrit jamais « Validé » de lui-même.**

**Questions à revalider.** `ids = questionsTouchees(comparaison, etats, choix).aRevalider` (lot 505). Pour chaque identifiant, sauf si la question est archivée par ce même plan :

- une écriture sur `Questions` : `Statut` = `STATUT_A_REVALIDER` ;
- une ligne d'historique : colonne `Statut`, `avant` = `STATUT_VALIDE`, `apres` = `STATUT_A_REVALIDER`, `motif` = `importId` suivi de `SUFFIXE_DU_MOTIF_DE_REVALIDATION` ;
- `questionsRevalidees` augmente de 1. Ces lignes ne comptent pas dans `modifiees`.

Les autres colonnes de validation de la question (`Validé par`, `Date de validation`) ne sont pas touchées.

### 6.4 Exécution d'une étape (`logique/import-application.js`)

**`executerUneEtape(etape, plan, clesDejaTracees, dependances)`** — `dependances` : `lireOnglet(onglet)`, `ajouterAHistorique(lignes)`, `ecrireLignesEntieres(onglet, lignes)`, `ajouterLignes(onglet, lignes)`. `clesDejaTracees` : un `Set` de textes `<Onglet>|<Ligne>|<Colonne>|<Motif>` déjà présents dans `Historique` pour cet import.

1. `lu = lireOnglet(etape.onglet)`.
2. **Historique d'abord.** Les lignes de `etape.historique` dont la clé n'est pas dans `clesDejaTracees` partent en **un seul** `ajouterAHistorique` ; leurs clés sont ajoutées à l'ensemble.
3. **Écritures.** Pour chaque écriture : la ligne de `lu` dont `ID` égale `id` ; aucune ou plusieurs → lève `ligne_introuvable`. La nouvelle ligne entière = les textes actuels de la ligne (`texteDeCellule` de chaque cellule, dans l'ordre de l'en-tête), remplacés par ceux de `valeurs`. Si elle est identique à l'actuelle, elle n'est pas réécrite. Les lignes à réécrire partent en **un seul** `ecrireLignesEntieres`, chaque cellule passée par `protegerTexte`.
4. **Ajouts.** Ceux dont l'`id` n'existe pas déjà dans `lu` partent en **un seul** `ajouterLignes`, dans l'ordre de l'en-tête, chaque cellule passée par `protegerTexte`.
5. **Relecture.** `lireOnglet` de nouveau : chaque cellule nommée par une écriture ou un ajout doit valoir le texte attendu (après `texteDeCellule`, sans la protection). Sinon lève `relecture_differente`, avec une propriété `ecarts` : au plus 20 objets `{ onglet, id, colonne }`, **sans valeur**.

Cette fonction peut être exécutée deux fois de suite sur la même étape sans rien changer la seconde fois : c'est ce qui permet la reprise.

### 6.5 Déroulé complet (`logique/import-application.js`)

**`appliquerLImport(message, idCompte, dependances)`** → la réponse du § 6.1.

`dependances` : celles du lot 505 (`exigerDroit`, `lirePropriete`, `ecrirePropriete`, `sousVerrou`, `maintenant`, `lireLesTroisEtats`, `perimetre`, `journaliserErreur`), plus : `identifiants()`, `lireVersion()`, `augmenterVersion()`, `assurerOngletHistorique()`, `sauvegarderLeContenu(nom)`, `ecrirePlan(texte)`, `lirePlan()` (rend le texte ou `null`), `lireClesDHistorique(importId)` (rend le `Set` du § 6.4), les quatre fonctions du § 6.4, `tempsEcouleMs()` (depuis le début de l'exécution), `regenererLesPaquets(idCompte)` (rend `{ ok, erreur }` ou `null`).

1. `exigerDroit(idCompte, 'contenu')`.
2. Dans **un seul** `sousVerrou` :
   1. `exigerDroit` de nouveau.
   2. État `aucun` → lève `import_non_prepare`.
   3. **État `preparee`** — rien n'est encore écrit dans le fichier Contenu :
      1. `empreinte` qui n'est pas un texte non vide, ou `choix` qui n'est pas un objet (tableau et `null` refusés) → `message_invalide` ;
      2. `etats = lireLesTroisEtats()` ; `comparaison = comparerLesTroisEtats(etats, perimetre())` ;
      3. `empreinteDeLaComparaison(comparaison)` différente de `message.empreinte` → `comparaison_perimee` ;
      4. `comparaison.applicable` faux → `import_bloque` ;
      5. `verifierLesChoix(comparaison, message.choix)` ;
      6. `plan = construireLePlan(…)`, avec `versionAvant = lireVersion()` ;
      7. `assurerOngletHistorique()` ;
      8. `sauvegarderLeContenu('Microbio – Contenu – avant ' + importId)` ; son identifiant va dans la propriété `ID_SAUVEGARDE` ;
      9. `ecrirePlan(JSON.stringify(plan))` ; `AVANCEMENT` = `0` ; puis **en dernier** `ETAT` = `en_application`.
   4. **État `en_application`** (reprise) : `plan = JSON.parse(lirePlan())` ; texte nul, illisible, ou `plan.importId` différent de la propriété `ID` → `plan_illisible`.
   5. `cles = lireClesDHistorique(plan.importId)` (une seule lecture par exécution).
   6. Pour chaque étape, à partir du rang `AVANCEMENT` : si `tempsEcouleMs()` dépasse `DUREE_MAX_D_UNE_EXECUTION_MS`, sortir de la boucle ; sinon `executerUneEtape`, puis `AVANCEMENT` = rang + 1.
   7. S'il reste des étapes : rendre `termine: false`.
   8. **Finalisation** : si `lireVersion()` vaut encore `plan.versionAvant`, `augmenterVersion()` ; puis `ETAT` = `aucun`, et la propriété `DERNIER` = `JSON.stringify({ importId, appliqueLe: maintenant(), resume })`.
3. Hors du verrou, si l'application est terminée : `paquets = regenererLesPaquets(idCompte)`.
4. Rend la réponse.

Une erreur à l'étape 2.6 ou 2.8 est passée à `journaliserErreur` (avec `ecarts` s'il y en a) puis relancée ; l'état reste `en_application`.

**Ce qui en découle**

- Tant que l'état vaut `preparee`, un échec ne laisse aucune trace dans le fichier Contenu.
- Dès que l'état vaut `en_application`, les seules actions possibles sur le contenu sont la reprise de cette application : le contrôle commun du lot 315 refuse les autres, et les actions du lot 505 répondent `import_en_cours`.
- `contenu.version` n'augmente qu'une fois, à la fin : pendant une application interrompue, les paquets ne sont pas reconstruits et les internes gardent l'ancien contenu (`lot-306.md` § 6.7).
- La reprise ne refait pas la comparaison : elle exécute le plan enregistré.

### 6.6 Ce que l'import ne peut pas faire

À vérifier par les tests et par relecture du code :

- **aucune suppression** : `dependances` n'a aucune fonction qui retire une ligne, un onglet ou un fichier ;
- **aucun accès aux joueurs** : `dependances` n'a aucune fonction qui lit ou écrit le fichier Joueurs ou un fichier Journal ; l'ELO d'une question, rangé dans `Etalonnage` sous son identifiant, ne peut donc pas changer ;
- **aucun identifiant modifié** : aucune écriture ne nomme la colonne `ID` ; seul un ajout la remplit ;
- **aucun numéro réutilisé** : le numéro d'une ligne ajoutée est supérieur à tous ceux de l'onglet, lignes archivées comprises ;
- **aucun « Validé » écrit par le code** : un statut « Validé » ne peut venir que d'une cellule de la copie.

### 6.7 Branchements (`stockage.js`, `import-application.js`)

**Opération ajoutée au module de stockage**

| Fonction | Rôle |
|---|---|
| `ecrireLignesEntieres(idFichier, onglet, lignes)` | `lignes` : tableau de `{ numero, valeurs }`, où `valeurs` est un tableau dans l'ordre de l'en-tête et de même longueur que lui, et `numero` ≥ 2. Écrit chaque ligne en entier. Les lignes de numéros consécutifs sont écrites ensemble, en une seule écriture par bloc. Commence par `verifierEcritureAutorisee`. Longueur incorrecte ou numéro en double → `ligne_invalide`, rien n'est écrit. |

**Fichier du plan** : `import-plan.json` (`import-essai-plan.json` pour l'essai), fichier texte privé du dossier des données, créé à la première application, remplacé en entier aux suivantes. **Il contient des valeurs du contenu** et ne sort jamais du serveur.
