## 1. Objectif

Donner à toute l'appli **une seule source de valeurs visuelles** et les premiers composants communs :

- les jetons du design system en variables CSS, dans un seul fichier ;
- les polices hébergées dans le dépôt, mises en cache par le service worker ;
- les matières (paillasse, gélose) et la table des milieux ;
- les boutons, la fiche, le dialogue, le scotch et les étoiles, prêts pour les lots 106, 202, 203 et 207 ;
- le dialogue de rechargement du lot 107 rebranché sur le dialogue commun, sans changer ce que voit l'interne ;
- une page qui montre tous ces composants à l'auteur.

### 6.7 Dialogue commun (`regles-dialogue.js`, `dialogue.js`)

**Le seul dialogue de l'appli.** Tout dialogue présent ou futur (rechargement, recalcul de l'ELO, import annuel, outils du mode test…) passe par `ouvrirDialogue`.

**`preparerDialogue(options)`** (pure) — lève une erreur `dialogue_mal_forme` si une option obligatoire manque ou n'a pas le bon type ; sinon rend un objet gelé :

| Option | Type | Défaut | Dans le résultat |
|---|---|---|---|
| `titre` | Texte non vide | — (obligatoire) | `titre` |
| `texte` | Texte | — (obligatoire) | `texte` |
| `action` | `{ libelle: texte non vide, surAppui: fonction }` | — (obligatoire) | `boutons[0]` = `{ role: 'action', libelle }` |
| `secondaire` | `{ libelle: texte non vide, surAppui: fonction }` | `{ libelle: 'Annuler', surAppui: () => {} }` | `boutons[1]` = `{ role: 'secondaire', libelle }` |
| `irreversible` | Booléen | `false` | `fermerSurVoile` = `!irreversible` ; `fermerSurEchap` = `true` |

Une option inconnue est ignorée. `surAppui` n'est pas recopié dans le résultat (il reste dans les options).

**`ouvrirDialogue(options)`** → `{ element, fermer() }`. Appelle `preparerDialogue` (l'erreur remonte), puis :

- **Aspect** (§ 9.11) : voile `--voile` (plan `--plan-dialogue`) ; dialogue centré, largeur `100% − --marge-dialogue`, au plus `--largeur-dialogue-max`, `--surface`, rayon `--rayon-3`, padding `--esp-6`, ombre `--ombre-4` ; titre `--texte-titre-2`, couleur `--texte` ; texte `--texte-corps` ; boutons `.bouton-principal` (action) et `.bouton-secondaire`, **empilés** (action en haut), espacés de `--esp-3` ; **au-delà de 600 px de large, côte à côte, l'action à droite**, de largeur égale. Hauteurs : celles du § 9.1 (60 et 50 px), même côte à côte (constat de l'auteur, lot 107).
- **Ouverture** (§ 7.6) : voile en fondu, `--duree-moyenne` ; dialogue de l'échelle 0,96 à 1 en fondu, `--duree-moyenne`, `--courbe-sortie`.
- **Fermeture** (décision 7) : l'inverse, `--duree-moyenne`, `--courbe-entree` ; l'élément est retiré de la page à la fin. La fermeture ne bloque rien : les rappels sont appelés au début de la fermeture.
- **Mouvement réduit** (`prefers-reduced-motion: reduce`) : fondu de `--duree-courte` à l'ouverture et à la fermeture, sans échelle.
- **Boutons** : un appui ferme le dialogue, puis appelle le `surAppui` du bouton. **Échap** = le bouton secondaire. **Toucher sur le voile** (hors du dialogue) = le bouton secondaire, sauf si `irreversible`.
- **Accessibilité** : `role="dialog"`, `aria-modal="true"`, `aria-labelledby` vers le titre, `aria-describedby` vers le texte ; à l'ouverture, le focus va au dialogue lui-même (`tabindex="-1"`, sans anneau visible) ; Tab et Maj+Tab restent dans le dialogue ; à la fermeture, le focus revient à l'élément qui l'avait avant l'ouverture, s'il est encore dans la page.
- **Un seul dialogue à la fois** : un `ouvrirDialogue` pendant qu'un dialogue est ouvert attend que le premier soit fermé, puis s'ouvre (dans l'ordre des appels). `fermer()` d'un dialogue en attente le retire de la file sans rien afficher.
- `fermer()` ferme sans appeler aucun `surAppui`. Un second `fermer()` ne fait rien.
- Le dialogue passe au-dessus d'une fiche ouverte (plan 60 contre 41).

## 7. Cas limites

| Cas | Comportement attendu |
|---|---|
| Clé `Milieu` vide, inconnue, en majuscules ou absente | `neutre`, sans erreur. |
| Clé `Milieu` ` sang ` (espaces) | `sang`. |
| Police pas encore chargée | Texte affiché tout de suite dans la police du système (`swap`), puis remplacé. |
| Hors ligne après la première visite | Polices servies par le cache de la coquille. |
| Caractère hors latin et latin étendu | Police du système pour ce caractère. |
| `installerMatieres()` appelé deux fois | Un seul `<svg>` de filtres dans la page. |
| Dialogue sans `secondaire` | Bouton « Annuler », qui ferme sans rien faire d'autre. |
| Dialogue sans `titre` ou sans `action` | Erreur `dialogue_mal_forme` ; rien ne s'affiche. |
| Deux `ouvrirDialogue` de suite | Le second attend la fermeture du premier. |
| Dialogue irréversible, toucher sur le voile | Rien. Échap ferme (bouton secondaire). |
| Élément d'avant retiré de la page pendant le dialogue | À la fermeture, le focus n'est pas déplacé. |
| Dialogue ouvert au-dessus d'une fiche | Le dialogue est au-dessus ; Échap ferme le dialogue seul. |
| Écran large (plus de 600 px) | Boutons du dialogue côte à côte, action à droite ; fiche centrée, au plus 480 px. |
| Écran bas (fiche plus haute que 88 % de l'écran) | La fiche mesure 88 % ; son contenu défile. |
| Mouvement réduit | Dialogue : fondu de 120 ms, sans échelle. Boutons : l'appui reste (c'est un retour au toucher), sans transition : passage direct à l'état appuyé et retour direct. |
| `angleDuScotch(10)`, `angleDuScotch('a')` | `3`, `0`. |
| `etatsDuTrio(5)`, `etatsDuTrio(-1)`, `etatsDuTrio(1.5)` | Trois vrais ; trois faux ; trois faux. |
| Base périmée pendant l'accueil | Le dialogue (plan 60) passe au-dessus de l'accueil, qui n'a pas de plan : cas quasi impossible, déjà accepté au lot 107. |
