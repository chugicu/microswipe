# Lot 306 — Paquets de contenu « internes » et « admin »

Phase 3. Dépend des lots 302 et 305 (et, par eux, du lot 301). Domaine de tests obligatoire : **filtre des questions non validées**.
Spec écrite en phase 0, lot 4b, conversation 2 (15 novembre 2026).
Amendée en conversation 4 (15 novembre 2026) : section `reglages` des deux paquets (point signalé 16 de l'index). Les ajouts sont les décisions 13 et 14, la fin des § 6.2 à § 6.6, et les tests 40 à 45.

Décisions de l'auteur du 15 novembre 2026 appliquées ici :

1. **Validation par champ** : pour un fait dont la ligne n'est pas « Validé », seules les colonnes listées dans `Champs validés` partent dans le paquet « internes », avec son `ID`. Aucune exception, pas même pour le libellé de la ligne.
2. Cette spec fixe la forme du paquet. Le lot 102 doit s'y conformer.
3. Le filtre du serveur applique la validation, la visibilité et l'archivage (schéma § 3.5, conditions 1 à 3). La condition 4 (valeur sans correspondance dans le niveau) reste au moteur de niveaux (lot 201).
4. Les niveaux de type `test` ne sont dans aucun paquet tant que le lot 313 ne les a pas ouverts.
5. `Mondes`, `Niveaux` et `Composition` sont filtrés sur la visibilité et l'archivage seulement.
6. Formats : `Champs validés` est une liste séparée par des points-virgules ; `Champ` contient un nom, ou autant de noms que de faits.
7. **Dans le doute, exclu** : tout ce que le filtre ne sait pas lire n'est pas servi aux internes.
8. Le paquet « internes » ne contient ni statut, ni nom de validateur, ni commentaire.
9. Un admin qui joue normalement reçoit le paquet « internes ». Le paquet « admin » n'est servi que sur demande explicite, après contrôle du droit « contenu ».
10. Les paquets sont reconstruits à la première demande qui suit un changement de `contenu.version`. Un paquet dont la version diffère de la version courante n'est jamais servi.
11. Avant d'enregistrer le paquet « internes », un second contrôle, écrit indépendamment du filtre, le relit. S'il trouve un défaut, rien n'est enregistré.
12. La recette se fait sur un fichier Contenu fictif créé par ce lot.
13. **Les deux paquets portent une section `reglages`** : tout l'onglet `Reglages`, clé → valeur, identique dans les deux paquets.
14. **Le serveur refuse de construire les paquets si les trois seuils d'étoiles manquent ou sont illisibles** (`reglage_invalide`). Une erreur de saisie dans `Reglages` reste ainsi sur le serveur au lieu de fermer tous les niveaux sur tous les téléphones.

## 1. Objectif

Écrire l'action `contenu` du serveur. Elle sert à un téléphone le paquet de contenu auquel son compte a droit :

- le paquet « internes », d'où **aucun élément non validé, invisible ou archivé ne peut sortir** ;
- le paquet « admin », qui contient aussi le contenu non validé et les mondes invisibles, pour le mode test, et qui n'est servi qu'aux comptes ayant le droit « contenu ».

Les deux paquets sont préparés à l'avance, rangés dans le dossier Drive des données, et remplacés en entier à chaque nouvelle version du contenu.

## 6. Interfaces

### 6.1 Message et réponse

Message :

```
{ "action": "contenu", "session": "<jeton>", "paquet": "internes", "versionLocale": 36 }
```

- `paquet` : `"internes"` ou `"admin"`.
- `versionLocale` : la version du paquet de ce type déjà présent sur le téléphone ; entier ≥ 0, ou `null` ou absent s'il n'en a pas.

Réponse quand le téléphone est à jour :

```
{ "ok": true, "aJour": true, "versionContenu": 37 }
```

Réponse sinon :

```
{ "ok": true, "aJour": false, "versionContenu": 37, "paquet": { … § 6.2 … } }
```

Échecs : `{ "ok": false, "erreur": "<code>" }`.

| Code | Cause |
|---|---|
| `session_invalide`, `comptes_indisponibles` | Rendus par le routeur (lot 302). |
| `message_invalide` | `paquet` ou `versionLocale` mal formé. |
| `droit_refuse` | Paquet « admin » demandé sans le droit « contenu ». |
| `occupe` | Verrou non obtenu en 20 secondes, ou paquet remplacé pendant sa lecture. |
| `contenu_incomplet` | Onglet ou colonne obligatoire absent du fichier Contenu, `Reglages` compris. |
| `structure_inattendue` | Colonne `Statut` présente dans `Mondes`, `Niveaux` ou `Composition`. |
| `contenu_incoherent` | Même `ID` sur deux lignes de `Mondes`, `Niveaux`, `Composition` ou `Questions`. |
| `paquet_refuse` | Le second contrôle a trouvé un défaut dans le paquet « internes ». |
| `reglage_invalide` | `contenu.version` absente ou non entière ; ou seuils d'étoiles absents ou illisibles (§ 6.4). |
| `reglage_en_double` | Même clé sur deux lignes de `Reglages`. |

### 6.2 Forme d'un paquet

```
{
  "type": "internes",
  "versionContenu": 37,
  "genereLe": "2027-01-12T14:03:22.000Z",
  "mondes": [ { "ID": "MON-01", "Nom": "Monde fictif 1", "Visible": "oui", … } ],
  "niveaux": [ { "ID": "NIV-0001", "Monde": "MON-01", … } ],
  "composition": [ { "ID": "CMP-000001", "Niveau": "NIV-0001", "Question": "Q-000001", "Ordre": "1" } ],
  "questions": [ { "ID": "Q-000001", "Monde": "MON-01", "Fait": "Faits_fictifs:FF-01", "Champ": "Colonne A", … } ],
  "faits": { "Faits_fictifs": [ { "ID": "FF-01", "Colonne A": "Valeur A1", … } ] },
  "compositionPrevue": { "NIV-0001": 3 },
  "reglages": { "contenu.version": "37", "etoiles.seuil_1": "60", "etoiles.seuil_2": "80", "etoiles.seuil_3": "100", … }
}
```

- Chaque ligne est un objet : nom d'en-tête exact du schéma → valeur. **Toutes les valeurs sont des textes**, passés par `texteDeCellule`.
- Les lignes gardent l'ordre de la feuille.
- `faits` : une clé par onglet de faits, dans l'ordre alphabétique ; un onglet sans ligne retenue n'a pas de clé.
- `compositionPrevue` : pour chaque niveau du paquet, le nombre de ses lignes de `Composition` non archivées, **avant** le filtre des questions. Il permet au lot 201 de savoir qu'un niveau est incomplet, sans rien révéler d'autre qu'un nombre.
- `reglages` : un objet clé → valeur, une entrée par ligne de l'onglet `Reglages` dont `Clé` n'est pas vide, dans l'ordre de la feuille. Clé et valeur sont des textes passés par `texteDeCellule` ; une `Valeur` vide donne un texte vide. Les colonnes `Description`, `Modifié le` et `Modifié par` n'y sont pas.
- La version d'un paquet reste `versionContenu`. `reglages["contenu.version"]` ne la remplace pas et n'est comparée à rien.
- Les nombres de cet exemple viennent du contenu fictif, pas du code.
- Le paquet « admin » a la même forme, la même section `reglages`, avec `"type": "admin"` et un champ en plus :

```
"etatDesQuestions": { "Q-000002": { "servie": false, "motifs": ["question_non_validee"] }, … }
```

### 6.3 Entrée du filtre et constantes (`logique/paquets-filtre.js`)

Le **contenu brut** donné aux fonctions pures :

```
{
  mondes:      { enTete, lignes },     // rendus par lireOnglet
  niveaux:     { enTete, lignes },
  composition: { enTete, lignes },
  questions:   { enTete, lignes },
  reglages:    { enTete, lignes },     // l'onglet Reglages
  faits: { "<Onglet>": { enTete, lignes }, … }   // seulement les onglets qui existent
}
```

| Constante | Valeur |
|---|---|
| `STATUT_VALIDE` | `Validé` |
| `VISIBLE_OUI` | `oui` |
| `SEPARATEUR_DE_LISTE` | `;` |
| `COLONNES_RESERVEES` | `Statut`, `Validé par`, `Date de validation`, `Commentaire du validateur`, `Champs validés`, `Archivé le`, `Modifié le`, `Modifié par` |
| `ONGLETS_DE_STRUCTURE` | `Mondes`, `Niveaux`, `Composition`, `Questions`, `Signalements`, `Historique`, `Reglages` |
| `TYPES_DE_NIVEAU_NON_OUVERTS` | `test` |
| `COLONNES_OBLIGATOIRES` | `Mondes` : `ID`, `Visible`, `Archivé le` ; `Niveaux` : `ID`, `Monde`, `Type`, `Archivé le` ; `Composition` : `ID`, `Niveau`, `Question`, `Archivé le` ; `Questions` : `ID`, `Monde`, `Fait`, `Champ`, `Statut`, `Archivé le` ; `Reglages` : `Clé`, `Valeur` |
| `CLES_SEUILS_ETOILES` | `etoiles.seuil_1`, `etoiles.seuil_2`, `etoiles.seuil_3` |
| `MOTIFS` | Dans cet ordre : `question_non_validee`, `monde_introuvable`, `monde_archive`, `monde_invisible`, `reference_illisible`, `champ_illisible`, `fait_introuvable`, `fait_en_double`, `fait_archive`, `champ_introuvable`, `fait_non_valide` |

Ces noms d'onglets et de colonnes sont ceux de la structure du schéma. **Aucun nom d'onglet de faits ni de colonne de faits n'est écrit dans le code** : ils viennent des colonnes `Fait`, `Champ` et `Champs validés`.

Les seules clés de `Reglages` écrites dans le code de ce lot sont `contenu.version` et celles de `CLES_SEUILS_ETOILES`. **Aucune valeur de seuil n'est écrite dans le code.**

Toute comparaison de cellule se fait après `texteDeCellule`. Une ligne dont `ID` est vide est ignorée partout ; dans `Reglages`, une ligne dont `Clé` est vide est ignorée.

### 6.4 Fonctions pures du filtre

| Fonction | Entrée → sortie |
|---|---|
| `estArchivee(valeurs)` | → vrai si `Archivé le` n'est pas vide. Colonne absente → faux. |
| `estValidee(valeurs)` | → vrai si `Statut` vaut exactement `STATUT_VALIDE`. Colonne absente → faux. |
| `lireListe(texte)` | → les parties séparées par `;`, sans espaces autour, sans les parties vides. |
| `lireReferences(texteFait)` | → tableau de `{ onglet, identifiant }`, ou `null`. Chaque partie de `lireListe` doit avoir la forme `Onglet:Identifiant` : un seul `:`, deux côtés non vides après retrait des espaces, et `Onglet` hors de `ONGLETS_DE_STRUCTURE`. Aucune partie, ou une partie mal formée → `null`. |
| `lireChamps(texteChamp, nombreDeFaits)` | → tableau de `nombreDeFaits` noms, ou `null`. Un seul nom dans `lireListe` → ce nom répété pour chaque fait. Autant de noms que de faits → ces noms, dans l'ordre. Tout autre nombre → `null`. |
| `ongletsDeFaitsCites(questions)` | → les noms d'onglets cités par les questions non archivées dont `Fait` est lisible, sans doublon, triés. |
| `verifierStructure(contenu)` | Lève `contenu_incomplet` si une colonne de `COLONNES_OBLIGATOIRES` manque (`Reglages` compris) ; `structure_inattendue` si `Mondes`, `Niveaux` ou `Composition` a une colonne `Statut` ; `contenu_incoherent` si un `ID` non vide apparaît deux fois dans `Mondes`, `Niveaux`, `Composition` ou `Questions`. |
| `champValide(ligneFait, champ)` | → vrai si `estValidee(ligneFait.valeurs)`, ou si `champ` est dans `lireListe(Champs validés)`. |
| `evaluerQuestion(question, contenu)` | → `{ servie, motifs }` pour une question non archivée. `servie` est vrai si `motifs` est vide. |
| `evaluerQuestions(contenu)` | → objet `ID` de question → `{ servie, motifs }`, pour toutes les questions non archivées. |
| `colonnesServies(onglet, ligneFait)` | → les en-têtes de l'onglet servis aux internes pour cette ligne (§ 6.5). |
| `construireReglages(contenu)` | → l'objet `reglages` du § 6.2 (voir ci-dessous). Lève `reglage_en_double`. |
| `verifierSeuilsEtoiles(reglages)` | → `[s1, s2, s3]`, trois entiers ; ou lève `reglage_invalide` (voir ci-dessous). |
| `construirePaquet(contenu, type, versionContenu, genereLe)` | → le paquet du § 6.2. Appelle d'abord `verifierStructure`, puis `construireReglages`, puis `verifierSeuilsEtoiles` sur son résultat : une erreur de l'une des trois empêche toute construction, quel que soit `type`. |
| `resumerPaquet(paquet)` | → `{ mondes, niveaux, composition, questions, faits, reglages }` : des nombres seulement (nombres de lignes ; pour `reglages`, nombre de clés). |

**Contrôles de `evaluerQuestion`.** Tous les motifs qui s'appliquent sont rendus, sans doublon, dans l'ordre de `MOTIFS`.

1. `estValidee` faux → `question_non_validee`.
2. Monde de rattachement (colonne `Monde`) : aucune ligne de `Mondes` de cet `ID` → `monde_introuvable` ; ligne archivée → `monde_archive` ; `Visible` différent de `VISIBLE_OUI` → `monde_invisible`.
3. `references = lireReferences(Fait)`. `null` → `reference_illisible` ; les contrôles 4 et 5 ne sont pas faits.
4. `champs = lireChamps(Champ, references.length)`. `null` → `champ_illisible` ; le contrôle 5 n'est pas fait.
5. Pour chaque couple (référence, champ) :
   1. l'onglet est absent de `contenu.faits`, ou n'a pas de colonne `ID` → `fait_introuvable` ;
   2. sinon, parmi les lignes de l'onglet dont `ID` égale l'identifiant : aucune → `fait_introuvable` ; plusieurs → `fait_en_double` ;
   3. sinon, pour la ligne trouvée : archivée → `fait_archive` ; `champ` absent de l'en-tête de l'onglet, ou présent dans `COLONNES_RESERVEES` → `champ_introuvable` ; sinon `champValide` faux → `fait_non_valide`.

Une question dont `Fait` cite un profil entier (schéma § 3.5) ne trouve aucune ligne de cet `ID` : elle reçoit `fait_introuvable` et n'est pas servie aux internes. C'est voulu jusqu'au lot 604.

**`construireReglages(contenu)`.** Pour chaque ligne de `contenu.reglages`, dans l'ordre de la feuille :

1. `cle = texteDeCellule(Clé)`. Clé vide → ligne ignorée.
2. Clé déjà rencontrée (test par `Object.prototype.hasOwnProperty.call`) → lève `reglage_en_double`.
3. Sinon `objet[cle] = texteDeCellule(Valeur)`.

La fonction ne lit aucune autre colonne. Onglet sans ligne → objet vide.

**`verifierSeuilsEtoiles(reglages)`.** Lève `reglage_invalide` si l'une de ces règles n'est pas tenue ; sinon rend les trois entiers.

1. Chaque clé de `CLES_SEUILS_ETOILES` est une propriété propre de `reglages`.
2. Chaque valeur correspond à `^[0-9]+$` (un texte vide, `60.5`, `abc`, `-1` sont refusés).
3. Chaque entier est compris entre 1 et 100.
4. `s1 ≤ s2 ≤ s3` (l'égalité est admise).

C'est la règle de `lireSeuilsEtoiles` du téléphone (`lot-201.md` § 6.3). **Si l'une des deux specs change cette règle, l'autre doit suivre.** Le lot 310 pourra réutiliser cette fonction.

### 6.5 Contenu de chaque paquet

**Paquet « internes »**

| Section | Lignes retenues | Colonnes |
|---|---|---|
| `mondes` | Non archivées et `Visible` = `oui`. | Toutes, sauf `COLONNES_RESERVEES`. |
| `niveaux` | Non archivées, dont le `Monde` est retenu, et dont le `Type` n'est pas dans `TYPES_DE_NIVEAU_NON_OUVERTS`. | Toutes, sauf `COLONNES_RESERVEES`. |
| `questions` | Non archivées et `servie` vrai. | Toutes, sauf `COLONNES_RESERVEES`. |
| `composition` | Non archivées, dont le `Niveau` et la `Question` sont retenus. | Toutes, sauf `COLONNES_RESERVEES`. |
| `faits` | Les lignes vers lesquelles pointe au moins une question retenue. | `colonnesServies` : voir ci-dessous. |
| `reglages` | Toutes les lignes de `Reglages` dont `Clé` n'est pas vide. | `Clé` → `Valeur` seulement (`construireReglages`). |

`colonnesServies(onglet, ligneFait)` :

- toujours `ID` ;
- si la ligne est « Validé » : tous les autres en-têtes de l'onglet, sauf `COLONNES_RESERVEES` ;
- sinon : seulement les en-têtes cités dans `lireListe(Champs validés)`, s'ils existent dans l'onglet et ne sont pas dans `COLONNES_RESERVEES`.

**Paquet « admin »**

| Section | Lignes retenues | Colonnes |
|---|---|---|
| `mondes` | Non archivées, visibles ou non. | Toutes. |
| `niveaux` | Non archivées, dont le `Monde` est retenu, et dont le `Type` n'est pas dans `TYPES_DE_NIVEAU_NON_OUVERTS`. | Toutes. |
| `questions` | Non archivées, quel que soit leur statut. | Toutes. |
| `composition` | Non archivées, dont le `Niveau` et la `Question` sont retenus. | Toutes. |
| `faits` | Les lignes non archivées vers lesquelles pointe au moins une question retenue (toutes celles de cet `ID` s'il y en a plusieurs). | Toutes. |
| `reglages` | Les mêmes que dans le paquet « internes ». | `Clé` → `Valeur` seulement. |
| `etatDesQuestions` | Une entrée par question retenue : le résultat de `evaluerQuestion`. | — |

**Les lignes archivées ne sont dans aucun paquet.**

`Reglages` n'a ni statut, ni visibilité, ni archivage : rien n'y est filtré, et la section est la même dans les deux paquets. **Conséquence : tout ce qui est rangé dans `Reglages` part sur le téléphone de chaque interne.** Un lot qui a besoin d'une valeur que le téléphone ne doit pas recevoir ne la range pas dans `Reglages`.

### 6.6 Second contrôle (`logique/paquets-controle.js`)

`controlerPaquetInternes(paquet, contenu)` → tableau de défauts `{ regle, onglet, id }` ; vide si tout est correct. **Un défaut ne contient jamais une valeur du contenu.**

Ce fichier est écrit comme si le filtre n'existait pas. Il ne peut appeler que `texteDeCellule`. Il découpe lui-même `Fait`, `Champ` et `Champs validés`, et relit lui-même `contenu.reglages`.

| `regle` | Défaut signalé |
|---|---|
| `type` | `paquet.type` ne vaut pas `internes`. |
| `colonne_reservee` | Une ligne de n'importe quelle section porte une des huit colonnes réservées. |
| `valeur_non_texte` | Une valeur d'une ligne, ou une valeur de `reglages`, n'est pas un texte. |
| `monde` | Un monde du paquet n'existe pas exactement une fois dans le contenu, est archivé, ou n'a pas `Visible` = `oui`. |
| `niveau` | Un niveau du paquet n'existe pas exactement une fois, est archivé, est de type `test`, ou son `Monde` n'est pas dans le paquet. |
| `question` | Une question du paquet n'existe pas exactement une fois, est archivée, n'est pas « Validé », ou son `Monde` n'est pas dans le paquet. |
| `composition` | Une ligne de composition du paquet n'existe pas exactement une fois, est archivée, ou son `Niveau` ou sa `Question` n'est pas dans le paquet. |
| `fait` | Une ligne de faits du paquet n'existe pas exactement une fois dans son onglet, ou est archivée. |
| `champ_non_valide` | Une ligne de faits du paquet porte une colonne, autre que `ID`, qui n'est pas un en-tête de son onglet, ou qui n'est validée ni par le statut de la ligne ni par `Champs validés`. |
| `valeur_modifiee` | Une valeur d'une ligne de faits du paquet diffère de la cellule d'origine passée par `texteDeCellule`. |
| `question_sans_fait` | Pour une question du paquet, un de ses couples (fait, champ) n'a pas sa ligne dans `paquet.faits`, ou cette ligne ne porte pas la colonne du champ. |
| `reglage` | Voir ci-dessous. |

**Règle `reglage`.** Le défaut a la forme `{ regle: 'reglage', onglet: 'Reglages', id: <la clé> }` ; `id` est un texte vide dans le premier cas. **`id` est la clé, jamais la valeur.**

1. `paquet.reglages` est absent, `null`, un tableau, ou n'est pas un objet. Les cas suivants ne sont alors pas examinés.
2. Une clé du paquet (propriété propre) n'existe pas exactement une fois dans la colonne `Clé` de l'onglet, après `texteDeCellule`.
3. La valeur d'une clé du paquet diffère de la cellule `Valeur` de sa ligne, passée par `texteDeCellule`.
4. Une clé non vide de l'onglet n'est pas dans le paquet.

Le second contrôle ne vérifie pas les seuils d'étoiles : `construirePaquet` l'a fait.

### 6.7 Service (`logique/paquets-service.js`)

| Fonction | Entrée → sortie |
|---|---|
| `TYPES_DE_PAQUET` | `internes`, `admin`. |
| `ATTENTE_VERROU_PAQUETS_MS` | 20 000. |
| `validerDemande(message)` | → `{ type, versionLocale }`, ou lève `message_invalide`. `versionLocale` absent ou `null` → `null` ; sinon un entier ≥ 0. |
| `preparerLesDeuxPaquets(contenu, versionContenu, genereLe)` | → `{ internes, admin }`, deux **textes** JSON. Construit les deux paquets, puis `controlerPaquetInternes`. Tableau non vide → lève `paquet_refuse`, après avoir attaché à l'erreur la propriété `defauts` (les 20 premiers). |
| `servirContenu(message, idCompte, dependances)` | → la réponse du § 6.1. |

`dependances` de `servirContenu` : `exigerDroit(idCompte, droit)`, `lireVersion()`, `lireVersionDesPaquets()` (entier ou `null`), `sousVerrou(fn, attenteMaxMs)`, `lireContenu()`, `ecrirePaquet(type, texte)`, `ecrireVersionDesPaquets(version)`, `lirePaquet(type)` (rend un texte), `maintenant()`, `journaliserErreur(contexte, erreur)`.

Déroulé de `servirContenu` :

1. `demande = validerDemande(message)`.
2. Si `demande.type` vaut `admin` : `exigerDroit(idCompte, 'contenu')`. **Avant toute lecture du contenu ou d'un paquet.**
3. `version = lireVersion()`.
4. Si `demande.versionLocale === version` → `{ ok: true, aJour: true, versionContenu: version }`. Fin.
5. Si `lireVersionDesPaquets() !== version` : `sousVerrou`, attente `ATTENTE_VERROU_PAQUETS_MS`. Sous le verrou :
   1. `version = lireVersion()` (relue) ;
   2. si `lireVersionDesPaquets() === version` : rien à faire, une autre exécution a reconstruit ;
   3. sinon : `contenu = lireContenu()`, `textes = preparerLesDeuxPaquets(contenu, version, maintenant())`, puis `ecrirePaquet('internes', …)`, `ecrirePaquet('admin', …)`, et **en dernier** `ecrireVersionDesPaquets(version)`.
   
   Une erreur à l'étape 3 est passée à `journaliserErreur` (avec `defauts` s'il y en a) puis relancée. **Rien n'est écrit si `preparerLesDeuxPaquets` échoue**, y compris pour `reglage_en_double` et `reglage_invalide`.
6. `paquet = JSON.parse(lirePaquet(demande.type))`.
7. Si `paquet.type !== demande.type` ou `paquet.versionContenu !== version` : reprends une seule fois depuis l'étape 3. Au second écart → lève `occupe`.
8. Rend `{ ok: true, aJour: false, versionContenu: version, paquet }`.

**Règle qui en découle** : le serveur ne rend jamais un paquet dont `versionContenu` diffère de la valeur de `contenu.version` lue pendant la même exécution.

## 7. Cas limites

| Cas | Comportement attendu |
|---|---|
| Fait « Validé », question « À valider » ou « À corriger » | Question absente du paquet « internes ». Le fait n'y est que si une autre question retenue pointe vers lui. |
| Question « Validé », fait non validé, champ absent de `Champs validés` | Question absente (`fait_non_valide`). |
| Fait non validé, `Champs validés` = `Libellé;Colonne A` | La question sur `Colonne A` est servie ; celle sur `Colonne B` ne l'est pas. La ligne du fait ne porte que `ID`, `Libellé` et `Colonne A`. |
| Fait non validé dont `Champs validés` cite une colonne qui n'existe pas, ou une colonne réservée | Cette colonne est ignorée. |
| `Statut` vaut `validé`, `Valide`, ou `Validé ?` | Non validé. Seul le texte exact `Validé`, espaces autour retirés, valide. |
| Question à plusieurs faits, dont un seul n'est pas validé | Question absente. |
| Question à plusieurs faits et un seul nom dans `Champ` | Ce champ vaut pour tous les faits. |
| Deux noms dans `Champ` pour trois faits | `champ_illisible`. |
| `Fait` vide, sans `:`, ou citant un onglet de structure | `reference_illisible`. |
| Fait introuvable, en double, archivé ; onglet de faits absent ; champ inexistant | Question absente, avec le motif correspondant. |
| Monde invisible | Lui, ses niveaux, leurs lignes de composition et les questions qui lui sont rattachées sont absents du paquet « internes » et présents dans le paquet « admin ». |
| Question d'un monde visible placée dans un niveau d'un monde invisible | La question est servie ; le niveau et la ligne de composition ne le sont pas. |
| Question d'un monde invisible placée dans un niveau d'un monde visible | La question et la ligne de composition sont absentes ; le niveau reste. |
| Ligne archivée (monde, niveau, composition, question, fait) | Absente des deux paquets. |
| Niveau de type `test` | Absent des deux paquets, avec ses lignes de composition. |
| Niveau dont aucune question n'est servie | Présent, sans ligne de composition ; `compositionPrevue` donne le nombre prévu. |
| Aucune question validée | Paquet « internes » valide, aux sections `questions`, `composition` et `faits` vides. |
| Même `ID` deux fois dans `Questions` | `contenu_incoherent` : aucun paquet n'est construit, les anciens restent enregistrés mais ne sont plus servis. |
| Colonne `Statut` ajoutée à `Niveaux` | `structure_inattendue` : même conséquence. **Arrête-toi et demande.** |
| Le second contrôle trouve un défaut | `paquet_refuse`, rien n'est enregistré, défauts journalisés sans valeur de contenu. |
| Paquet « admin » demandé sans le droit | `droit_refuse` ; ni le contenu ni un paquet ne sont lus. |
| Droit « contenu » retiré après un premier chargement | Refus à la demande suivante. |
| Deux téléphones demandent en même temps après un changement de version | Un seul reconstruit ; l'autre attend le verrou puis sert le paquet déjà prêt. |
| Version augmentée pendant la reconstruction | La demande suivante reconstruit ; aucun paquet d'une version dépassée n'est servi. |
| Échec entre l'écriture d'un paquet et celle de `PAQUETS_VERSION` | La demande suivante reconstruit les deux. |
| `versionLocale` plus grande que la version courante | Le paquet courant est renvoyé (`aJour: false`). |
| `versionLocale` négative, décimale ou textuelle | `message_invalide`. |
| Ligne de `Reglages` dont `Clé` est vide | Ignorée. |
| `Valeur` vide dans `Reglages` | La clé est dans le paquet, avec un texte vide. |
| Cellule `Valeur` numérique (onglet qui ne serait pas au format texte) | Texte, par `texteDeCellule`. |
| Clé de `Reglages` inconnue du serveur | Servie comme les autres, dans les deux paquets. |
| Même clé sur deux lignes de `Reglages` | `reglage_en_double` : aucun paquet n'est construit, les anciens restent enregistrés mais ne sont plus servis. |
| Onglet `Reglages` absent, ou sans colonne `Clé` ou `Valeur` | `contenu_incomplet` : même conséquence. |
| Une clé de `CLES_SEUILS_ETOILES` absente, vide, non entière, hors de 1 à 100, ou seuils décroissants | `reglage_invalide` : même conséquence, pour les deux paquets. Les téléphones gardent le contenu qu'ils ont déjà (lot 307). |
