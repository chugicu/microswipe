### 6.2 Convention des fichiers du serveur

Apps Script charge tous les fichiers dans **une seule portée globale** : pas d'`import`, pas d'`export`, pas de `require`.

**Deux dossiers**

- `serveur/logique/` : fonctions pures. Aucun service Google, aucun `new Date()` sans argument, aucun `Date.now()`, aucun `Math.random()`. Ce qui touche à Google, à l'heure ou au hasard arrive par un paramètre `dependances`.
- `serveur/` (hors `logique/`) : branchements sur les services Google. Aussi minces que possible.

**Règles valables pour tous les fichiers du serveur**

1. Au niveau du fichier, seulement des déclarations : `function`, et `const` dont la valeur est un littéral (nombre, texte, tableau ou objet de littéraux). **Aucun appel de fonction au niveau du fichier.** L'ordre de chargement des fichiers n'a alors aucune importance.
2. Chaque nom déclaré au niveau d'un fichier est unique dans tout le serveur.
3. Une fonction appelle une fonction d'un autre fichier par son nom, sans import.

**Règles en plus pour `serveur/logique/`**

4. Le fichier se termine par ce bloc, qui liste **tous** les noms déclarés au niveau du fichier :

```
if (typeof module !== 'undefined') {
  module.exports = { nomA, nomB, CONSTANTE_C };
}
```

Apps Script ignore ce bloc (`module` n'y existe pas). Node s'en sert.

**Chargeur pour Node — `tests/serveur/charger-serveur.js`**

`chargerServeur(dossier)` :

- `dossier` : chemin du dossier à charger ; par défaut `serveur/logique/` ;
- charge chaque fichier `.js` du dossier et de ses sous-dossiers, dans l'ordre alphabétique des chemins ;
- copie chaque nom exporté sur `globalThis`, pour imiter la portée globale d'Apps Script (règle 3) ;
- lève une erreur qui nomme les deux fichiers si un même nom est exporté deux fois ;
- rend un objet contenant tous les noms exportés ;
- peut être appelé plusieurs fois sans effet supplémentaire pour un même dossier.

Un test obtient ainsi ses fonctions : `const { traiterRequete } = chargerServeur();`.

### 6.4 Enveloppe et routeur

**Requête** : un `POST` dont le corps est un texte JSON.

```
{ "action": "<nom>", "session": "<jeton>" ou null, …champs de l'action… }
```

**Réponse** : un texte JSON, toujours l'une de ces deux formes.

```
{ "ok": true, …champs de l'action… }
{ "ok": false, "erreur": "<code>" }
```

**Table des actions** — `tableDesActions()` dans `serveur/actions.js` rend un objet : nom de l'action → `{ executer, publique }`.

- `executer(message, contexte)` reçoit le message décodé et `contexte = { idCompte, environnement }`. Elle rend l'objet de réponse.
- `publique: true` : l'action s'exécute sans session ; `contexte.idCompte` vaut `null`.
- Dans ce lot : `{ ping: { executer: actionPing, publique: true } }`.
- **Un lot enregistre une action en ajoutant une ligne à cet objet.**

**Fonctions pures (`logique/routeur.js`)**

| Fonction | Entrée → sortie |
|---|---|
| `NOMS_DE_PROPRIETES_REQUISES` | Constante : `ID_DOSSIER_DONNEES`, `ID_CONTENU`, `ID_JOUEURS`. |
| `verifierConfiguration(proprietes)` | `proprietes` : objet nom → valeur. → `true` si `ENVIRONNEMENT` vaut `test` ou `production` et si les trois propriétés requises sont des textes non vides ; `false` sinon. |
| `decoderMessage(texteRecu)` | → le message, ou `null` si `texteRecu` n'est pas un texte, n'est pas du JSON, ne décode pas en objet (un tableau et `null` sont refusés), ou si `action` n'est pas un texte non vide. |
| `traiterRequete(texteRecu, dependances)` | → l'objet de réponse. **Ne lève jamais.** |

`dependances` de `traiterRequete` : `lireConfiguration()` (rend l'objet des propriétés), `actions` (la table), `verifierSession(jeton)`, `journaliserErreur(contexte, erreur)`.

Déroulé de `traiterRequete` :

1. `proprietes = lireConfiguration()`. Si `verifierConfiguration(proprietes)` est faux → `configuration_invalide`.
2. `message = decoderMessage(texteRecu)`. `null` → `message_invalide`.
3. `entree` = la propriété **propre** de `actions` nommée `message.action` (utilise `Object.prototype.hasOwnProperty.call`). Absente → `action_inconnue`.
4. Si `entree.publique` ne vaut pas `true` : `idCompte = verifierSession(message.session)`. Sinon `idCompte = null`.
5. `reponse = entree.executer(message, { idCompte, environnement: proprietes.ENVIRONNEMENT })`.
6. Si `reponse` n'est pas un objet dont `ok` est un booléen : `journaliserErreur` puis `erreur_interne`.
7. Toute erreur levée aux étapes 1 à 5 : si `codeDeLErreur` rend un code → `{ ok: false, erreur: <code> }` ; sinon `journaliserErreur` puis `{ ok: false, erreur: "erreur_interne" }`. **La réponse ne contient jamais le message ni la pile d'une erreur.**

**Dans `serveur/actions.js`**

- `refuserToutesLesSessions(jeton)` : lève `creerErreur('session_invalide')`. C'est la `verifierSession` de ce lot ; le lot 302 la remplace.
- `actionPing(message, contexte)` → `{ ok: true, version: VERSION_SERVEUR, environnement: contexte.environnement, maintenant: maintenant() }`.

**`VERSION_SERVEUR`** (`serveur/version.js`) : un entier. Il vaut `1` dans ce lot. **Tout lot qui modifie le serveur l'augmente de 1.**

### 6.5 Point d'entrée (`entree.js`)

`doPost(e)` :

1. `texteRecu` = `e.postData.contents` s'il existe, sinon `null` ;
2. appelle `traiterRequete` avec les vraies dépendances : `lireConfiguration` construite sur `lirePropriete`, `tableDesActions()`, `refuserToutesLesSessions`, `journaliserErreur` ;
3. rend `ContentService.createTextOutput(JSON.stringify(reponse))` au type MIME JSON.

Pas de `doGet` dans ce lot.

### 6.6 Module de stockage (`stockage.js`)

**Règle** : `SpreadsheetApp`, `DriveApp`, `PropertiesService` et `CacheService` n'apparaissent dans aucun autre fichier du serveur. Une opération qui manque à un lot s'ajoute ici, jamais à côté.

Un fichier Google se désigne par son identifiant Drive (`idFichier`), lu dans une propriété du script. Une ligne lue a la forme `{ numero, valeurs }` : `numero` est le numéro de la ligne dans la feuille (2 pour la première ligne de données), `valeurs` un objet nom d'en-tête → valeur.

**Lecture**

| Fonction | Rôle |
|---|---|
| `ongletExiste(idFichier, onglet)` | → booléen. |
| `lireEnTete(idFichier, onglet)` | → les textes de la ligne 1, sans les espaces de début et de fin. Onglet absent → `onglet_introuvable`. |
| `lireOnglet(idFichier, onglet)` | → `{ enTete, lignes }`, toutes les colonnes, en une seule lecture. |
| `lireColonnes(idFichier, onglet, colonnes)` | → les lignes, réduites aux colonnes nommées. **Ne lit dans la feuille que ces colonnes** : une lecture par colonne demandée. |
| `trouverLigne(idFichier, onglet, colonneCle, valeurCle)` | Lit la colonne `colonneCle`, cherche la première cellule dont `String(cellule)` égale `String(valeurCle)`, puis lit cette ligne entière. → la ligne, ou `null`. |

- Les colonnes se repèrent par leur nom d'en-tête exact, accents compris, jamais par leur position.
- Les lectures rendent toutes les lignes, de la ligne 2 à la dernière ligne remplie de la feuille, lignes vides comprises. L'appelant filtre.
- Les valeurs sont celles de `getValues()` : texte, nombre, booléen ou date ; une cellule vide donne un texte vide.
- En-tête demandé absent → `colonne_introuvable`. Deux colonnes de même en-tête dans l'onglet → `en_tete_en_double`.

**Écriture** — chaque fonction commence par `verifierEcritureAutorisee`.

| Fonction | Rôle |
|---|---|
| `ecrireLigne(idFichier, onglet, numero, valeurs)` | Écrit les seules cellules nommées dans `valeurs` (objet en-tête → valeur) de la ligne `numero` (≥ 2). Les autres cellules ne sont pas touchées. |
| `ajouterLignes(idFichier, onglet, lignes)` | `lignes` : tableau de tableaux, chacun dans l'ordre de l'en-tête et de même longueur que lui. **Une seule écriture**, sur la plage qui suit la dernière ligne remplie ; insère d'abord les lignes manquantes si la feuille est trop courte. → le numéro de la première ligne ajoutée. Longueur incorrecte → `ligne_invalide`, rien n'est écrit. |
| `creerOnglet(idFichier, onglet, enTete)` | Crée l'onglet, écrit l'en-tête en ligne 1, **met toutes ses colonnes au format texte brut**. Onglet déjà présent → `onglet_existant`. |
| `creerClasseur(nom, premierOnglet, enTete)` | Crée un classeur dans le dossier `ID_DOSSIER_DONNEES`, renomme sa première feuille `premierOnglet`, écrit l'en-tête. **N'applique aucun format** : l'appelant choisit avec `mettreAuFormatTexte`. → l'identifiant du classeur. |
| `mettreAuFormatTexte(idFichier, onglet, colonnes)` | Met au format texte brut (`@`) les colonnes entières nommées, ou toutes si `colonnes` vaut `'toutes'`. |
| `creerDossier(nom)` | Crée un dossier à la racine du Drive du compte. → son identifiant. |
| `forcerEcriture()` | `SpreadsheetApp.flush()`. |

- Le module écrit les valeurs telles quelles. Protéger un texte qui commence par `=` est à la charge de l'appelant.
- Pourquoi le format texte : sans lui, Sheets transforme un identifiant fait de chiffres en nombre et un texte de date en date.
- Aucune fonction de ce lot ne modifie ni ne supprime une ligne existante autrement que par `ecrireLigne`.

**Propriétés et cache**

| Fonction | Rôle |
|---|---|
| `lirePropriete(nom)` | → le texte, ou `null`. **Relit le service à chaque appel**, sans rien garder en mémoire (une autre exécution peut l'avoir écrite). |
| `ecrirePropriete(nom, valeur)` | Écrit une propriété du script. |
| `lireCache(cle)` | → le texte, ou `null`. Cache du script. |
| `ecrireCache(cle, valeur, dureeSecondes)` | Écrit un texte dans le cache du script. |
| `effacerCache(cle)` | Retire une clé. |

Le module garde en mémoire, pour la durée de l'exécution, les classeurs déjà ouverts.

**Fonctions pures (`logique/stockage-regles.js`)**

| Fonction | Entrée → sortie |
|---|---|
| `indexDesColonnes(enTete, colonnes)` | → tableau des positions (base 0) des `colonnes` dans `enTete`, après retrait des espaces de début et de fin. Lève `colonne_introuvable` ou `en_tete_en_double`. |
| `lignesEnObjets(enTete, matrice, premierNumero)` | → tableau de `{ numero, valeurs }`. |
| `verifierEcritureAutorisee(idFichier, idCarnetRea)` | Lève `ecriture_interdite` si `idCarnetRea` est un texte non vide égal à `idFichier`. Ne fait rien sinon. |
| `verifierLignesAAjouter(lignes, largeur)` | Lève `ligne_invalide` si `lignes` n'est pas un tableau de tableaux de longueur `largeur`. |
| `texteDeCellule(valeur)` | → texte vide pour `null`, `undefined` et le texte vide ; `toISOString()` pour une date ; `String(valeur)` sans espaces de début et de fin sinon. |

### 6.7 Verrou (`verrou.js`, `logique/verrou-regles.js`)

`sousVerrou(fn, attenteMaxMs)` : exécute `fn` sous le verrou du script et rend sa valeur. `attenteMaxMs` vaut `ATTENTE_VERROU_MS` (20 000) s'il est absent.

La logique est dans la fonction pure `executerSousVerrou(fn, attenteMaxMs, dependances)`, avec `dependances` = `prendre(attenteMaxMs)` (rend un booléen), `liberer()`, `forcerEcriture()`, `apresObtention()`, et `etat` (objet `{ tenu: false }` gardé par `verrou.js` pour la durée de l'exécution) :

1. si `etat.tenu` est vrai : exécute `fn` directement et rend sa valeur (appel imbriqué, pas de second verrou) ;
2. `prendre(attenteMaxMs)` faux → lève `occupe` ; `fn` n'est pas exécutée ;
3. `etat.tenu = true`, puis `apresObtention()` ;
4. exécute `fn` ;
5. dans tous les cas, erreur de `fn` comprise : `forcerEcriture()`, puis `liberer()`, puis `etat.tenu = false`. Une erreur de `fn` est relancée telle quelle.

Dans `verrou.js` : `prendre` = `LockService.getScriptLock().tryLock(attenteMaxMs)` ; `apresObtention` = `oublierReglages` (§ 6.8). Ce qui a été lu avant le verrou peut être périmé : **relis sous le verrou ce dont dépend une écriture.**

### 6.9 Horloge et journalisation

### 6.10 Installation de l'environnement de test (`installation.js`)

`installerEnvironnementDeTest()` se lance **depuis l'éditeur Apps Script**. Elle n'est pas dans la table des actions.

Fonction pure `peutInstaller(proprietes)` (`logique/installation-regles.js`) → `true` seulement si `ENVIRONNEMENT` est absente ou vaut `test`, **et** si aucune des propriétés `ID_DOSSIER_DONNEES`, `ID_CONTENU`, `ID_JOUEURS` n'existe.

Déroulé :

1. `peutInstaller` faux → lève une erreur dont le message dit quelle propriété bloque. Rien n'est créé.
2. Écrit `ENVIRONNEMENT` = `test`.
3. `creerDossier('Microbio – test – données')` ; écrit `ID_DOSSIER_DONNEES`.

### 6.12 Côté client

**`client/config.js`**

| Nom | Valeur |
|---|---|
| `ADRESSES_SERVEUR` | `{ test: '<adresse /exec du déploiement de test>', production: '' }`. |
| `ORIGINE_PRODUCTION` | `'https://chugicu.github.io'`. |
| `CHEMIN_PRODUCTION` | `'/microswipe/'`. |
| `choisirEnvironnement(emplacement)` | `emplacement` : objet `{ origin, pathname }`. → `'production'` si `origin` égale `ORIGINE_PRODUCTION` **et** si `pathname` commence par `CHEMIN_PRODUCTION` ; `'test'` dans tous les autres cas. |
| `adresseDuServeur(emplacement)` | → `ADRESSES_SERVEUR[choisirEnvironnement(emplacement)]`. |

`ADRESSES_SERVEUR.production` reste un texte vide dans ce lot.

**`client/reseau/appel-serveur.js`** — seul fichier du client à appeler le serveur Microbio.

| Nom | Rôle |
|---|---|
| `DELAI_MAX_PAR_DEFAUT_MS` | 30 000. |
| `creerAppelServeur(dependances)` | → une fonction `appelerServeur`. `dependances` : `adresse` (texte), `fetch`, `fournirSession()` (rend un jeton ou `null`), `demarrerMinuterie(fn, ms)`, `arreterMinuterie(jeton)`. |
| `appelerServeur(action, corps, options)` | L'instance par défaut : `adresse` = `adresseDuServeur(location)`, `fetch` du navigateur, `setTimeout` et `clearTimeout`. |
| `definirFournisseurDeSession(fn)` | Remplace le fournisseur de session de l'instance par défaut. Par défaut : `() => null`. Le lot 303 l'appellera. |

Comportement de `appelerServeur(action, corps, options)` :

1. `adresse` vide → rejet `adresse_absente` ; `fetch` n'est pas appelé.
2. Message envoyé : les champs de `corps` (objet, ou absent), puis `action` et `session: fournirSession()`. **`action` et `session` de l'enveloppe l'emportent** sur des champs de même nom dans `corps`.
3. `fetch(adresse, { method: 'POST', headers: { 'Content-Type': 'text/plain;charset=utf-8' }, body: JSON.stringify(message), redirect: 'follow', signal })`. Ce type de contenu évite la requête préalable que le serveur Apps Script ne sait pas traiter.
4. Délai : `options.delaiMaxMs`, ou `DELAI_MAX_PAR_DEFAUT_MS`. Délai dépassé → abandon de la requête par le signal, rejet `delai`.
5. `fetch` rejette → rejet `reseau`.
6. La réponse ne se décode pas en un objet dont `ok` est un booléen → rejet `reponse_illisible`.
7. Sinon la promesse est **résolue** avec l'objet décodé, que `ok` soit vrai ou faux.

Un rejet est un `Error` dont `message` et `code` valent le code. Le module ne renvoie jamais une requête de lui-même, n'écrit dans aucun stockage et n'affiche rien.

## 7. Cas limites

| Cas | Comportement attendu |
|---|---|
| Corps absent, vide, non JSON, tableau, `null`, `action` absente ou non textuelle | `message_invalide`. |
| Action nommée `constructor`, `toString` ou `__proto__` | `action_inconnue`. |
| Action non publique, dans ce lot | `session_invalide` ; `executer` n'est pas appelée. |
| `ping` avant l'installation | `configuration_invalide`. |
| `ENVIRONNEMENT` vaut autre chose que `test` ou `production` | `configuration_invalide`, pour toutes les actions. |
| Une action lève une erreur sans code | `erreur_interne`, erreur journalisée, ni message ni pile dans la réponse. |
| Une action rend autre chose qu'un objet avec `ok` booléen | `erreur_interne`. |
| Verrou non obtenu | `occupe` ; `fn` n'est pas exécutée. |
| `fn` lève sous le verrou | Écriture forcée, verrou libéré, erreur relancée. |
| `sousVerrou` appelé sous `sousVerrou` | `fn` s'exécute, sans second verrou ni blocage. |
| Clé de `Reglages` lue avant le verrou, puis sous le verrou | Relue dans la feuille sous le verrou. |
| Onglet sans ligne de données | Les lectures rendent un tableau vide. |
| En-tête avec des espaces autour dans la feuille | Reconnu. |
| En-tête qui ne diffère que par un accent | Non reconnu : `colonne_introuvable`. |
| Écriture demandée vers le fichier dont l'identifiant est dans `ID_CARNET_REA` | `ecriture_interdite`, quelle que soit la fonction d'écriture. |
| `installerEnvironnementDeTest` lancée une seconde fois | Erreur, rien n'est créé. |
| `installerEnvironnementDeTest` interrompue en cours de route | La relance est refusée. **Arrête-toi et demande** : ne supprime ni propriété ni fichier de toi-même. |
| Page servie depuis `localhost`, ou depuis l'origine de production sous un autre chemin | Environnement `test`. |
| Page de production alors que l'adresse de production est vide | Rejet `adresse_absente`. |
| Le serveur répond `{ ok: false, … }` | Promesse résolue, pas rejetée. |
| Téléphone hors ligne | Rejet `reseau`. Le module ne consulte pas `navigator.onLine`. |

## 9. Critères d'acceptation

1. `node --test` passe en entier ; les tests 1 à 36 existent.
2. Une recherche dans le dossier du serveur ne trouve `SpreadsheetApp`, `DriveApp`, `PropertiesService` et `CacheService` que dans `stockage.js`, `LockService` que dans `verrou.js`, `ContentService` que dans `entree.js`.
3. Aucun fichier de `serveur/logique/` ne contient `Date.now`, `new Date()` sans argument, `Math.random`, ni le nom d'un service Google.
4. Une recherche de `fetch(` dans le dossier du client ne trouve que `client/reseau/appel-serveur.js`.
5. `.clasp.json` ne contient qu'un `scriptId`, celui du projet de test, et `rootDir`. Le dépôt ne contient aucun identifiant ni adresse de production.
6. Après `clasp push` et la mise à jour du déploiement de test :
   1. avant l'installation, un `POST` de `{ "action": "ping" }` répond `{ "ok": false, "erreur": "configuration_invalide" }` ;
   2. `installerEnvironnementDeTest`, lancée par l'auteur, crée le dossier `Microbio – test – données`, le fichier Contenu avec l'onglet `Reglages` et la ligne `contenu.version` = `0`, le fichier Joueurs avec l'onglet `Profils` et ses douze en-têtes ; une seconde exécution échoue sans rien créer ;

   4. un `POST` de `{ "action": "inconnue" }` répond `action_inconnue` ; un `POST` du texte `bonjour` répond `message_invalide` ;

8. Aucun contenu médical ni aucune donnée de Carnet Réa dans le code, les tests, les commentaires ni le commit.
9. `PROGRESS.md` est à jour et note, pour les lots suivants : les chemins réels des fichiers ; le nom et la signature de chaque fonction des § 6.3 à § 6.9 et § 6.12 ; les noms des propriétés ; la règle « une action = une ligne de `tableDesActions()` » ; la règle « tout lot qui modifie le serveur augmente `VERSION_SERVEUR` » ; l'identifiant du déploiement de test et son adresse.
