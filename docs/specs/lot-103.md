### 6.3 Service worker

**Version** — `VERSION_CLIENT` (`client/version.js`) : un entier, `1` dans ce lot. `sw.js` porte la même valeur dans sa constante `VERSION_DE_LA_COQUILLE`, écrite sur une seule ligne. **Tout lot qui modifie un fichier servi au téléphone augmente les deux de 1** : c'est le changement de `sw.js` qui déclenche la mise à jour sur les téléphones. Un test vérifie que les deux valeurs sont égales.

**`client/coquille/sw/regles-sw.js`** — script classique, sans `import` ni `export`, terminé par l'export réservé à Node de `lot-301.md` § 6.2. Aucun appel au chargement.

| Nom | Valeur, ou entrée → sortie |
|---|---|
| `PREFIXE_DES_CACHES` | `microbio-coquille-v` |
| `FICHIERS_DE_LA_COQUILLE` | Les chemins, relatifs à la racine du site, de tous les fichiers nécessaires pour ouvrir et jouer hors ligne : `./`, `index.html`, `manifest.webmanifest`, et chaque fichier de `client/` sauf ceux de `DOSSIERS_HORS_COQUILLE` et les fichiers `package.json`. |
| `DOSSIERS_HORS_COQUILLE` | `client/verifications/` (pages de vérification du lot 108). |
| `nomDuCache(version)` | → `microbio-coquille-v<version>`. |
| `cachesASupprimer(noms, version)` | → les noms qui commencent par `PREFIXE_DES_CACHES` et diffèrent de `nomDuCache(version)`. **Un nom sans ce préfixe n'est jamais rendu** : les caches de Carnet Réa, d'EchoLearn et de tout autre site du domaine ne sont pas touchés. |
| `strategiePour(requete, portee, fichiers)` | `requete` : `{ methode, url, mode }` ; `portee` : l'adresse de la portée du service worker. → `page` pour une navigation (mode `navigate`) dans la portée ; `coquille` pour un `GET` d'une adresse de la portée qui correspond à un fichier de la liste ; `reseau` pour tout autre `GET` de la portée ; `ignorer` pour toute autre méthode ou toute adresse hors de la portée (serveur Apps Script, Carnet Réa, autres sites). Les paramètres d'adresse (`?…`) et l'ancre (`#…`) ne comptent pas pour reconnaître un fichier. |

**`sw.js`** — à la racine, pour que sa portée couvre tout le site :

1. `importScripts('client/coquille/sw/regles-sw.js')`.
2. **Installation** : ouvre `nomDuCache(VERSION_DE_LA_COQUILLE)` et y range tous les fichiers de la liste, en contournant le cache HTTP. Un seul fichier en échec → l'installation échoue ; l'ancienne version reste en service.
3. **Activation** : supprime les caches de `cachesASupprimer`, puis prend le contrôle des pages ouvertes.
4. **Requêtes**, selon `strategiePour` :
   - `page` → `index.html` du cache courant ; à défaut, le réseau ;
   - `coquille` → le cache courant ; à défaut, le réseau ;
   - `reseau` → le réseau, sans rien ranger ;
   - `ignorer` → le service worker ne répond pas : le navigateur fait la requête lui-même.
5. **Message `passer`** venu de la page → le nouveau service worker en attente s'active tout de suite. Sans ce message, il attend.
6. Rien d'autre : ni synchronisation en arrière-plan, ni notification, ni écriture dans IndexedDB.

Le contenu médical ne passe jamais par ce cache : il vient du serveur (hors portée) et est rangé dans IndexedDB (lot 107).

### 6.4 Écran d'accueil (`accueil.js`, `regles.js`)

| Nom | Valeur, ou entrée → sortie |
|---|---|
| `DUREE_ACCUEIL_MS` | 1 000 |
| `CLE_LOGO_A_L_OUVERTURE` | `accueil.logo` |
| `logoActive(reglages)` (pure) | → faux si `reglages` est un objet dont `accueil.logo`, sans espaces autour, vaut exactement `non` ; vrai dans tous les autres cas (clé absente, valeur vide, autre valeur, `reglages` absent). |
| `doitMasquerLAccueil({ ecouleMs, appliPrete, toucher, logo })` (pure) | → vrai si `appliPrete` et (`logo` faux, ou `toucher`, ou `ecouleMs` ≥ `DUREE_ACCUEIL_MS`). Faux sinon. |
| `definirFournisseurDuLogo(fn)` | `fn()` rend une promesse d'un booléen (logo actif ou non). Par défaut : `() => Promise.resolve(true)`. **Le lot 107 la remplace** par la lecture de `accueil.logo` dans le paquet « internes » rangé. |
| `annoncerAppliPrete()` | Appelée par le démarrage quand le premier écran est prêt derrière l'accueil. |
| `accueilTermine` | Promesse résolue quand l'accueil a disparu. |

Déroulé :

1. L'accueil est déjà affiché par le HTML. `accueil.js` note l'heure de début (`performance.now()`).
2. Il interroge le fournisseur du logo. Une réponse fausse, un rejet ou une réponse arrivée après la fin de l'accueil n'ont d'effet que sur ce qui reste à attendre ; un rejet compte comme « logo actif ».
3. Un toucher sur l'accueil compte comme `toucher` ; il ne fait pas disparaître l'accueil avant que l'appli soit prête.
4. Dès que `doitMasquerLAccueil` est vrai : l'accueil disparaît selon le design system (sans animation si le téléphone est réglé pour réduire les animations), `accueilTermine` est résolue.

Conséquences voulues :

- logo coupé par un admin : l'accueil disparaît dès que l'appli est prête, souvent en une fraction de seconde (il peut apparaître brièvement le temps de lire le réglage) ;
- le réglage n'agit qu'après que le téléphone a reçu un paquet qui le porte (lot 107, puis lot 307) ; à la toute première ouverture, le logo s'affiche ;
- démarrage plus long qu'une seconde : l'accueil reste jusqu'à ce que l'appli soit prête ;
- **aucun indicateur de chargement** sur l'accueil.

### 6.5 Mise à jour (`mise-a-jour.js`)

| Fonction | Rôle |
|---|---|
| `demarrerMiseAJour({ pendantLAccueil })` | Enregistre `sw.js` (portée `./`), demande au navigateur de chercher une version plus récente, et applique une version en attente selon la règle ci-dessous. Navigateur sans service worker → ne fait rien. |
| `versionEnAttente()` | → vrai si un nouveau service worker attend. |

**Règle de la mise à jour silencieuse** (décision 3) :

- **Pendant l'accueil de l'ouverture**, si un service worker attend : message `passer`, puis, quand le nouveau a pris le contrôle, **un seul rechargement de la page**, avant que l'accueil disparaisse. Aucun message à l'interne.
- **À tout autre moment** (appli restée ouverte, partie en cours) : rien. La version attend l'ouverture suivante.
- Première installation (aucune version précédente) : pas de rechargement.
- Le rechargement n'a lieu que sur le changement de contrôle provoqué par ce message : il ne peut pas boucler. Aucun repère n'est gardé dans `localStorage` ni `sessionStorage`.

Une appli installée que l'interne ne ferme jamais reçoit la mise à jour quand le téléphone la ferme lui-même : limite acceptée (point signalé de l'index).

### 6.7 Démarrage (`client/demarrage.js`)

Dans cet ordre, sans rien attendre du réseau :

1. `demarrerInstallation()` ;
2. `demarrerMiseAJour({ pendantLAccueil: true })`, sans l'attendre ;
3. les démarrages des lots suivants, ajoutés à la suite par chacun d'eux (lot 107 : `demarrerContenu()`), sans les attendre ;
4. affichage de la coquille vide dans le conteneur ;
5. `annoncerAppliPrete()`.

Une erreur d'un démarrage branché est écrite par `console.error` et n'empêche ni les autres ni l'affichage.

## 7. Cas limites

| Cas | Comportement attendu |
|---|---|
| Navigateur sans service worker | L'appli marche en ligne ; pas de hors-ligne ; aucune erreur. |
| Première visite hors ligne | Rien ne peut s'afficher au-delà de ce que le navigateur a ; aucune erreur dans l'appli. |
| Seconde visite hors ligne | La coquille s'ouvre depuis le cache. |
| Un fichier de la liste manque sur le site | L'installation du nouveau service worker échoue ; l'ancien reste. Le test 9 l'évite avant publication. |
| Fichier ajouté dans `client/` sans être mis dans la liste | Le test 9 échoue. |
| `VERSION_CLIENT` augmentée sans `sw.js` | Le test 8 échoue. |
| Nouvelle version publiée, appli ouverte | Rien ne change avant l'ouverture suivante. |
| Nouvelle version, ouverture suivante | Rechargement unique pendant l'accueil ; l'interne ne voit qu'un accueil un peu plus long. |
| Caches `carnet-rea-…` ou autres sur le domaine | Jamais supprimés ni lus. |
| Requête vers le serveur Apps Script | Non interceptée. |
| `accueil.logo` vaut `non` | Accueil masqué dès que l'appli est prête. |
| `accueil.logo` vaut `Non`, `oui`, vide, ou absent | Logo affiché (seul `non` exact le coupe). |
| Toucher l'accueil avant que l'appli soit prête | Rien ; l'accueil disparaît dès qu'elle l'est. |
| Téléphone en paysage | Colonne centrée, aucun message. |
| Appli déjà installée | Aucune invitation, pas de ligne dans Profil. |
| Navigateur sans moyen d'installer (`aucun`) | Aucune invitation, pas de ligne dans Profil. |
| Invitation native refusée | `refusee` ; l'invitation n'est plus disponible jusqu'à ce que le navigateur en propose une autre ; `moyen` peut repasser à `aucun`. |

## 9. Critères d'acceptation

1. `node --test` passe en entier ; les tests 1 à 12 existent.
2. Dans un navigateur à moteur Chromium, servi localement, en largeur de téléphone : le logo s'affiche dès le premier affichage, disparaît après environ une seconde ; un toucher le fait passer ; la coquille vide apparaît ; aucune erreur dans la console.
3. Même navigateur : le service worker est actif ; le cache `microbio-coquille-v1` contient la liste ; hors ligne (outils du navigateur), la page se recharge.
4. `VERSION_CLIENT` et `sw.js` passés à 2 en local : à la première ouverture, rien ne change ; à l'ouverture suivante, la page se recharge une fois pendant l'accueil, le cache v2 remplace le v1 ; un cache fictif `carnet-rea-essai` créé à la main dans les outils du navigateur est toujours là. Version remise à 1 ensuite si ce n'était qu'un essai.
5. Avec un fournisseur du logo d'essai qui rend faux, l'accueil disparaît dès que l'appli est prête.
6. Fenêtre en paysage : colonne centrée, aucun message.
7. **Après publication** (§ 6.9), sur `https://chugicu.github.io/microswipe/` : un navigateur Android propose l'installation (invitation native gardée : `etatDeLInstallation().moyen` vaut `bouton`) ; sur iPhone, « Sur l'écran d'accueil » installe l'appli sous le nom MicroSwipe avec l'icône du logo ; l'appli installée s'ouvre en plein écran et, en mode avion, se rouvre.
