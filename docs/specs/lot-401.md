# Lot 401 — Moteur ELO, fonctions pures

Phase 4. Dépend des lots 102 et 301 (pour la convention des fonctions pures du serveur). Domaine de tests obligatoire : **moteur ELO**.
Spec écrite en phase 0, lot 4b, conversation 5 (16 novembre 2026). Le lot 402 branche ce moteur sur la synchronisation et sur le téléphone ; le lot 403 l'utilise pour le recalcul complet.

Décisions de l'auteur du 16 novembre 2026 appliquées ici :

1. **Un seul ELO par interne.** La campagne ne le fait jamais bouger : elle ne sert qu'à étalonner les questions. Côté interne, seuls le classé et le pré-test comptent.
2. **Pré-test** : ses réponses passent par le même calcul que celles du classé, à partir d'une valeur de départ unique (`elo.interne.depart`). Elles comptent dans la période provisoire et n'étalonnent pas les questions. Sans pré-test, l'interne reste à la valeur de départ, en provisoire.
3. **Seul un interne sorti de sa période provisoire étalonne les questions**, dans tous les modes qui étalonnent (campagne, classé, entraînement).
4. **« Déjà vue »** : une question est vue dès la première réponse de l'interne dans le journal, quel que soit le mode, sauf en pré-test et en post-test, et même si cette réponse n'a pas étalonné.
5. **En classé, toutes les réponses font bouger l'interne**, question déjà vue ou non.
6. **c = 1 / nombre de réponses proposées.** Ce nombre est envoyé par le téléphone avec chaque réponse et gardé dans le journal (colonne `Réponses proposées`, champ `reponsesProposees`).
7. **La colonne `Plancher` d'une question contient un nom**, ou reste vide. La valeur de chaque nom est dans la clé `elo.planchers`.
8. **K par tranches**, dans une seule clé, sous la forme « à partir de N réponses : K ».
9. Les seize choix par défaut acceptés le même jour (tableau des modes, arrondis, cas sans valeur de secours, forme du code).

Le briefing § 3 et § 4, le schéma § 3.4 et § 5 n'ont pas encore été alignés sur ces décisions (signalé dans l'index des lots). **Là où ils disent autre chose, cette spec l'emporte.**

**Aucune valeur chiffrée de l'ELO n'est écrite dans le code** : K, paliers, planchers, durée de la période provisoire, ELO de départ et poids de l'entraînement sont lus dans `Reglages`. Le lot 5 de la phase 0 (simulation) les chiffrera.

## 1. Objectif

Écrire le moteur ELO en fonctions pures, dans un seul fichier, sans aucun accès à une feuille, à l'heure ni au hasard :

- lire et contrôler les sept clés ELO de `Reglages` ;
- calculer la probabilité de réussite, avec la correction du hasard ;
- dire, pour une réponse, ce qui bouge : l'interne, la question, la marque « déjà vue » ;
- rejouer une suite de réponses dans l'ordre donné, sur un état en mémoire.

Le même moteur sert au calcul officiel (lot 402), au recalcul complet (lot 403), à l'estimation du téléphone (lot 402) et à la simulation (phase 0, lot 5).

### 6.2 Clés de `Reglages` et constantes

**Les sept clés ELO** (onglet `Reglages`, schéma § 3.13). Leurs valeurs sont des textes, comme dans la section `reglages` du paquet (`lot-306.md` § 6.2).

| Clé | Format de la valeur | Sens |
|---|---|---|
| `elo.interne.depart` | nombre | ELO de départ de tout interne. |
| `elo.interne.k` | tranches | K de l'interne, selon son nombre de réponses comptées. |
| `elo.interne.provisoire` | entier | L'interne est provisoire tant que son nombre de réponses comptées est inférieur à cette valeur. |
| `elo.question.k` | tranches | K de la question, selon le nombre de réponses qui l'ont étalonnée. |
| `elo.question.poids_entrainement` | nombre de 0 à 1 | Poids d'une réponse d'entraînement dans l'étalonnage. |
| `elo.paliers` | liste nommée, au moins une entrée | ELO de départ d'une question, par valeur de la colonne `Palier`. |
| `elo.planchers` | liste nommée, peut être vide | Plancher d'une question, par valeur de la colonne `Plancher`. |

Formats, tous lus après retrait des espaces de début et de fin :

- **nombre** : `^[0-9]+(\.[0-9]+)?$`. Point décimal ; ni signe, ni virgule, ni exposant.
- **entier** : `^[0-9]+$`.
- **tranches** : des parties séparées par `;`. Chaque partie s'écrit `N:K`, avec `N` entier et `K` nombre. Règles : au moins une partie ; le premier `N` vaut 0 ; les `N` sont strictement croissants ; les `K` ne remontent jamais (chaque `K` est inférieur ou égal au précédent). Exemple de forme : `0:a;20:b;100:c`, où a, b et c sont des nombres.
- **liste nommée** : des parties séparées par `;`. Chaque partie s'écrit `nom:valeur`, avec exactement un `:`, un `nom` non vide et une `valeur` nombre. Un même nom ne figure qu'une fois. Les noms se comparent tels quels, accents et majuscules compris.
- Dans les deux listes, les espaces autour d'une partie, d'un nom et d'une valeur sont retirés, et une partie vide est ignorée.

Les noms des paliers et des planchers sont des données : **aucun n'est écrit dans le code**.

**Constantes**

| Constante | Valeur |
|---|---|
| `CLES_REGLAGES_ELO` | Les sept clés ci-dessus, dans cet ordre. |
| `ECHELLE_ELO` | 400 (formule du briefing § 4). |
| `BASE_ELO` | 10 (formule du briefing § 4). |
| `DECIMALES_ELO` | 2 |
| `DECIMALES_RESULTAT_ELO` | 6 |
| `DECIMALES_TAUX_ELO` | 4 |
| `REPONSES_PROPOSEES_MIN` | 2 |
| `VALEUR_OUI_ELO` | `oui` |
| `DEFAUTS_REGLAGE_ELO` | `absente`, `illisible` |
| `MOTIFS_SANS_EFFET_ELO` | Dans cet ordre : `mode_inconnu`, `question_inconnue`, `palier_illisible`, `plancher_illisible`, `hasard_inconnu`, `resultat_illisible` |
| `EFFETS_ELO_PAR_MODE` | Le tableau du § 6.3. |

400 et 10 font partie de la formule, pas des réglages. Ce sont, avec les décimales d'arrondi et le minimum de 2 réponses proposées, **les seuls nombres du fichier**.

### 6.3 Effets par mode (`EFFETS_ELO_PAR_MODE`)

Les clés sont les valeurs exactes de la colonne `Mode` du journal (schéma § 5).

| Mode | `interne` | `question` | `vue` |
|---|---|---|---|
| `classé` | `true` | `plein` | `true` |
| `campagne` | `false` | `plein` | `true` |
| `entraînement` | `false` | `entrainement` | `true` |
| `sprint` | `false` | `aucun` | `true` |
| `survie` | `false` | `aucun` | `true` |
| `jour` | `false` | `aucun` | `true` |
| `duel` | `false` | `aucun` | `true` |
| `pré-test` | `true` | `aucun` | `false` |
| `post-test` | `false` | `aucun` | `false` |

- `interne` : la réponse fait bouger l'ELO de l'interne.
- `question` : la réponse peut étalonner la question, avec le poids 1 (`plein`) ou le poids `elo.question.poids_entrainement` (`entrainement`).
- `vue` : la réponse marque la question « déjà vue » pour cet interne.

Le mode test n'est pas dans ce tableau : il n'atteint jamais le journal. Un mode absent du tableau n'a aucun effet (motif `mode_inconnu`).

### 6.4 Lecture des réglages

| Fonction | Entrée → sortie |
|---|---|
| `decouperListeElo(texte)` | → les parties séparées par `;`, sans espaces autour, sans les parties vides. `null`, `undefined` ou un non-texte → tableau vide. |
| `lireNombreElo(texte)` | → le nombre si le texte, sans espaces autour, a le format « nombre » ; `null` sinon (non-texte compris). |
| `lireEntierElo(texte)` | → l'entier si le format « entier » est tenu ; `null` sinon. |
| `lireTranchesElo(texte)` | → tableau de `{ depuis, k }` dans l'ordre, ou `null` si une règle des tranches n'est pas tenue. |
| `lireListeNommeeElo(texte)` | → objet `nom → nombre`, vide pour un texte vide ; `null` si une règle n'est pas tenue. |
| `lireReglagesElo(reglages)` | → `{ valide: true, reglages: <réglages lus> }` ou `{ valide: false, defauts: [ { cle, defaut } ] }`. |
| `empreinteDesReglagesElo(reglages)` | → `JSON.stringify` du tableau des sept valeurs, dans l'ordre de `CLES_REGLAGES_ELO` : le texte sans espaces autour, ou `null` pour une clé absente. |

`reglages` est un objet clé → texte : la section `reglages` d'un paquet, ou le même objet construit depuis l'onglet. Les clés qui ne sont pas dans `CLES_REGLAGES_ELO` sont ignorées.

**`lireReglagesElo`** examine les sept clés, dans l'ordre :

- clé qui n'est pas une propriété propre de `reglages`, ou `reglages` qui n'est pas un objet → défaut `absente` ;
- valeur qui n'est pas un texte, ou qui ne tient pas son format → défaut `illisible` ;
- `elo.question.poids_entrainement` supérieur à 1 → `illisible` ;
- `elo.paliers` sans aucune entrée → `illisible`. `elo.planchers` vide est accepté.

Tous les défauts sont rendus, pas seulement le premier. **Aucune valeur de secours** : un seul défaut suffit pour que `valide` soit faux.

**Réglages lus** :

```
{
  depart: <nombre>,
  kInterne: [ { depuis: 0, k: <nombre> }, … ],
  provisoire: <entier>,
  kQuestion: [ { depuis: 0, k: <nombre> }, … ],
  poidsEntrainement: <nombre>,
  paliers: { "<nom>": <nombre>, … },
  planchers: { "<nom>": <nombre>, … }
}
```

Toutes les fonctions des § 6.5 à § 6.7 reçoivent les réglages lus, jamais l'objet brut.

### 6.5 Calculs élémentaires

| Fonction | Entrée → sortie |
|---|---|
| `arrondirElo(x)` | → `Math.round(x × 100) / 100`. |
| `normaliserResultatElo(x)` | → `Math.round(x × 1 000 000) / 1 000 000` si `x` est un nombre fini de 0 à 1 ; `null` sinon. |
| `chanceAuHasard(reponsesProposees)` | → `1 / reponsesProposees` si c'est un entier (`Number.isInteger`) supérieur ou égal à `REPONSES_PROPOSEES_MIN` ; `null` sinon. |
| `probabiliteDeReussite(eloInterne, eloQuestion, c)` | → `c + (1 − c) / (1 + Math.pow(BASE_ELO, (eloQuestion − eloInterne) / ECHELLE_ELO))`. |
| `kDeLaTranche(tranches, nombre)` | → le `k` de la dernière tranche dont `depuis` est inférieur ou égal à `nombre`. |
| `estProvisoire(etatInterne, reglagesLus)` | → `etatInterne.reponsesComptees < reglagesLus.provisoire`. |
| `creerEtatInterneElo(reglagesLus)` | → `{ elo: reglagesLus.depart, reponsesComptees: 0 }`. |
| `infoQuestionElo(ligne)` | `ligne` : objet aux noms de colonnes de `Questions`. → `{ palier, plancher, simplifiee }` : les textes de `Palier` et `Plancher` sans espaces autour (texte vide si absents), et `simplifiee` vrai si `Simplifiée`, sans espaces autour, vaut `VALEUR_OUI_ELO`. |
| `indexerQuestionsElo(lignes)` | `lignes` : tableau d'objets portant `ID`, `Palier`, `Plancher`, `Simplifiée`. → objet `ID` → `infoQuestionElo(ligne)`. `ID` vide : ligne ignorée. `ID` en double : la première ligne est gardée. |
| `departDeLaQuestion(info, reglagesLus)` | → `{ motif: null, depart, plancher }` ou `{ motif }` (voir ci-dessous). |
| `eloCourantDeLaQuestion(etatQuestion, info, depart)` | `depart` : le résultat sans motif de `departDeLaQuestion`. → l'ELO de la question à cet instant (voir ci-dessous). |

**`departDeLaQuestion`**

1. `info.palier` n'est pas une propriété propre de `paliers` (texte vide compris) → `{ motif: 'palier_illisible' }`.
2. `info.plancher` non vide et absent de `planchers` → `{ motif: 'plancher_illisible' }`.
3. `plancher` = `planchers[info.plancher]`, ou `null` si `info.plancher` est vide.
4. `depart` = `paliers[info.palier]`, relevé à `plancher` si celui-ci est plus grand.

**`eloCourantDeLaQuestion`**

- `etatQuestion` nul (question jamais étalonnée), ou `info.simplifiee` vrai → `depart.depart` ;
- sinon → `etatQuestion.elo`, relevé à `depart.plancher` si celui-ci n'est pas nul et est plus grand.

Une question simplifiée garde donc toujours l'ELO de départ de son palier. Un palier modifié après le premier étalonnage ne change pas l'ELO courant (règle d'architecture 10) ; un plancher modifié s'applique dès la lecture suivante.

### 6.6 Effet d'une réponse (`calculerEffetElo`)

`calculerEffetElo(entree, reglagesLus)` est le cœur du moteur. Elle ne modifie rien.

Entrée :

```
{
  mode: "classé",
  reTest: false,
  resultat: 1,
  reponsesProposees: 2,
  interne: { elo: <nombre>, reponsesComptees: <entier> },
  question: { elo: <nombre>, reponsesComptees: <entier>, tauxDeReussite: <nombre> },   // ou null : jamais étalonnée
  info: { palier: "<nom>", plancher: "", simplifiee: false },                          // ou null : question inconnue
  dejaVue: false
}
```

Sortie :

```
{
  motif: null,                 // ou un motif de MOTIFS_SANS_EFFET_ELO
  probabilite: <nombre>,       // null si rien n'a été calculé
  interneBouge: true,
  questionEtalonnee: false,
  interne: { elo, reponsesComptees },                    // nouvel état ; égal à l'entrée si interneBouge est faux
  question: { elo, reponsesComptees, tauxDeReussite },   // nouvel état ; égal à l'entrée (null compris) si questionEtalonnee est faux
  vue: true                    // la question est « déjà vue » après cette réponse
}
```

« Sortie sans effet » ci-dessous veut dire : `probabilite` nul, `interneBouge` et `questionEtalonnee` faux, `interne` et `question` égaux à l'entrée.

Déroulé, dans cet ordre :

1. `reTest` vaut `true` → sortie sans effet, `motif` nul, `vue` = `dejaVue`. **Un re-test n'a jamais d'effet et n'est pas une anomalie.**
2. `mode` n'est pas une propriété propre de `EFFETS_ELO_PAR_MODE` → sortie sans effet, motif `mode_inconnu`, `vue` = `dejaVue`.
3. `effets = EFFETS_ELO_PAR_MODE[mode]`. Pour toute la suite : `vue` = `dejaVue` ou `effets.vue`.
4. `effets.interne` faux et `effets.question` = `aucun` → sortie sans effet, `motif` nul.
5. `info` nul → sortie sans effet, motif `question_inconnue`.
6. `poids` = 1 si `effets.question` = `plein` ; `reglagesLus.poidsEntrainement` si `entrainement` ; 0 si `aucun`.
7. `etalonnable` = toutes ces conditions à la fois :
   - `poids` > 0 ;
   - `dejaVue` faux ;
   - `info.simplifiee` faux ;
   - `estProvisoire(entree.interne, reglagesLus)` faux. **L'état de l'interne est celui d'avant la réponse.**
8. `effets.interne` faux et `etalonnable` faux → sortie sans effet, `motif` nul.
9. `depart = departDeLaQuestion(info, reglagesLus)`. Motif → sortie sans effet, avec ce motif.
10. `c = chanceAuHasard(reponsesProposees)`. Nul → sortie sans effet, motif `hasard_inconnu`.
11. `r = normaliserResultatElo(resultat)`. Nul → sortie sans effet, motif `resultat_illisible`.
12. `D = eloCourantDeLaQuestion(question, info, depart)` ; `E = interne.elo` ; `P = probabiliteDeReussite(E, D, c)` ; `ecart = r − P`. `probabilite` = `P`.
13. **Interne**, si `effets.interne` : `elo` = `arrondirElo(E + kDeLaTranche(kInterne, interne.reponsesComptees) × ecart)` ; `reponsesComptees` + 1 ; `interneBouge` vrai.
14. **Question**, si `etalonnable` : avec `n` = `question.reponsesComptees`, ou 0 si `question` est nul, et `taux` = `question.tauxDeReussite`, ou 0 :
    - `elo` = `arrondirElo(D − kDeLaTranche(kQuestion, n) × poids × ecart)`, relevé à `depart.plancher` s'il n'est pas nul et est plus grand ;
    - `reponsesComptees` = `n + 1` ;
    - `tauxDeReussite` = `(taux × n + r) / (n + 1)`, arrondi à `DECIMALES_TAUX_ELO` décimales ;
    - `questionEtalonnee` vrai.

Points à retenir :

- l'interne et la question partent tous deux de `E` et de `D` d'avant la réponse ;
- un score partiel entre tel quel dans `r` (7 sur 8 = 0,875) ;
- l'interne n'a ni plancher ni plafond ;
- une réponse d'entraînement compte pour une réponse dans `reponsesComptees` de la question, malgré son poids réduit ;
- le pré-test fait bouger l'interne contre l'ELO courant de la question, sans l'étalonner ni la marquer « vue ».

### 6.7 État en mémoire et rejeu

**État** — un objet JSON simple, sans fonction ni `Map`, pour que le lot 403 puisse l'enregistrer entre deux tranches :

```
{
  v: 1,
  internes:  { "<ID compte>": { elo, reponsesComptees } },
  questions: { "<ID question>": { elo, reponsesComptees, tauxDeReussite } },
  vues:      { "<ID compte>": { "<ID question>": true } },
  sansEffet: { "<motif>": <nombre de réponses> }
}
```

| Fonction | Entrée → sortie |
|---|---|
| `creerEtatElo()` | → `{ v: 1, internes: {}, questions: {}, vues: {}, sansEffet: {} }`. |
| `appliquerReponseElo(etat, reponse, questions, reglagesLus)` | Applique une réponse à `etat`, **en le modifiant**. → la sortie de `calculerEffetElo`. |
| `rejouerReponsesElo(reponses, questions, reglages)` | → `{ valide: false, defauts }` si `lireReglagesElo(reglages)` n'est pas valide ; sinon `{ valide: true, etat }`, après `appliquerReponseElo` sur chaque réponse, **dans l'ordre du tableau**, à partir de `creerEtatElo()`. |

`reponse` : `{ idCompte, question, mode, reTest, resultat, reponsesProposees }`. `questions` : le résultat de `indexerQuestionsElo`.

**`appliquerReponseElo`**, dans cet ordre :

1. Si `etat.internes` n'a pas `idCompte` : `etat.internes[idCompte] = creerEtatInterneElo(reglagesLus)`. **Un interne existe dans l'état dès sa première réponse, quelle qu'elle soit.**
2. `dejaVue` = `etat.vues[idCompte]` existe et porte `reponse.question`.
3. `effet = calculerEffetElo({ mode, reTest, resultat, reponsesProposees, interne: etat.internes[idCompte], question: etat.questions[question] ou null, info: questions[question] ou null, dejaVue }, reglagesLus)`.
4. `effet.interneBouge` → `etat.internes[idCompte] = effet.interne`.
5. `effet.questionEtalonnee` → `etat.questions[reponse.question] = effet.question`.
6. `effet.vue` vrai et `dejaVue` faux → `etat.vues[idCompte][reponse.question] = true` (en créant `etat.vues[idCompte]` s'il manque).
7. `effet.motif` non nul → `etat.sansEffet[motif]` augmente de 1 (à partir de 0).
8. Rend `effet`.

C'est la seule fonction du fichier qui modifie un paramètre : rejouer plusieurs centaines de milliers de réponses en recopiant l'état à chaque fois serait trop lent. Elle ne modifie ni `reponse`, ni `questions`, ni `reglagesLus`.

**L'ordre fait le résultat** : la même liste de réponses dans un autre ordre donne en général d'autres ELO. L'ordre de référence est celui du journal (lots 402 et 403).

### 6.8 Ce que la simulation doit pouvoir faire (phase 0, lot 5)

Le lot 5 écrira un script Node qui simule des internes fictifs pour chiffrer les sept clés. **Ce lot n'écrit pas ce script**, mais le moteur doit le permettre tel quel :

1. charger `serveur/logique/elo.js` **seul**, par `require`, sans aucun autre fichier du serveur ;
2. contrôler un jeu de réglages candidat avec `lireReglagesElo`, à partir d'un simple objet clé → texte ;
3. tirer la réponse d'un interne fictif avec `probabiliteDeReussite` et `chanceAuHasard` (le hasard est dans le script, jamais dans le moteur) ;
4. rejouer les réponses avec `creerEtatElo` et `appliquerReponseElo`, ou d'un bloc avec `rejouerReponsesElo`, sans feuille, sans réseau, sans horloge ;
5. lire dans l'état l'ELO de chaque interne et de chaque question, et le nombre de réponses sans effet par motif ;
6. rejouer 100 000 réponses en quelques secondes sur un ordinateur ordinaire.

Les valeurs retenues par la simulation seront saisies dans `Reglages` par l'auteur ; le code ne change pas.

## 7. Cas limites

| Cas | Comportement attendu |
|---|---|
| Une des sept clés absente ou illisible | `lireReglagesElo` rend `valide: false` et la liste des défauts. Aucun calcul n'est possible ; aucune valeur de secours. |
| Tranches dont le premier `N` n'est pas 0, dont les `N` ne croissent pas, ou dont un `K` remonte | `illisible`. |
| Liste nommée avec un nom en double, une partie sans `:` ou à deux `:` | `illisible`. |
| Nombre écrit avec une virgule, un signe ou un exposant | `illisible`. |
| `elo.planchers` vide | Accepté : aucun plancher n'existe ; une question dont `Plancher` n'est pas vide reçoit `plancher_illisible`. |
| Re-test, dans n'importe quel mode | Aucun effet ; la marque « vue » ne change pas ; rien dans `sansEffet`. |
| Mode absent du tableau | Aucun effet, `mode_inconnu`. |
| Sprint, survie, jour, duel | Ni l'interne ni la question ne bougent ; la question est marquée « vue ». Aucune lecture du palier : une question au palier vide n'y produit aucun motif. |
| Post-test | Rien ne bouge, rien n'est marqué. |
| Pré-test | L'interne bouge ; la question n'est ni étalonnée ni marquée « vue ». |
| Campagne, interne provisoire | Rien ne bouge ; la question est marquée « vue », et n'étalonnera plus jamais pour cet interne. |
| Campagne, interne stabilisé, première réponse | La question est étalonnée ; l'interne ne bouge pas. |
| Campagne, question déjà vue (niveau rejoué, ou question dans un second niveau) | Rien ne bouge. |
| Classé, question déjà vue | L'interne bouge ; la question non. |
| Classé, interne provisoire, première réponse | L'interne bouge ; la question non, et elle est marquée « vue ». |
| Classé, réponse qui fait sortir l'interne de sa période provisoire | La question n'est pas étalonnée : c'est l'état d'avant la réponse qui compte. |
| Entraînement, interne stabilisé, première réponse | La question bouge avec le poids réduit ; l'interne ne bouge pas. |
| `elo.question.poids_entrainement` = `0` | L'entraînement n'étalonne plus ; la question est quand même marquée « vue ». |
| Question simplifiée | Jamais étalonnée ; son ELO est celui de son palier, même si un état existe pour elle. |
| Palier vide ou inconnu, nom de plancher inconnu | Aucun effet, `palier_illisible` ou `plancher_illisible` ; la question est marquée « vue » si le mode le dit. |
| Question absente de `questions` | Aucun effet, `question_inconnue` ; marquée « vue » si le mode le dit. |
| `reponsesProposees` absent, non entier ou inférieur à 2 | Aucun effet, `hasard_inconnu`. |
| `resultat` hors de 0 à 1, ou non numérique | Aucun effet, `resultat_illisible`. |
| ELO de la question qui passerait sous son plancher | Il vaut le plancher. |
| Palier de départ sous le plancher | L'ELO de départ est le plancher. |
| Palier d'une question modifié après son premier étalonnage | L'ELO courant est gardé. Un rejeu complet repartirait du nouveau palier : **c'est le seul cas où un rejeu diffère du fil de l'eau** (lot 403). |
| Identifiant de compte ou nom de palier égal à un nom de propriété d'objet (`constructor`, par exemple) | Traité comme un identifiant ordinaire (recherche par propriété propre). |
