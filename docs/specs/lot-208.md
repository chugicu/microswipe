Décisions de l'auteur du 15 novembre 2026 appliquées ici :

1. **Le boss s'ouvre** quand tous les niveaux jouables du monde sont réussis **et** que les étoiles du monde atteignent `Étoiles pour le boss`.

## 6. Interfaces

### 6.1 Ce qui est lu dans le paquet

| Section | Colonnes lues |
|---|---|
| `mondes` | `ID`, `Ordre`, `Étoiles pour le boss`, `Seuil du boss`, `Questions du boss` |
| `niveaux` | `ID`, `Monde`, `Ordre`, `Type` |
| Par `preparerNiveau` (lot 201) | `jouable` et le nombre de questions jouables de chaque niveau. |

La colonne `Parcours` de `Mondes` n'est pas lue : le chemin suit `Ordre`, tous parcours confondus (signalé dans l'index des lots).

**La réserve d'un boss** = les questions jouables de son niveau, c'est-à-dire `preparerNiveau(index, idDuBoss).questions` (schéma § 3.6). Sa taille n'est pas un réglage : c'est le nombre de questions que l'auteur y a placées et qui sont servies.

### 6.2 Stockage

**Magasin `progression`** — clé : `[compte, niveau]`.

Un enregistrement reprend les colonnes de l'onglet `Progression` (schéma § 4.2) :

| Champ | Colonne du schéma | Type |
|---|---|---|
| `compte` | `ID compte` | Texte. |
| `niveau` | `Niveau` | Texte, `ID` du niveau. |
| `etoiles` | `Étoiles` | Entier de 0 à 3. Toujours 0 pour un boss. |
| `meilleurScore` | `Meilleur score` | Nombre de 0 à 1. |
| `tentatives` | `Tentatives` | Entier : parties terminées. |
| `reussites` | `Réussites` | Entier : parties terminées et réussies. |
| `derniereReussite` | `Dernière réussite` | Texte ISO 8601 en UTC, ou texte vide. |

**Interface du dépôt** (toutes les fonctions rendent une promesse) :

| Fonction | Rôle |
|---|---|
| `lireLignes(compte)` | Tous les enregistrements du compte. |
| `ecrireLigne(enregistrement)` | Crée ou remplace l'enregistrement de clé `[compte, niveau]`. |

**Compte** : chaque enregistrement porte le compte qui a joué. Avant le lot 303, il n'y a pas de connexion : `compteCourant()` rend la constante `COMPTE_LOCAL` (`local`), définie dans `suivi.js`. Le lot 303 la remplacera par le vrai compte.

**Rien d'autre n'est stocké.** Aucun « niveau débloqué », aucun « monde ouvert », aucun total : tout se recalcule (§ 6.4).

### 6.3 Le chemin (`regles.js`)

**`lireReglesDuBoss(monde)`** → `{ etoilesRequises, seuil, questions }`, ou `null`.

| Champ | Colonne de `Mondes` | Règle |
|---|---|---|
| `etoilesRequises` | `Étoiles pour le boss` | `lireEntier`, entier ≥ 0. |
| `seuil` | `Seuil du boss` | `lireEntier`, entier de 1 à 100. |
| `questions` | `Questions du boss` | `lireEntier`, entier ≥ 1. |

Une seule des trois cellules vide ou hors règle → `null`. Une cellule qui contient autre chose qu'un entier (par exemple un nombre suivi d'un commentaire) est hors règle.

**`construireChemin(index, preparer)`** → tableau de mondes, dans l'ordre du chemin.

`preparer(idNiveau)` rend le résultat de `preparerNiveau` ; en production c'est `(id) => preparerNiveau(index, id)`.

```
[
  {
    monde: "MON-01",
    regles: { etoilesRequises: 6, seuil: 90, questions: 4 },   // ou null
    niveaux: [ { niveau: "NIV-0001", type: "normal", jouable: true, questions: 3 }, … ],
    boss: { niveau: "NIV-0004", jouable: true, reserve: 6 },   // ou null
    anomalies: []
  },
  …
]
```

Les nombres de cet exemple viennent d'un paquet fictif.

- **Mondes** : ceux de `index.mondes`, triés par `lireEntier(Ordre)` croissant. `Ordre` illisible → après les autres. À égalité, l'ordre du paquet.
- Un monde invisible n'est pas dans le paquet « internes » : **il est sauté sans aucun code particulier**.
- **`niveaux`** : les niveaux du monde dont le `Type` est `normal` ou `révélation`, triés de la même façon par `Ordre`. `jouable` et `questions` viennent de `preparer`.
- **`boss`** : le niveau du monde de `Type` = `boss`. S'il y en a plusieurs : le premier par `Ordre` ; anomalie `boss_en_double`. Aucun : `boss: null` ; anomalie `sans_boss`.
- `boss.reserve` = nombre de questions jouables du niveau boss. `boss.jouable` = `regles` non nul **et** `reserve ≥ regles.questions`.
- `regles` nul → anomalie `regles_du_boss_illisibles`. `reserve < regles.questions` → anomalie `reserve_insuffisante`.
- Un niveau d'un autre `Type` est ignoré. Le boss est toujours le dernier nœud de son monde, quel que soit son `Ordre`.

### 6.4 L'état de la carte (`regles.js`)

**`estReussi(ligne)`** → vrai si `ligne` existe et `ligne.reussites ≥ 1`.

**`calculerEtatDeLaCarte(chemin, lignesParNiveau)`** — `lignesParNiveau` : `Map` de l'`ID` du niveau vers son enregistrement, pour le compte courant.

```
{
  mondes: [
    {
      monde: "MON-01",
      ouvert: true,
      etoiles: 7,
      etoilesRequises: 6,            // null si les règles du boss sont illisibles
      niveaux: [
        { niveau: "NIV-0001", type: "normal", etat: "reussi", jouable: true, etoiles: 3, meilleurScore: 1 }, …
      ],
      boss: { niveau: "NIV-0004", etat: "verrouille", jouable: true, raisons: ["niveaux"], meilleurScore: null },
      bossReussi: false,
      maitrise: false,
      anomalies: []
    }, …
  ],
  totalEtoiles: 7,
  niveauCourant: "NIV-0003"
}
```

Règles, monde par monde, dans l'ordre du chemin :

1. **Chaîne du monde** : ses `niveaux` dont `jouable` est vrai, dans l'ordre. Un niveau non jouable n'en fait pas partie : il est sauté.
2. **Monde ouvert** si l'une de ces conditions est vraie :
   - c'est le premier monde du chemin ;
   - le monde précédent du chemin a `bossReussi` vrai ;
   - un de ses niveaux, ou son boss, est réussi.
3. **État d'un niveau de la chaîne**, à la position `k` :
   - `reussi` si `estReussi(ligne)` ;
   - sinon `ouvert` si le monde est ouvert et que `k` vaut 0 ou que le niveau `k − 1` de la chaîne est réussi ;
   - sinon `verrouille`.
4. **État d'un niveau non jouable** : `reussi` s'il est réussi, `verrouille` sinon. Dans les deux cas `jouable: false` : il ne peut pas être lancé.
5. **`etoiles` du monde** = somme des `etoiles` des lignes de ses `niveaux` (jouables ou non). Le boss n'en a pas.
6. **État du boss** :
   - `reussi` si `estReussi(ligne du boss)` ;
   - sinon `ouvert` si `raisons` est vide ;
   - sinon `verrouille`.
7. **`raisons`** du boss, dans cet ordre, toutes celles qui s'appliquent :
   - `monde_ferme` : le monde n'est pas ouvert ;
   - `niveaux` : un niveau de la chaîne n'est pas réussi ;
   - `regles` : `regles` est nul ;
   - `etoiles` : `regles` non nul et `etoiles < regles.etoilesRequises` ;
   - `reserve` : `regles` non nul et `reserve < regles.questions`.
8. **`bossReussi`** = `estReussi(ligne du boss)` ; faux si le monde n'a pas de boss.
8 bis. **`maitrise`** (amendement du 17 novembre) = `bossReussi` vrai **et** chaque niveau de la **chaîne du monde** (ses niveaux jouables, règle 1) a `etoiles` = 3. Les niveaux non jouables ne comptent pas. Faux si le monde n'a pas de boss. Une chaîne vide ne bloque rien : seul le boss compte.
9. `etoiles` et `meilleurScore` d'un niveau : ceux de sa ligne ; 0 et `null` sans ligne.
10. **`totalEtoiles`** = somme des `etoiles` de tous les mondes du chemin.
11. **`niveauCourant`** = l'`ID` du premier nœud, dans l'ordre du chemin (niveaux de la chaîne puis boss, monde après monde), dont l'état est `ouvert` et `jouable` est vrai ; `null` s'il n'y en a pas.

Conséquences voulues :

- **Un niveau acquis ne se referme pas.** Si l'auteur insère un niveau avant lui, le nouveau niveau s'ouvre (son précédent est réussi) et les niveaux déjà réussis le restent.
- **Monde invisible** : ses lignes restent dans le magasin, mais ses niveaux ne sont plus dans le chemin. Ses étoiles sortent de `totalEtoiles` et de l'affichage. Quand il redevient visible, tout revient sans rien recalculer.
- **Le chemin saute le monde invisible** : « le monde précédent du chemin » est le monde visible précédent.
- **Boss fermé pour une raison de données** (`regles`, `reserve`, monde sans boss) : le monde suivant ne s'ouvre pas. C'est voulu ; l'anomalie se voit en mode test (lot 213).
- **Monde maîtrisé, puis niveau ajouté ou redevenu jouable** : `maitrise` redevient faux jusqu'à ce que ce niveau ait 3 étoiles. C'est la conséquence de la règle 8 bis, sans rien stocker.

**`peutJouer(etatDeLaCarte, idNiveau)`** → vrai si le nœud de cet `ID` existe, que son `etat` est `ouvert` ou `reussi`, et que `jouable` est vrai.

### 6.5 Mise à jour d'une ligne (`regles.js`)

**`appliquerFinDePartie(ligne, fin, compte, maintenant)`** → le nouvel enregistrement, ou `null` s'il n'y a rien à écrire.

- `fin` : l'événement de fin de partie du lot 201. `maintenant` : texte ISO 8601 en UTC.
- Rend `null` si `fin.modeTest` vaut `true`, ou si `fin.mode` n'est pas `campagne`.
- `ligne` nulle → part de `{ compte, niveau: fin.niveau, etoiles: 0, meilleurScore: 0, tentatives: 0, reussites: 0, derniereReussite: "" }`.
- `tentatives` + 1.
- `meilleurScore` = le plus grand de l'ancien et de `fin.score`.
- `etoiles` = le plus grand de l'ancien et de `fin.etoiles` (toujours 0 pour un boss, dont la partie n'a pas de seuils d'étoiles).
- Si `fin.reussi` : `reussites` + 1 et `derniereReussite` = `maintenant`.

Un niveau est rejouable sans limite : un moins bon score ne retire ni étoile ni réussite. Une partie abandonnée n'émet pas de fin de partie : elle ne compte pas dans `tentatives`.

### 6.6 Options de partie (`regles.js`)

**`optionsDePartie(mondeDuChemin, idNiveau, optionsDeBase, aleatoire)`** → les options à passer à `creerPartie`.

- `optionsDeBase` : le résultat de `optionsDuNiveau` (lot 201).
- Si `idNiveau` n'est pas le boss du monde : rend `optionsDeBase` sans changement.
- Si c'est le boss :
  - `mondeDuChemin.boss.jouable` faux → lève `boss_ferme` ;
  - sinon rend `optionsDeBase` avec :

| Option | Valeur pour un boss |
|---|---|
| `seuilsEtoiles` | `null` (pas d'étoiles) |
| `seuilDeReussite` | `regles.seuil` |
| `tirage` | `{ nombre: regles.questions, aleatoire }` |
| `reTestAutorise` | `false` |

Le tirage se fait à chaque appel de `creerPartie` : **chaque tentative tire une nouvelle série dans la réserve**, sans remise. Une partie reprise après interruption (lot 209) garde sa série, puisque l'état de la partie est sauvegardé.

À l'endroit où une partie est créée (lots 204 et 207), le code devient :

1. `etat = etatDeLaCarte()` ; si `peutJouer(etat, idNiveau)` est faux → la partie n'est pas créée ;
2. `options = optionsDePartie(mondeDuChemin, idNiveau, optionsDuNiveau(index, idPartie), Math.random)` ;
3. `creerPartie(preparerNiveau(index, idNiveau), options)`.

`Math.random` n'est écrit qu'à cet endroit, jamais dans `regles.js`.

### 6.7 Branchement (`suivi.js`)

`demarrerProgression(dependances)` — `dependances` : `depot`, `emetteur` (par défaut `emetteurDuJeu`), `compteCourant()`, `maintenant()`, `lireIndex()` (l'index du paquet « internes » en cours), `etatDeLInstallation()` (par défaut celle du lot 103), `demanderInvitation()` (la fonction du lot 207 qui affiche la carte d'invitation ; par défaut, ne fait rien).

Rend :

| Membre | Rôle |
|---|---|
| `pret` | Promesse résolue quand les lignes du compte courant sont chargées en mémoire. |
| `etatDeLaCarte()` | → `calculerEtatDeLaCarte(construireChemin(index, preparer), lignes en mémoire)`. Synchrone. |
| `cheminCourant()` | → `construireChemin(…)` pour l'index en cours. |
| `recharger()` | Relit les lignes du compte courant dans le dépôt. À appeler quand le compte ou le paquet change. |
| `evenements` | Un `EventTarget` qui émet `progression-changee`. |

À chaque fin de partie reçue de l'émetteur :

1. `nouvelle = appliquerFinDePartie(ligne en mémoire, fin, compteCourant(), maintenant())` ; `null` → rien ;
2. la ligne en mémoire est remplacée **tout de suite** ;
3. `progression-changee` est émis ;
4. `depot.ecrireLigne(nouvelle)` part **sans être attendu**. S'il échoue : un second essai ; s'il échoue encore : `console.error`, et la ligne reste en mémoire jusqu'à la fermeture de l'appli.
5. **Invitation à installer** (amendement du 17 novembre) : `parties` = somme des `tentatives` des lignes en mémoire du compte courant (tous les niveaux, mondes invisibles compris) ; `{ installee, moyen } = etatDeLInstallation()`. Si `doitInviterApresPartie(parties, installee)` est vrai et que `moyen` n'est pas `aucun`, appeler `demanderInvitation()`, sans l'attendre ; une erreur est écrite par `console.error` et n'arrête rien. Une fin de partie ignorée à l'étape 1 (`null`, dont le mode test) ne demande jamais l'invitation.

Le jeu n'attend jamais le dépôt. La carte lit la mémoire.

## 7. Cas limites

| Cas | Comportement attendu |
|---|---|
| Premier lancement, aucune ligne | Premier niveau jouable du premier monde `ouvert` ; tout le reste `verrouille`. |
| Niveau réussi avec 1 étoile | Le niveau suivant de la chaîne s'ouvre. |
| Partie terminée sans étoile | `tentatives` + 1 ; le niveau reste `ouvert` ; le suivant reste `verrouille`. |
| Niveau rejoué avec un moins bon score | Étoiles, meilleur score et réussite gardés. |
| Tous les niveaux réussis, étoiles insuffisantes | Boss `verrouille`, raison `etoiles`. Rejouer des niveaux pour gagner des étoiles l'ouvre. |
| Étoiles suffisantes, un niveau jouable non réussi | Boss `verrouille`, raison `niveaux`. |
| Boss joué à un score inférieur au seuil | `tentatives` + 1, `meilleurScore` mis à jour ; monde suivant fermé. |
| Boss réussi | `bossReussi` vrai ; le monde suivant du chemin s'ouvre. |
| Boss réussi, puis `Étoiles pour le boss` augmentée par l'auteur | Le boss reste `reussi`, le monde suivant reste ouvert. |
| Boss rejoué | Une nouvelle série est tirée ; pas de re-test ; pas d'étoiles. |
| Réserve jouable plus petite que `Questions du boss` | Boss `verrouille`, raison `reserve` ; `optionsDePartie` lève `boss_ferme`. |
| `Seuil du boss` vide, ou `Questions du boss` qui n'est pas un entier | Boss `verrouille`, raison `regles`. |
| Monde sans niveau boss | Anomalie `sans_boss` ; le monde suivant ne s'ouvre pas, sauf s'il a déjà un niveau réussi. |
| Niveau sans aucune question jouable | Sauté : le niveau suivant s'ouvre comme s'il n'existait pas ; il ne compte pas dans la raison `niveaux`. |
| Niveau de type `révélation` | Sauté dans ce lot (non jouable jusqu'au lot 211). |
| Monde devenu invisible | Absent du chemin ; ses lignes restent dans le magasin ; le boss du monde précédent ouvre le monde visible suivant. |
| Monde redevenu visible | Ses étoiles et ses réussites reviennent. Les niveaux déjà réussis des mondes suivants restent réussis. |
| Niveau inséré par l'auteur avant un niveau déjà réussi | Le nouveau niveau est `ouvert` ; les niveaux réussis restent `reussi`. Le boss déjà réussi le reste. |
| Dernier monde du chemin, boss réussi | Rien d'autre ne s'ouvre ; `niveauCourant` peut valoir `null`. |
| Fin de partie du mode test | Ignorée : aucune ligne créée ni modifiée, aucun `progression-changee`. |
| Écriture IndexedDB impossible | La ligne reste en mémoire ; la carte est à jour ; aucun message. |
| Lancement d'un niveau `verrouille` | La partie n'est pas créée. |
| Ligne du magasin pour un niveau absent du paquet | Ignorée par les calculs, jamais supprimée. |
