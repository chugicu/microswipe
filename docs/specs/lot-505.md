# Lot 505 — Import annuel : préparer et comparer

Phase 5. Dépend des lots 302, 305, 306 et 501. Domaine de tests obligatoire : **import**.
Spec écrite en phase 0, lot 4b, conversation 4 (16 novembre 2026). Le lot 506 applique ce que ce lot compare : **lis aussi `docs/specs/lot-506.md` § 1 et § 6.1 avant de commencer**.

Décisions de l'auteur du 16 novembre 2026 appliquées ici :

1. **Trois états.** « Préparer » crée deux copies du fichier Contenu : une copie de travail, que l'auteur modifie, et une copie de référence, jamais touchée. L'import compare la référence, la copie et la production.
2. **Un conflit** est une ligne changée en production depuis la référence **et** changée dans la copie, différemment. Une ligne changée seulement en production garde sa version de production, sans rien demander.
3. **Périmètre** : les douze onglets de faits du lot 305, `Notions` et `Questions`. `Mondes`, `Niveaux`, `Composition`, `Reglages`, `Signalements` et `Historique` ne sont jamais comparés.
4. **Identifiants** : une ligne ajoutée a un `ID` vide dans la copie ; le serveur l'attribuera à l'application (lot 506). Un identifiant présent dans la copie et absent de la référence bloque l'application. Une espèce nouvelle recevra le préfixe `ESP-`.
5. **Question à réponse propre** : elle repassera à « À valider » quand la colonne qu'elle teste change, sauf si sa propre ligne a été modifiée dans la copie.
6. **Ce lot n'écrit rien dans le fichier Contenu.** L'état de l'import est rangé dans les propriétés du script.
7. Une ligne supprimée de la copie mais modifiée en production depuis la référence est un conflit, pas un retrait.
8. Une question dont l'`Origine` n'est ni `tableur` ni `import …` n'est jamais retirée par l'import.
9. Une colonne ou un onglet inconnu est ignoré sans erreur. Une colonne absente de la copie n'est pas comparée.
10. Le résultat de la comparaison est gardé dans un fichier privé et porte une empreinte.
11. L'écran « Import annuel » vit dans l'espace Admin, en ligne seulement ; rien n'est stocké sur le téléphone.

## 1. Objectif

Permettre à un admin « contenu » de préparer la mise à jour annuelle du contenu et d'en voir l'effet **avant toute écriture** :

- **préparer** : faire les deux copies du fichier Contenu ;
- **comparer** : rapprocher les lignes par identifiant, onglet par onglet, et classer chacune (ajoutée, modifiée, retirée, en conflit…) ;
- **montrer** le récapitulatif et le détail à l'admin ;
- **abandonner** un import préparé.

L'application des différences est le lot 506.

### 6.1 Vocabulaire

- **Production** : le fichier Contenu désigné par la cible (§ 6.7). **Référence** : la copie jamais modifiée. **Copie** : la copie de travail.
- Toute cellule est comparée après `texteDeCellule`. Deux cellules sont égales si leurs textes sont égaux, majuscules et accents compris.
- Une ligne dont `ID` est vide est ignorée dans la référence et dans la production. Dans la copie, c'est une ligne ajoutée si une de ses cellules n'est pas vide ; sinon elle est ignorée.

### 6.3 Les trois états et les colonnes comparées (`logique/import-comparaison.js`)

Les **trois états** donnés aux fonctions pures :

```
{
  reference:  { noms: [ … ], onglets: { "<Onglet>": { enTete, lignes } } },   // lignes rendues par lireOnglet
  copie:      { noms: [ … ], onglets: { … } },
  production: { noms: [ … ], onglets: { … } }
}
```

`noms` : tous les onglets du fichier. `onglets` : seulement ceux du périmètre qui existent dans ce fichier.

`colonnesDeLOnglet(onglet, enTeteReference, enTeteCopie, enTeteProduction)` → `{ comparees, inconnues, absentesDeLaCopie, absentesDeLaReference }` :

- `jamais` = `COLONNES_JAMAIS_REPRISES_DE_LA_COPIE`, plus celles de `COLONNES_JAMAIS_REPRISES_PAR_ONGLET[onglet]` ;
- `comparees` : les colonnes de l'en-tête de **production**, dans son ordre, présentes dans les trois en-têtes et absentes de `jamais` ;
- `inconnues` : colonnes de la copie absentes de la production ;
- `absentesDeLaCopie` : colonnes de la production absentes de la copie, hors `jamais` ;
- `absentesDeLaReference` : colonnes de la production absentes de la référence, hors `jamais`.

Une colonne renommée dans la copie apparaît donc deux fois : sous son ancien nom dans `absentesDeLaCopie`, sous son nouveau nom dans `inconnues`. **Aucune de ces listes ne produit d'erreur ni de blocage.**

### 6.4 Classement d'une ligne (`logique/import-comparaison.js`)

Pour un identifiant donné, `r`, `c` et `p` sont les textes de la ligne sur les colonnes `comparees`, dans la référence, la copie et la production. `archR` et `archP` sont les textes de `Archivé le` dans la référence et la production (texte vide si la colonne manque).

- `copieChangee` = `c` diffère de `r` sur au moins une colonne.
- `productionChangee` = `p` diffère de `r` sur au moins une colonne, **ou** `archP` diffère de `archR`.
- `protegee` (onglet `Questions` seulement) = `texteDeCellule(Origine)` de la ligne de production n'est pas `ORIGINE_TABLEUR` et ne commence pas par `PREFIXE_ORIGINE_IMPORT`. Colonne `Origine` absente ou vide → protégée.

| Référence | Copie | Production | Condition | Catégorie |
|---|---|---|---|---|
| présente | présente | présente | ni l'une ni l'autre changée | `inchangee` |
| présente | présente | présente | production changée seule | `gardee_de_la_production` |
| présente | présente | présente | copie changée seule | `modifiee` |
| présente | présente | présente | les deux changées, `c` égal à `p` | `identique_des_deux_cotes` |
| présente | présente | présente | les deux changées, `c` différent de `p` | `conflit`, motif `modifiee_des_deux_cotes` |
| présente | absente | présente | `protegee` | `retrait_refuse` |
| présente | absente | présente | sinon, `archP` non vide | `deja_archivee` |
| présente | absente | présente | sinon, production changée | `conflit`, motif `retiree_dans_la_copie` |
| présente | absente | présente | sinon | `retiree` |
| absente | absente | présente | — | `creee_en_production` |
| absente | présente (`ID` non vide) | présente ou absente | — | blocage `identifiant_non_reconnu` |
| présente | présente ou absente | absente | — | blocage `ligne_absente_de_la_production` |
| — | ligne sans `ID`, non vide | — | — | `ajoutee` |

Les conditions se lisent de haut en bas ; la première qui s'applique donne la catégorie.

**Conséquences voulues**

- Une question créée dans l'espace Admin après la préparation est `creee_en_production` : l'import n'y touche pas.
- Une question d'origine `admin` ou `mode test` supprimée de la copie est `retrait_refuse` : l'import n'y touche pas non plus.
- Une ligne archivée en production après la préparation, et non modifiée dans la copie, est `gardee_de_la_production` : elle reste archivée.
- Une ligne déjà archivée peut être `modifiee` : son contenu change, elle reste archivée. L'import ne restaure jamais une ligne.
- Dans la copie, les colonnes `Archivé le`, `Modifié le`, `Modifié par` et, pour `Questions`, `Origine` sont ignorées : ce que l'auteur y écrit n'a aucun effet.

### 6.5 Comparaison d'un onglet et des trois états (`logique/import-comparaison.js`)

**`comparerUnOnglet(onglet, etats)`** → `{ onglet, colonnes, lignes, blocages, comptes }`.

1. Blocages d'onglet, dans cet ordre ; le premier trouvé arrête la comparaison de cet onglet (`lignes` vide) :
   - `onglet_absent_de_la_production`, `onglet_absent_de_la_reference`, `onglet_absent_de_la_copie` ;
   - `colonne_id_absente` : la colonne `ID` manque dans l'un des trois en-têtes (`ou` dit lequel).
2. `colonnes = colonnesDeLOnglet(…)`.
3. Blocage `identifiant_en_double` pour chaque identifiant non vide présent deux fois dans un même état (`ou` : `reference`, `copie` ou `production`). La comparaison continue avec la première ligne de chaque identifiant.
4. Classe chaque identifiant selon le § 6.4, puis chaque ligne ajoutée.
5. `lignes` : d'abord les identifiants dans l'ordre de la **production**, puis les lignes ajoutées dans l'ordre de la copie. Une entrée :

```
{
  cle: "Faits_fictifs:FF-02",          // "<Onglet>:<ID>" ; pour une ligne ajoutée : "<Onglet>:+<numéro de la ligne dans la copie>"
  id: "FF-02",                          // texte vide pour une ligne ajoutée
  categorie: "modifiee",
  motif: null,                          // un motif de MOTIFS_DE_CONFLIT pour un conflit
  colonnesChangees: [ "Colonne A" ],    // colonnes comparées où la copie diffère de la production ; [] si la copie est absente
  reference:  { "Colonne A": "Valeur A2", … },   // textes des colonnes comparées ; null si absente
  copie:      { … },                              // null si absente
  production: { … },                              // null si absente
  archiveeEnProduction: false           // archP non vide
}
```

   Pour les catégories `inchangee` et `creee_en_production`, `reference`, `copie` et `production` valent `null` : ces lignes ne sont que comptées. Pour une ligne `ajoutee`, `copie` porte **toutes** les colonnes de l'en-tête de production présentes dans la copie et absentes de `jamais`, et `colonnesChangees` est la liste de ses colonnes non vides.
6. `comptes` : un nombre par catégorie de `CATEGORIES_DE_LIGNE`.
7. Un blocage : `{ type, onglet, id, ou }` (`id` et `ou` : texte vide s'ils sont sans objet). **Jamais une valeur de cellule.**

**`comparerLesTroisEtats(etats, perimetre)`** → la **comparaison** :

```
{
  onglets: [ <résultat de comparerUnOnglet>, … ],      // dans l'ordre du périmètre
  ongletsIgnores:  [ "Mondes", … ],     // onglets de la copie hors périmètre et dans ONGLETS_DE_STRUCTURE
  ongletsInconnus: [ "Onglet nouveau" ],// onglets de la copie hors périmètre et hors ONGLETS_DE_STRUCTURE
  blocages: [ … ],                      // ceux de tous les onglets, dans l'ordre
  questionsARevalider: { certaines: [ "Q-000001" ], possibles: [ "Q-000004" ] },
  questionsOrphelines: { certaines: [ … ], possibles: [ … ] },
  applicable: true                      // aucun blocage
}
```

La fonction ne modifie pas `etats` et ne lève pas pour un défaut des données : tout défaut est un blocage.

### 6.6 Questions touchées et empreinte (`logique/import-comparaison.js`)

**`questionsTouchees(comparaison, etats, choix)`** → `{ aRevalider, orphelines }`, deux tableaux d'identifiants de questions, dans l'ordre de la production. `choix` : objet clé de conflit → `production` ou `copie` (objet vide si aucun choix n'est fait).

1. **Faits modifiés** : pour chaque ligne d'un onglet autre que `Questions`, de catégorie `modifiee`, ou `conflit` de motif `modifiee_des_deux_cotes` dont le choix vaut `copie` : retenir `cle` → `colonnesChangees`.
2. **Faits retirés** : chaque ligne d'un onglet autre que `Questions`, de catégorie `retiree`, ou `conflit` de motif `retiree_dans_la_copie` dont le choix vaut `copie`.
3. Pour chaque ligne de `Questions` de la **production**, non archivée, à `ID` non vide :
   - `references = lireReferences(Fait)` ; `null` → la question est passée ;
   - `champs = lireChamps(Champ, references.length)` ; `null` → passée ;
   - **orpheline** si l'une de ses références (`onglet:identifiant`) est un fait retiré ;
   - **à revalider** si toutes ces conditions sont vraies : `texteDeCellule(Statut)` vaut `STATUT_VALIDE` ; `texteDeCellule(Réponse propre)` n'est pas vide ; l'un de ses couples (référence, champ) désigne un fait modifié dont `colonnesChangees` contient ce champ ; **et** la ligne de la question n'est pas elle-même reprise de la copie (sa catégorie n'est ni `modifiee`, ni `conflit` avec le choix `copie`).

`comparerLesTroisEtats` remplit `certaines` avec `questionsTouchees(comparaison, etats, {})`, et `possibles` avec ce que donne en plus un `choix` où tous les conflits valent `copie`.

Une question orpheline n'est modifiée par aucun lot de l'import : elle cessera d'être servie (motif `fait_archive` du lot 306) et l'admin décide de son sort dans l'espace Admin.

**Empreinte**

| Fonction | Entrée → sortie |
|---|---|
| `empreinteDeTexte(texte)` | → `<longueur>-<8 chiffres hexadécimaux>`. Hachage FNV-1a sur 32 bits des unités de code UTF-16 : `h = 0x811c9dc5` ; pour chaque unité `u` : `h = h XOR u`, puis `h = Math.imul(h, 0x01000193) >>> 0`. Vecteurs de contrôle : texte vide → `0-811c9dc5` ; `abc` → `3-1a47e90b` ; `Bactérie A` → `10-65e265e1`. |
| `empreinteDeLaComparaison(comparaison)` | → `empreinteDeTexte(JSON.stringify(forme))`, où `forme` est le tableau, onglet par onglet dans l'ordre du périmètre, de `[ onglet, [ [ cle, categorie, motif, copie, production, archiveeEnProduction ], … ] ]` pour toutes les lignes sauf celles de catégorie `inchangee`, suivi du tableau des blocages. |

L'empreinte ne sert qu'à reconnaître qu'une comparaison a changé. Ce n'est pas une protection.

### 6.8 Actions (`logique/import-service.js`)

Toutes sont non publiques. **Chacune commence par `exigerDroit(idCompte, 'contenu')`**, avant toute lecture.

`dependances` : `exigerDroit(idCompte, droit)`, `lirePropriete(nom)` et `ecrirePropriete(nom, valeur)` (noms déjà préfixés), `sousVerrou(fn)`, `maintenant()`, `copierFichier(nom)` (copie la production), `lireLesTroisEtats()`, `perimetre()`, `ecrireComparaison(texte)`, `lireComparaison()` (rend le texte ou `null`), `journaliserErreur(contexte, erreur)`.

| Fonction pure | Action |
|---|---|
| `etatDeLImport(idCompte, dependances)` | `importEtat` |
| `preparerLImport(idCompte, dependances)` | `importPreparer` |
| `comparerLImport(idCompte, dependances)` | `importComparer` |
| `detailDeLImport(message, idCompte, dependances)` | `importDetail` |
| `abandonnerLImport(idCompte, dependances)` | `importAbandonner` |

**`importEtat`** — message : `{ "action": "importEtat", "session": "<jeton>" }`. Réponse :

```
{ "ok": true, "etat": "preparee", "importId": "IMP-2027-09-02T13:05:11.000Z",
  "prepareLe": "2027-09-02T13:05:11.000Z", "compareLe": "", "empreinte": "",
  "nomDeLaCopie": "Microbio – import 2027-09-02 – copie de travail" }
```

Dans l'état `aucun`, les autres champs sont des textes vides. N'écrit rien.

**`importPreparer`** — message sans autre champ. Tout se passe dans un seul `sousVerrou` :

1. `exigerDroit` de nouveau.
2. État différent de `aucun` → lève `import_deja_prepare` (ou `import_en_cours` si l'état vaut `en_application`).
3. `date = maintenant()` ; `jour` = ses dix premiers caractères.
4. `copierFichier('Microbio – import <jour> – référence (ne pas modifier)')`, puis `copierFichier('Microbio – import <jour> – copie de travail')`. **Les deux copies sont faites sous le même verrou** : aucune écriture de contenu ne peut passer entre elles.
5. Écrit `ID_REFERENCE`, `ID_COPIE`, `ID` (`IMP-` + `date`), `PREPARE_LE`, `EMPREINTE` et `COMPARE_LE` (textes vides), puis **en dernier** `ETAT` = `preparee`.
6. Rend la réponse de `importEtat`.

Une interruption avant l'étape 5 laisse l'état à `aucun` et un ou deux fichiers sans usage : la relance en crée d'autres. **Aucun fichier n'est supprimé.**

**`importComparer`** — message sans autre champ.

1. État `aucun` → `import_non_prepare`. État `en_application` → `import_en_cours`.
2. `etats = lireLesTroisEtats()` ; `comparaison = comparerLesTroisEtats(etats, perimetre())` ; `empreinte = empreinteDeLaComparaison(comparaison)`.
3. `ecrireComparaison(…)`, puis écrit `EMPREINTE` et `COMPARE_LE`.
4. Rend le **récapitulatif** :

```
{ "ok": true, "importId": "…", "compareLe": "…", "empreinte": "1234-0a1b2c3d", "applicable": true,
  "onglets": [ { "onglet": "RN_specifiques",
                 "comptes": { "ajoutee": 2, "modifiee": 14, "retiree": 1, "conflit": 1, "retrait_refuse": 0,
                              "gardee_de_la_production": 3, "creee_en_production": 0,
                              "identique_des_deux_cotes": 0, "deja_archivee": 0, "inchangee": 1049 },
                 "colonnesInconnues": [], "colonnesAbsentesDeLaCopie": [], "colonnesAbsentesDeLaReference": [] } ],
  "ongletsIgnores": [ "Mondes", "Niveaux", "Composition", "Reglages" ],
  "ongletsInconnus": [],
  "blocages": [ { "type": "identifiant_non_reconnu", "onglet": "Regles", "id": "REG-999", "ou": "copie" } ],
  "blocagesEnTout": 1,
  "questionsARevalider": { "certaines": [ "Q-000001" ], "possibles": [] },
  "questionsOrphelines": { "certaines": [], "possibles": [] } }
```

Le récapitulatif ne contient **que des nombres, des noms d'onglets et de colonnes, et des identifiants**. `blocages` est coupé à `BLOCAGES_MAX_DANS_LA_REPONSE`.

Cette action ne prend pas le verrou : elle ne fait que lire. La production peut changer pendant la lecture ; le lot 506 refait la comparaison sous verrou avant d'appliquer.

**`importDetail`** — message : `{ "action": "importDetail", "session": "<jeton>", "onglet": "RN_specifiques", "categorie": "modifiee", "page": 1 }`.

- `onglet` : un onglet du périmètre ; `categorie` : une catégorie autre que `inchangee` et `creee_en_production` ; `page` : entier ≥ 1. Sinon → `message_invalide`.
- `lireComparaison()` nul, ou son `importId` différent de la propriété `ID` → `comparaison_absente`.
- Réponse : `{ "ok": true, "empreinte": "…", "page": 1, "pages": 3, "lignes": [ <entrées du § 6.5> ] }`, `TAILLE_DE_PAGE_DU_DETAIL` lignes par page. Une page au-delà de la dernière rend `lignes` vide.

**Cette réponse contient des valeurs du contenu.** Elle n'est servie qu'après `exigerDroit`.

**`importAbandonner`** — message sans autre champ. Sous `sousVerrou` : état `en_application` → `import_en_cours` ; état `aucun` → rend `{ ok: true, etat: "aucun" }` sans rien écrire ; sinon écrit `ETAT` = `aucun`, `EMPREINTE` et `COMPARE_LE` vides. ### 6.9 Fonction d'essai (`installation-import.js`)

`essaiImportComparer()` se lance depuis l'éditeur Apps Script, hors de la table des actions. Elle lève une erreur si `ENVIRONNEMENT` ne vaut pas `test`. Elle utilise `CIBLE_IMPORT_ESSAI` et le compte `compte-essai-A`, à qui l'auteur a donné le droit « contenu » pour l'essai (fonction du `lot-302.md` § 6.8). Elle écrit dans les journaux d'exécution des nombres et des codes, **jamais une valeur**.

1. Si l'état d'essai n'est pas `aucun` : `abandonnerLImport`.
2. `comparerLImport` → `import_non_prepare`.
3. `preparerLImport` → état `preparee` ; deux fichiers créés ; un second appel → `import_deja_prepare`.
4. `comparerLImport` sans rien modifier → `applicable` vrai ; tous les comptes sont à zéro sauf `inchangee` ; l'empreinte est notée.
5. Dans la **copie de travail** d'essai (jamais ailleurs), par `ecrireLigne` et `ajouterLignes` : modifie la colonne `Valeur` de `RNS-001` ; ajoute dans `RN_specifiques` une ligne sans `ID` ; ajoute une ligne d'`ID` `RNS-9999`.

7. `detailDeLImport` (`RN_specifiques`, `modifiee`, page 1) → une ligne, de clé `RN_specifiques:RNS-001`, dont `colonnesChangees` vaut `Valeur`.
8. Avec un compte sans droit (`compte-essai-E`) : chacune des cinq fonctions → `droit_refuse`.

10. Le fichier Contenu d'essai est inchangé : même nombre de lignes dans chaque onglet qu'avant l'essai, et même `contenu.version`.

### 6.10 Écran « Import annuel » (`client/admin/import/`)

**Règles**

- L'écran n'existe que dans l'espace Admin, pour un compte dont l'action `profil` donne le droit « contenu ». Le serveur revérifie le droit à chaque action : l'écran ne protège rien.
- Il demande du réseau. Chaque appel passe par `appelerServeur`, avec `options.delaiMaxMs` = `DELAI_DES_ACTIONS_D_IMPORT_MS`.
- **Rien de ce qu'il reçoit n'est rangé dans IndexedDB, dans le cache du service worker ni ailleurs** : tout reste en mémoire et disparaît quand on quitte l'écran.
- Un indicateur d'attente est permis ici : ce n'est pas un écran de jeu.
- Aucune couleur, durée ni espacement hors de `docs/design-system.md`.

**Fonctions pures (`modele.js`)**

| Cas | Comportement attendu |
|---|---|
| Lignes de la copie dans un autre ordre que la production | Sans effet : le rapprochement se fait par identifiant. |

| Même correction faite des deux côtés | `identique_des_deux_cotes`. |
| Ligne modifiée des deux côtés, sur des colonnes différentes | `conflit` : le choix porte sur la ligne entière (lot 506). |
| Ligne supprimée de la copie, intacte en production | `retiree`. |
| Ligne supprimée de la copie, modifiée en production | `conflit`, motif `retiree_dans_la_copie`. |
| Ligne supprimée de la copie, déjà archivée | `deja_archivee`. |
| Ligne archivée en production après la préparation, modifiée dans la copie | `conflit`. |
| Question créée dans l'espace Admin après la préparation | `creee_en_production`. |
| Question d'origine `admin` supprimée de la copie | `retrait_refuse`. |
| Question d'origine `tableur` ou `import 2027` supprimée de la copie | `retiree`. |
| `Origine` vide ou colonne absente | Question protégée : `retrait_refuse`. |

| Colonne ajoutée dans la copie | `inconnues` ; ignorée. |
| Colonne renommée dans la copie | Citée dans `absentesDeLaCopie` et dans `inconnues` ; non comparée. |
| Colonne ajoutée en production après la préparation | `absentesDeLaReference` ; non comparée. |
| Onglet ajouté dans la copie | `ongletsInconnus` ; non lu. |
| `Niveaux` modifié dans la copie | `ongletsIgnores` ; non lu. |
| Onglet du périmètre supprimé de la copie | Blocage `onglet_absent_de_la_copie`. |
| Fait modifié, question à réponse propre non touchée | La question est dans `questionsARevalider.certaines`. |
| Même fait, question à réponse propre touchée dans la copie | Elle n'y est pas. |
| Fait modifié sur une autre colonne que le `Champ` de la question | Elle n'y est pas. |
| Fait en conflit | Les questions concernées sont dans `possibles`. |
| Fait retiré, question qui pointe vers lui | `questionsOrphelines.certaines`. |
| Question ajoutée dans la copie qui pointe vers un fait ajouté dans la copie | Impossible : ce fait n'a pas encore d'identifiant. Rien ne le détecte dans ce lot ; à écrire dans `PROGRESS.md` comme limite connue. |
| `importPreparer` deux fois | La seconde → `import_deja_prepare`. |
| `importComparer` relancée sans changement | Même empreinte. |
| `importDetail` après une nouvelle préparation, avant de comparer | `comparaison_absente`. |
| Compte sans le droit « contenu » | `droit_refuse` pour les cinq actions ; aucune lecture. |
| État `en_application` | `importPreparer`, `importComparer`, `importAbandonner` → `import_en_cours`. |
| Copie de travail supprimée ou illisible | L'erreur du module de stockage est journalisée ; la réponse est `erreur_interne`. **Arrête-toi et demande** si cela arrive pendant l'essai. |
